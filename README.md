# iRacing 주행 코치

내 iRacing IBT와 Garage61 개인 API로 내려받은 다른 드라이버의 주행을 비교하는 로컬 앱입니다. React 화면과 FastAPI 분석 서버로 구성됩니다.

## 실행

프로젝트 폴더의 **[실행.bat](실행.bat)를 더블클릭**하세요. 분석 서버와 화면을 함께 실행하고, 준비되면 http://localhost:24157 을 브라우저에서 엽니다. 매번 npm 명령을 입력할 필요가 없습니다. 실행 창을 유지하고, 종료할 때 `Ctrl+C`를 누르거나 창을 닫으세요. 이미 실행 중인 앱은 재사용하며, 기존 서버는 종료하지 않습니다.

실행 오류는 화면에 표시되며 상세 로그는 `logs/backend.log`, `logs/frontend.log`에 남습니다. Python 3.10 이상이 필요하고 3.12를 권장합니다. `설치.bat`과 `실행.bat`은 `scripts/find_python.bat`으로 같은 Python을 고릅니다: 프로젝트의 `.venv` → `iRacing_Backend/.venv` → `py -3.12` → `py -3.13` → `python`(3.12·3.13) → 3.11·3.10 → 3.14 이상(`python`, `py -3`) 순서입니다. `설치.bat`은 `PYYAML_FORCE_LIBYAML=0`으로 설치해, PyYAML의 미리 만든 설치 파일이 없는 새 Python(예: 3.15)에서도 C++ 컴파일러 없이 순수 Python 판을 설치합니다(설치 파일이 있으면 빠른 C 판을 씁니다). 3.14 이상에서 설치가 실패하면 3.12 설치(`py install 3.12` 또는 python.org)를 안내합니다. 화면 개발 서버를 쓸 때만 Node.js가 필요합니다.

평소 실행은 빌드된 화면(`build/`)을 같은 주소로 서빙하므로 Node 개발 서버가 필요 없습니다. 화면 소스를 고친 뒤에는 `npm run build`를 한 번 실행하세요. 빌드가 없거나 소스보다 오래됐으면 자동으로 개발 서버를 사용하며, `실행.bat --dev`로 개발 서버를 직접 선택할 수 있습니다.

분석 서버는 이 PC에서만 접속할 수 있습니다(`127.0.0.1`). 다른 기기에서 접속해야 하면 `IRACING_API_HOST`와 `CORS_ORIGINS` 환경변수로 직접 허용하세요. 인증이 없으므로 신뢰하는 네트워크에서만 사용하세요.

개발 중에는 기존처럼 두 개의 터미널로 실행할 수도 있습니다.

1. 분석 서버: `python iRacing_Backend/backend_api.py`
2. 화면: `npm start` 또는 `npm run dev`
3. 브라우저에서 http://localhost:24157 접속

처음 설치할 때는 `npm ci`와 `python -m pip install -r iRacing_Backend/requirements_core.txt`를 실행합니다. Garage61 수집에는 `requirements_crawler.txt`의 의존성을 확인하세요. 기존 API 토큰 설정은 그대로 사용합니다.

기본 API 주소는 http://localhost:24158 입니다. 다른 주소를 쓰려면 `.env.local`에 `REACT_APP_API_BASE_URL`을 설정하고 화면을 재시작하세요.

## 사용 흐름

음성 코치는 기본 **측정값 답변** 모드에서 연료·순위·간격·랩타임 등 확인 가능한 질문에 프로그램의 계산으로 답하며 AI 토큰을 사용하지 않습니다. 원리나 가능한 원인 설명이 필요하면 **AI 원인 분석**을 선택하세요. 이 모드도 측정값으로 답할 수 있는 질문은 AI를 호출하지 않고, 추가 분석이 필요한 질문에서만 기존 Vertex AI Gemini를 사용합니다. AI 답변에서는 **“더 자세히 설명해줘”**, **“짧게 말해줘”**로 설명 길이를 조절할 수 있습니다. 같은 주행의 최근 3분 안 대화 최대 3개를 문맥으로 참고하고 최근 주행 표본은 주요 변화와 시작·끝을 보존해 최대 24개로 줄여 전송합니다. 현재 자료는 최근 약 20초의 부분 관측이며, 이전 랩 전체나 기준 주행을 분석한 것처럼 평가하지 않습니다. 차량 연결이 없는 일반 운전 개념 질문도 **AI 원인 분석** 선택과 AI 연결이 필요합니다.

화면은 [BMW M 디자인 기준](<bwm m design.txt>)의 상단 삼색 마커를 유지하고, 어두운 중립색과 절제된 파란 강조색으로 통일했습니다. 제목·수치·설명에 서로 다른 글자 크기와 일정한 간격을 적용하고, 한글이 단어 중간에서 무작위로 끊기지 않도록 정리했습니다. 랩 기록은 하나의 수치 영역으로 묶고 코너 그래프는 불필요한 중첩 테두리를 줄였습니다. 내 주행의 하늘색 실선과 기준 주행의 주황색 점선은 유지합니다. 셋업 선택지는 같은 디자인 안에서 테두리·배경·체크 표시로 선택 상태를 구분합니다. 기록은 주행 분석과 셋업 실험 이력을 나누고, 매뉴얼은 목차와 읽기 영역으로 구성합니다. PC에서는 왼쪽 메뉴, 모바일에서는 한 줄 가로 메뉴를 사용합니다.

### 레이스 피트월 · 세 명의 엔지니어

음성 코치 화면 위쪽의 **레이스 피트월**에서 사용할 수 있습니다. 주행 코치는 남성 **Algenib**, 레이스 엔지니어는 남성 **Charon**, 전략 엔지니어는 남성 **Orus**이며 모두 기존 출력장치·볼륨과 1.15배속을 사용합니다. 역할별 **목소리 들어보기**로 확인하세요. 음성 인식과 GCP 연결은 기존 설정을 사용합니다.

- **자동 보고 시작**을 누르면 실제 Race 세션에서 먼저 보고합니다. 마이크를 준비하지 않아도 자동 보고는 사용할 수 있습니다. 브라우저를 열어두면 다른 탭에서도 동작하며, 페이지를 새로 열면 시작 버튼을 다시 누릅니다.
- **중요한 것만**은 완주 연료 부족·연료 임박·황기·체커기를 보고합니다. **일반 보고 포함**은 같은 클래스 뒤차의 빠른 페이스와 가까운 거리, 앞뒤 차량의 피트 진입, 여러 랩에 걸쳐 같은 구간에서 말한 어려움도 알려줍니다. **끄기** 또는 **자동 보고 중지**로 멈춥니다.
- **완주 여유 연료**는 기본 0.5랩입니다. 실제 깨끗한 완주랩 소비량의 보수적인 값을 사용합니다. 시간제 경기는 전체 선두의 종료 후 마지막 통과와 내 다음 통과를 추정하므로 선두와 내 완주 페이스가 필요합니다. 랩 제한 경기에서도 선두에 뒤처진 경우 선두의 종료 시점을 반영합니다.
- **예상 피트 총손실**은 피트 진입·작업·복귀 전체에서 평소 주행보다 잃는 시간을 초로 입력합니다. 같은 클래스 모든 상대의 진행률과 관측 페이스가 있으면 대략적인 복귀 순위를 계산합니다. 미입력·관측 부족일 때 순위를 만들지 않습니다.
- “뒤차가 더 빨라?”, “앞차와 간격은?”, “지금 몇 등?”, “끝까지 연료 돼?”, “몇 리터 넣어야 해?”, “지금 피트 들어가면?”을 음성 또는 텍스트로 질문하세요. 질문에 따라 담당과 목소리가 자동으로 바뀝니다. 경기 수치는 프로그램이 계산하며 언어 모델이 수치를 만들어내지 않습니다.

일반 보고는 제동·조향 부담이 적을 때 전달하고, 급한 연료·깃발 보고를 우선합니다. 녹음·질문 처리·음성 재생 중에는 다음 자동 보고를 기다립니다. 동일 보고에는 재보고 간격을 두고, 연결 단절·세션 변경·오래 걸린 음성 합성에서 지난 상황의 보고를 폐기합니다. 앱의 한국어 스포터가 엔지니어보다 우선합니다. 외부 게임/Crew Chief 스포터의 발화는 감지하지 못하므로 중복 사용은 피하세요.

간격은 랩 진행 거리를 내 페이스로 환산한 추정이며 공식 상대 간격이 아닙니다. 복귀 순위는 상대의 피트 계획·추월·교통 변화와 타이어 교체 효과를 포함하지 않습니다. 현재 버전은 가능한 최적 언더컷/오버컷을 확정하지 않습니다. 상대 연료·타이어 마모·손상을 추측해 보고하지 않습니다. 보고와 당시 계산 근거는 SQLite에 저장되며, IBT에 연결되면 주행 후 분석에서 확인할 수 있습니다. 이 기록은 셋업 효과 학습의 근거로 사용하지 않습니다.

자동 보고는 AI를 호출하지 않습니다. 음성은 역할별 고정 문구를 처음 사용할 때만 Google TTS로 합성해 저장하고, 같은 문구·목소리는 앱 재시작 후에도 재사용합니다. 정확한 수치는 화면과 기록에 남깁니다. 예를 들어 급유량이 3.0L에서 4.0L로 바뀌어도 음성은 “완주 연료가 부족합니다. 추가 급유량을 화면에서 확인하세요.”를 재사용합니다. 목소리 들어보기도 같은 캐시를 사용합니다. 음소거·볼륨 0·음성 답변 끄기에서는 문자로만 기록해 자동 보고의 음성 합성을 호출하지 않습니다. 고정 음성은 개인 대화 DB 폴더의 `radio_audio`에 저장하며 `IRACING_RADIO_AUDIO_DIR`로 경로를 변경할 수 있습니다. 목소리·문구 변경 또는 캐시 삭제 시 최초 합성 비용이 다시 발생합니다. 목소리 변경 환경 변수는 `IRACING_TTS_VOICE`(주행), `IRACING_TTS_RACE_VOICE`(레이스), `IRACING_TTS_STRATEGY_VOICE`(전략)입니다. 피트월 추가 API는 `POST /api/live-coach/reports`, `POST /api/live-coach/voices/{coach|race|strategy}/test`입니다.

보고는 화면이 수신을 확인한 뒤 재보고 간격을 적용합니다. 질문이나 중지 때문에 전달되지 않은 보고는 전달 대기로 남기며, 다음 요청에서 아직 유효하면 재사용합니다. `POST /api/live-coach/reports/{note_id}/ack`가 수신 확인 API입니다. 개발 검증은 `python scripts/validate_pit_wall.py`로 실행하고, 실제 세 남성 음성의 Google 연결 확인은 별도 과금 요청이 포함된 `--cloud` 옵션을 사용합니다. 합성 음성 원본은 검증 파일에 저장하지 않습니다.

### 보고 타이밍 · 배틀 · 연료 절약 개선 (2026-10-09)

- **보고 구간 학습:** 같은 차량·트랙·레이아웃의 현재 세션에서 깨끗한 전체 랩 2개부터 반복되는 낮은 조작 부담 구간을 학습합니다. 현재 속도와 제동 전 여유를 반영해 긴 보고가 들어갈 시간을 계산하고, 짧은 구간에는 가능한 보고를 한 문장으로 줄입니다. 실제 음성 길이도 재생 전에 확인하며 제동·큰 조향·옆 차량 접근 때 일반 자동 보고를 중단합니다. 학습 전에는 기존 조작 부담 조건을 사용하고 세션이 바뀌면 새로 학습합니다. 좌우 접촉과 긴급 경고는 기존 우선순위를 유지합니다.
- **배틀 보고:** 같은 클래스 앞뒤 순위 경쟁 상대를 출발선 부근의 같은 위치에서 연속 3회 이상 관측한 뒤 간격이 계속 줄거나 벌어지는지 보고합니다. 관측 방향이 바뀌면 지속적인 접근으로 단정하지 않습니다. 피트 진입·상대 변경·순위 관계 변경 때 이 기록을 다시 수집합니다. 다른 클래스의 가까운 차량은 별도로 안내합니다. 모든 간격은 공식 시간차가 아닌 거리 환산 추정입니다.
- **연료 절약 코치:** 피트월의 **연료 절약 목표**에서 무급유 완주 / 안전 여유 포함 / 피드백 끄기를 선택합니다. 랩 시작 때의 목표를 저장하고 깨끗한 완료 랩의 실제 소비량과 비교합니다. 연속 3개 랩에서 목표를 유지하면 알려줍니다. 급유하면 이전 스틴트의 소비량과 피드백을 초기화합니다. 목표 달성 가능성과 최적 리프트 위치를 확정하는 기능은 아직 포함하지 않습니다.

배틀과 완료 랩 절약 피드백은 **일반 보고 포함**에서 사용합니다. “뒤차가 따라와?”, “다른 클래스 차량 있어?”, “연료 절약 목표 지켰어?”로 직접 질문할 수도 있습니다. 이번 개선 검증은 `python -m unittest discover -s iRacing_Backend -p 'test_*.py'`에 포함되며, 경기 운영·코스 공략의 추가 조사와 다음 후보는 [엔지니어 주행 안내 조사](docs/race-engineer-driving-guidance.md)에 정리했습니다.

### 시간제 레이스의 남은 랩과 급유량 (2026-10-11)

- 시간제 레이스는 시계가 0이 된 뒤 전체 선두가 처음 결승선을 지날 때 끝나고, 나는 그다음 내 통과에서 끝납니다. 앱은 선두와 내 페이스로 내가 달릴 랩 수를 계산하고, 그 값이 한 랩 늘거나 줄 수 있는 경계에 가까운지도 함께 봅니다.
- **마지막 피트의 급유량을 숫자 하나로 말합니다.** "급유는 22리터입니다." 선두 위치 때문에 한 랩 늘 수 있는 상황이면 그 한 랩을 포함한 양을 말합니다. 가득 채우는 피트에서는 말하지 않습니다.
- **한 번 급유로 끝까지 갈 수 있게 되면 알려 줍니다.** "지금부터는 한 번 급유로 끝까지 갑니다."
- **경기 후반에 한 랩이 늘어 연료가 모자라게 되면 알려 줍니다.** "한 랩 늘었습니다. 연료가 모자랍니다."
- "몇 랩 남았어?"라고 물으면 "11랩 남았습니다."라고 답합니다.
- 급유량에는 "완주 여유 연료"가 들어갑니다. 정확히 맞추고 싶으면 그 값을 낮추세요.
- 한계: 선두의 피트나 옐로는 예측하지 못합니다. 경계 판단의 기준은 검증 전 초기값입니다.

### 타이어 계획 · 자동 피트 손실 (2026-10-11)

- **타이어 계획:** 피트가 두 랩쯤 남으면 타이어를 어떻게 할지 한마디로 알려 줍니다("타이어는 바꾸지 않습니다." / "타이어도 바꿉니다."). 게임의 타이어 체크가 계획과 다르면 그것도 알려 줍니다.
  - 1시간 미만 경기는 바꾸지 않습니다.
  - 1시간 이상 경기는 음성 코치의 **피트 작업 방식**(동시 교체/순차 교체)을 경기 전에 골라 두어야 안내가 나옵니다. 바꿀 때 드는 시간(더 서 있는 시간 + 차가운 타이어 약 4초)과 안 바꿀 때 잃을 수 있는 시간을 예전 기록으로 계산해 작은 쪽을 고릅니다. 한 세트로 세 스틴트는 가지 않고, 마지막 스틴트가 짧으면 바꾸지 않습니다.
- **예상 피트 총손실 자동 입력:** 그 트랙에서 피트한 기록이 있으면 비워 두어도 자동으로 계산합니다. 직접 넣으면 그 값을 씁니다.
- **근거:** 예전 레이스 33개에서 잰 급유 속도, 타이어 교체 시간, 트랙별 피트 통과 손실, 타이어 마모율입니다. 앞으로 주행할 때마다 계속 쌓입니다. 옛 파일을 새로 복사해 넣었다면 `python scripts/learn_pit_history.py`로 다시 읽을 수 있습니다.
- **한계:** 예전 기록에서 타이어는 36퍼센트 닳을 때까지 느려지지 않았고, 그보다 더 닳은 기록은 없습니다. 두 스틴트를 이어 쓰면 그 범위를 넘을 수 있으니 페이스가 떨어지면 알려 주세요.

### 충돌 뒤 차량 상태 비교 (2026-10-11)

- iRacing은 수리가 필요하다는 신호만 주고, 수리 시간은 피트박스에 멈춰야 알려 줍니다. 손상 부위와 정도는 알려 주지 않습니다.
- 그래서 앱은 충돌(2점 이상 인시던트 또는 수리 신호) 뒤 처음으로 깨끗하게 돈 랩을 충돌 전 랩들과 비교해 한 번 알려 줍니다. 예: "충돌 뒤 랩타임과 최고속은 그대로입니다. 직선에서 핸들이 0.6도 틀어졌습니다."
- 비교하는 것은 랩타임, 직선 최고속, 직선에서 핸들이 돌아가 있는 각도입니다. 같은 스틴트에서 충돌 전 깨끗한 랩이 2개 이상 있어야 하고, 평소 랩 간 차이 안이면 "그대로"라고 합니다.
- 측정된 차이만 말합니다. 어디가 망가졌는지, 수리해야 하는지는 판단하지 않습니다.

### 엔지니어 안내 확장 (2026-10-10)

완결된 문장 여러 개를 이어 한 번에 말하는 방식으로 안내를 넓혔습니다. 수치는 모두 측정값이고, 측정이 부족하면 말하지 않습니다.

- **랩 종료 한 묶음:** 랩타임, 최근 페이스와의 차이, 바뀐 순위를 한 번에 말합니다. 퀄리파잉에서는 랩타임과 순위·차이를 한 번에 말합니다.
- **긴 직선에서:** 아래 중 가장 오래 말하지 않은 것을 직선 길이에 맞춰 말합니다(자동 보고 범위 "일반 보고 포함").
  - 지난 랩에서 잃은 코너와 가장 좋았던 코너 (코너 번호를 확정한 트랙)
  - 지금 랩이 베스트보다 얼마나 앞서 있는지, 뒤져 있는지
  - 이론상 베스트(구간 최고를 모두 합친 기록)와 지금 베스트와의 차이
  - 앞차·뒤차보다 빠른 곳과 느린 곳 (5초 이내일 때, 트랙을 8구간으로 나눠 비교)
  - 앞차를 따라잡는 데 필요한 랩당 시간, 또는 지금 줄이는 속도와 닿기까지 남은 랩
  - 클래스 선두와 앞차의 지난 랩, 피트 뒤에는 지난 스틴트 평균
- **피트 예고:** 피트 총손실을 입력해 두면 "두 랩 안에 피트합니다." 뒤에 "피트하면 클래스 14위로 나옵니다."를 덧붙입니다.
- **질문 즉답:** 간격, 순위, 남은 시간, 랩타임, "따라잡을 수 있어?", "이론상 베스트 얼마야?" 같은 질문은 준비된 문장으로 바로 답합니다.
- **한계:** 다른 차량의 구간 시간은 1초에 한 번 읽는 위치로 계산한 것이라 0.3초 미만 차이는 말하지 않고, 상대가 트래픽에 막혔던 랩은 구분하지 못합니다.

### 4시간 경기 기록으로 고친 것 (2026-10-10)

### 말 시작 보류 · 퀄리파잉 · 긴 직선 한 줄 (2026-10-10)

- **제동·조향 앞에서 말 시작 보류:** 음성 코치의 레이스 피트월에서 켜고 끌 수 있고, 몇 초 전부터 보류할지 정할 수 있습니다(기본 켜짐 · 1.0초). 켜면 제동·조향 중이거나 그 시간 안에 제동·조향이 다가올 때 새 안내를 시작하지 않습니다. 이미 말하고 있는 안내는 끊지 않습니다. 끄면 언제든 말합니다. 좌우 차량·깃발 같은 급한 호출은 설정과 관계없이 바로 나옵니다.

### 끊긴 안내 다시 말하기 (2026-10-10)

- 한번 시작한 안내는 제동이나 조향이 시작돼도 끊지 않고 끝까지 말합니다. 시작은 여전히 조작 부담이 낮은 구간에서만 합니다.
- 그사이 내용이 더는 맞지 않게 됐으면 말하지 않습니다. 같은 안내는 최대 두 번까지만 다시 시도합니다.
- 직접 멈춘 음성은 다시 나오지 않습니다.

### 내구 레이스 연료 안내 (2026-10-10)

- **연료는 적게 남았을 때만 말합니다.** 급유가 여러 번 필요한 긴 경기에서는 "완주까지 몇 리터 부족"을 반복하지 않습니다. 스틴트마다 "두 랩 안에 피트합니다" 한 번, 피트해야 하는 랩의 초반과 후반에 "이번 랩 박스" 한 번씩이 기본입니다.
- **탱크 용량은 차마다 다릅니다.** 시리즈의 연료 제한(BoP)을 반영한 실제 한도를 씁니다(예: 100리터 탱크에 98% 제한이면 98리터).
- **급유 설정 확인:** 설정한 급유량이 모자랄 때만 말합니다. 가득 채워야 하는 피트에서는 "가득 채워야 합니다", 마지막 피트에서는 필요한 리터를 말합니다. 피트로드에 있는 동안에는 연료 안내를 하지 않습니다.
- **절약 목표:** 필요한 절약이 10% 이하일 때만 "완주까지 N리터 부족"과 랩별 절약 목표를 안내합니다. 그보다 크면 절약이 아니라 급유로 해결할 거리로 봅니다.
- **화면:** 피트월의 "다음 급유"가 다음 피트에서 넣을 양을 보여 줍니다(가득이면 "가득 · 급유 약 N번").

### 공식 코너 번호 · 숫자 읽기 (2026-10-10)

- **코너 번호 확인:** 코너 비교 화면의 **코너 번호 확인**에서 자동 구간에 공식 코너 번호를 붙입니다. iRacing 공식 지도의 코너 표기를 주행 궤적에 맞춰 자동으로 제안하고, 틀린 곳만 고친 뒤 **이대로 확정**을 누르면 됩니다. 확정한 내용은 트랙 레이아웃별로 저장되어 다른 차량과 다음 주행에도 적용되고, 화면의 “자동 구간 N”이 “5번 코너”로 바뀝니다. 뉘르부르크링처럼 번호 없이 이름만 있는 트랙은 이름을 제안하며, “음성으로 부를 말”에 한글(예: 플룩플라츠)을 적으면 그대로 읽습니다.
- **제안의 한계:** 번호는 지도 위 글자 위치로만 있어 가까운 구간에 붙입니다. 시케인은 “1-2”처럼 묶이고, 공식 번호가 없는 구간은 비어 있습니다. 지도가 주행 궤적과 맞지 않으면(맞춤 오차 15m 초과) 제안하지 않습니다. 반드시 한 번 확인하세요.
- **음성:** 확정한 트랙에서는 코너 진입 전 안내가 “다음 5번 코너. 지난 랩에 0.4초 잃었습니다. 제동이 일렀습니다.”처럼 번호를 말하고, “방금 랩 어때?”의 답도 번호로 말합니다. 확정 전에는 “다음 코너”라고만 합니다.
- **화면에만 있던 수치 읽기:** 남은 시간·랩(“10분 남았습니다”), 순위 변동(“클래스 4위로 내려갔습니다”), 최근 페이스 차이, 세션 베스트 랩타임, 완주 연료 부족량, 랩 연료와 목표, 견인 시간을 음성으로 말합니다.
- **숫자 읽는 법(들어 보고 정함):** 순위·랩 수·정수 리터는 음성으로 보낼 때만 한글로 바꿉니다(“오위”, “다섯랩”, “오리터”). 숫자로 두면 “오…위”처럼 늘어졌습니다. 소수(“2.3리터”, “0.4초”)와 초·분·점·도는 숫자 그대로 둡니다. 화면 표기는 바뀌지 않습니다.
- API: `GET /api/corner-names?filename=`, `PUT /api/corner-names`.

### 엔지니어 무전 확장과 문구 변형 (2026-10-10)

엔지니어가 같은 내용을 매번 같은 문장으로 말하지 않도록, 안내마다 2~4개의 표현을 두고 돌려 씁니다. 숫자가 들어가는 안내는 “뒤차 1.8초. 가까워지고 있습니다.”처럼 **문장 전체를 한 번에 합성한 음성**을 쓰고, 이 안내들은 음성으로도 실제 수치를 말합니다. 직접 들어 보고 정한 규칙은 세 가지입니다. 조각을 이어 붙이지 않고, 숫자 뒤에는 항상 마침표로 끊고, 음성 문구에 쉼표를 쓰지 않습니다. 또 “최근 랩”, “두 랩”처럼 “랩” 앞을 띄우면 목소리가 길게 끊어 읽어, 음성으로 보낼 때만 앞말에 붙여 읽게 합니다(화면 표기는 그대로). 랩타임은 스포터가 “1분 42초 3입니다.”처럼 0.1초 단위로 읽고, 화면에는 지금처럼 랩 번호와 0.01초 단위 기록을 표시합니다.

| 피트 예고 | 완주에 급유가 필요할 때 남은 연료 기준 약 5랩 전, 2랩 전에 알립니다. 2랩 전부터 게임의 급유 설정량이 필요량보다 1리터 넘게 적으면 설정량과 필요량을 알립니다. |
| 상대 피트 | 같은 클래스 앞뒤 차량이 피트에 들어가면 알립니다. |

| 체커 후 결과 | 체커 플래그 아래에서 출발선을 지나면 클래스 순위를 알립니다. |

| 수리 신호 | 인시던트가 한 번에 2점 이상 늘고 4초 뒤에도 수리 필요 신호가 없으면 알립니다. 무손상을 뜻하지는 않습니다. |
| 일정한 페이스 | 연속 3개의 깨끗한 랩이 0.3초 안이면 알립니다. |
| 노면·날씨 | 노면이 젖기 시작하거나 마를 때, 노면 온도가 4도 이상 변할 때 알립니다. |
| 레인 타이어 | 게임이 웨트 타이어를 허용한 상태에서 노면 젖음 단계에 따라 “다음 피트에서 준비”(약간 젖음) → “이번 랩 피트 검토”(보통 이상 젖음, 또는 약하게 젖었는데 드라이 랩타임보다 5% 이상 느림) 순으로 알립니다. 웨트 타이어로 달리는 중 노면이 마르면 드라이 복귀를 알립니다. 예보는 SDK에 없어 현재 상태만 사용합니다. 장착 타이어를 게임에서 읽지 못하는 차량은 타이어 교체를 말하지 않고 “노면이 많이 젖었습니다”만 알립니다. |
| ABS·TC·브레이크 바이어스 | 같은 설정으로 옆 차량 없이 달린 깨끗한 랩 3개에서, 제동·가속 중 조향을 반대로 준 횟수와 ABS 개입 시간을 셉니다. 불안정 신호가 반복될 때만 먼저 알리고(바이어스 앞쪽, TC·ABS 개입 늘리기), 신호가 없을 때의 “한 단계 줄여 시험” 제안은 **“TC 어떻게 해?”**처럼 물었을 때만 답합니다. 화면의 실시간 코너 비교 카드에서도 볼 수 있습니다. 설정값을 복창하지는 않습니다. |
| 퀄리파잉 | 게임이 알려주는 세션 종류가 퀄리파잉이면 랩 중에는 경고 외에 말하지 않고, 랩이 끝나면 클래스 순위와 선두(1위일 때는 2위)와의 차이만 알립니다. 연습·레이스에서는 나오지 않습니다. |
| 발언 확인 | 메모만 기록했거나 느낌을 저장했을 때 긴 안내 대신 “카피.”, “체크.” 같은 짧은 확인을 무작위로 말합니다. 전체 안내문은 대화 기록에 남습니다. |

레인 타이어 시점과 ABS·TC·바이어스 추천의 기준값은 실제 주행으로 검증하지 않은 초기값입니다. 모두 “시험해 볼 방향”이며 효과를 보장하지 않습니다. 이어 붙인 음성이 자연스러운지는 실제로 들어 보고 문구를 다듬어야 합니다.

**엔지니어 음성 미리 준비:** 음성 코치 화면의 **전부 받아 두기**를 누르면 모든 문구 변형과 숫자 문장 약 30,800개(약 64만 자)를 한 번에 합성해 저장합니다. Google의 분당 요청 한도 때문에 2~3시간 걸립니다. 이후 주행 중에는 합성하지 않습니다. 미리 만드는 범위는 간격 0.1~9.9초, 순위 1~60위, 퀄리파잉 결과(1~40위 × 0.1~3.0초 차), 인시던트 1~40점, 그리고 GT3 페이스 중심의 랩타임(0:40~3:30, 르망 3:50~4:30, 뉘르부르크링 6:30~9:30, 0.1초 단위 × 표현 3개)입니다. 범위를 벗어난 값과 급유량 안내는 처음 쓰일 때 한 문장을 합성합니다. 동시에 4개씩 받으며 수십 분 걸릴 수 있습니다. 받는 동안 다른 화면을 써도 되고, 멈추거나 실패해도 받은 만큼 사용하며 다시 누르면 빠진 것만 받습니다. 요청 한도에 걸리면 20초 기다렸다 이어 받습니다. 목소리 환경변수나 문구를 바꾸면 그 부분을 다시 받아야 합니다. API는 `GET /api/live-coach/radio-audio`, `POST /api/live-coach/radio-audio/prepare`, `POST /api/live-coach/radio-audio/stop`입니다.

**직접 들어 보기:** `python scripts/voice_pilot.py`는 모든 안내를 하나씩(약 140개), `--all-variants`는 모든 표현(약 300개)을 실제 목소리로 합성해 `artifacts/voice-pilot/`에 한 페이지로 만듭니다. 과금 요청이 발생합니다.

### 실시간 코너 비교 · 전방 위험 · 바로 뒤 차량 (2026-10-09)

- **실시간 코너 비교:** 주행 중 각 자동 구간의 통과 시간, 제동 시작 위치, 최저속도, 가속 시작 위치를 측정해 **이번 실행에서 깨끗하게 통과한 내 구간 최고 기록**과 비교합니다. AI를 사용하지 않습니다. 음성 코치 화면의 **실시간 코너 비교**에서 최근 완료 랩의 손실 구간을 확인하세요. 옆에 차량이 있었거나 옐로·인시던트·데이터 끊김이 있던 통과는 비교와 기준에서 제외합니다.
- **사용 조건:** 해당 차량·트랙·레이아웃의 주행 파일을 한 번 분석해 구간 정의가 저장되어 있어야 합니다. 구간 번호는 코너 비교 화면의 자동 구간 번호와 같으며 공식 턴 번호가 아닙니다. 앱을 다시 시작하면 구간 최고 기록은 새로 쌓습니다.
- **코너 진입 전 안내:** 스포터와 **일반 보고 포함**이 켜져 있으면, 지난 랩에서 0.1초 이상 가장 많이 잃은 구간 하나를 그 구간의 제동 지점 6~12초 전에 한 번만 알립니다. 예: “다음 코너, 지난 랩은 제동이 일렀습니다.” 문장을 끝낼 시간이 부족하면 말하지 않습니다. 측정된 차이를 알릴 뿐 원인을 확정하지 않으므로 연습 세션에서 먼저 사용해 보세요.
- **질문:** “방금 랩 어때?”, “어디서 느렸어?”, “이전 코너 뭐 잘못했어?”는 **측정값 답변**에서 이 비교 수치로 답합니다. **AI 원인 분석**에서는 같은 수치를 근거로 AI가 설명합니다. 구간 정의가 없으면 기존처럼 주행 후 분석을 안내합니다.
- **전방 위험:** 약 1.5~10초 앞의 차량이 두 번 연속 트랙 밖에서 관측되거나 내 속도의 35% 미만으로 움직이면 스포터가 “전방 트랙 밖 차량” 또는 “전방 느린 차량”을 알립니다. 로컬 옐로에서도 동작하고 풀코스 옐로·레드·피트에서는 중지합니다. 상대 위치는 1초 간격이라 안내가 1~2초 늦을 수 있고, 사고 여부나 원인은 판단하지 않습니다.
- **바로 뒤 차량:** 뒤차가 약 0.5초 이내로 붙으면 한 번 알리고, 0.8초 이상 벌어진 뒤 다시 붙어야 다시 알립니다. **다중 클래스·랩핑 접근, 바로 뒤 차량 안내** 설정으로 끌 수 있습니다.
- **AI 요청 축소:** AI에 보내는 최근 주행 표본을 같은 값 그대로 열 형식으로 보내 크기를 약 66% 줄였고, 지침의 고정 부분을 앞에 두어 반복 요청에서 캐시 할인을 받을 수 있게 했습니다. 답변 길이와 지침 내용은 줄이지 않았습니다. 실제 토큰 수는 로그의 `Voice answer tokens` 줄에서 확인할 수 있습니다.

새 스포터 문구 3종은 다음에 **스포터 켜기**를 누를 때 한 번 합성되고, 코너 안내 문구 4종은 처음 사용할 때 한 번 합성됩니다.

### 한국어 스포터 사용

1. `실행.bat`로 앱을 실행하고 **음성 코치 → 한국어 스포터 → 스포터 켜기**를 누릅니다. 스포터와 세 명의 엔지니어 자동 보고를 함께 시작하며 마이크는 별도로 준비합니다. 엔지니어 보고는 아래 피트월에서 별도로 중지할 수 있습니다.
2. **스포터 목소리 듣기**로 소리를 확인하고 아래 **오디오 출력장치·답변 볼륨**을 설정합니다. 스포터는 별도의 남성 **Fenrir**, 1.15배속이며 공통 음소거·볼륨을 사용합니다. **음성으로 답변** 체크는 스포터를 끄지 않습니다.
3. iRacing에서 실제 차량에 탑승하면 좌우 겹침 상태가 표시됩니다. 스포터를 한 곳에서만 사용하도록 iRacing/Crew Chief의 스포터를 직접 끄세요. 앱은 게임 설정을 변경하지 않습니다. **앱과 브라우저 페이지를 열어두고**, 페이지를 다시 열면 스포터를 다시 켜야 합니다.

좌우 안내는 왼쪽·오른쪽 차량, 양쪽 차량, 한쪽 두 대, 한 대만 남음, 방향별/양쪽 클리어와 방향별 반복입니다. 차량 클래스에 관계없이 SDK `CarLeftRight`를 약 30Hz로 읽습니다. 겹침은 약 50ms, 클리어는 기본 150ms 지속 확인 후 안내합니다. **스포터 안내 설정**에서 반복 간격(2·3·5초)과 클리어 확인 시간(150·300·500ms)을 변경할 수 있습니다. 재생 실패·중단 시 현재 확인된 상태만 재시도하며, 만료된 클리어와 이전 방향은 재생하지 않습니다. 순간적인 클리어 후보는 확정된 좌우 음성을 끊지 않습니다. 피트·채널 미제공·0(off) 상태에서는 **차량 겹침 안내만** 중지합니다. 리플레이·차량 밖·연결 단절에서는 모든 실시간 안내를 멈춥니다. 0.5초 이상 오래된 좌우 데이터는 사용하지 않으며, 재연결·세션 변경 후 이전 상태로 클리어를 추측하지 않습니다.

**다중 클래스·랩핑 접근 안내**는 기본으로 켜져 있습니다. 트랙 위 앞뒤 차량을 순위상의 라이벌과 구분해 표시합니다. 1Hz 상대 관측을 최소 세 번 확인해 접근 추세와 최근 랩 기준 클래스 페이스 차이를 판단하며, 빠른 클래스가 뒤에서 접근하거나 느린 클래스에 접근할 때 짧게 알립니다. 같은 클래스의 한 랩 이상 앞선/뒤처진 차량도 구분합니다. 표시 간격과 접근 시간은 트랙 진행률을 이용한 추정이며 좌우 공간이나 추월 방향을 뜻하지 않습니다. 피트·옐로·세션 변화·관측 단절에서는 접근 안내를 폐기합니다.

**피트박스 카운트다운(추정)**은 기본으로 꺼져 있습니다. 설정에서 켜기 전에 연습 세션에서 해당 트랙의 위치를 확인하세요. 내 차량의 `DriverPitTrkPct`와 명시된 트랙 길이를 읽고, 피트 진입 뒤 15m 이상 실제 이동과 위치 변화가 일치할 때 추정 거리를 표시합니다. 200·100·50·20·10m를 지날 때 최신 거리 한 개만 안내하며, 출발선 통과도 처리합니다. 견인·위치 급변·역주행·박스 통과·데이터 누락 시 이번 진입 안내를 중지합니다. 정확한 정차 지시를 대신하지 않습니다. 설정은 브라우저에 저장하고 다음 스포터 시작 때 적용합니다.

**일반 보고 포함**에서는 상세 페이스와 반복 실수 조언도 사용합니다. **중요한 것만**은 완주 연료 부족 등 중요한 엔지니어 판단을 유지하며 스포터의 기본 랩타임·경기 안내는 계속합니다. “랩타임 알려줘”, “경기전 브리핑”, “피트 제한속도 얼마야”, “지금 몇 등?”은 스포터가 답하고, “랩타임 왜 느려?”, “뒤차 간격”, “클래스 2위랑 거리 차이는?”, “데미지 리포트”, “완주 연료 돼?”는 담당 엔지니어에게 넘깁니다. 데미지 리포트는 필수·선택 수리 신호를 사용하며 인시던트 점수를 사고 횟수나 손상량으로 해석하지 않습니다.

플래그 자동 안내는 **스포터 전담**입니다. 블루 플래그·화이트 플래그·옐로 플래그·레드 플래그·블랙 플래그·체커드 플래그·레드 닷처럼 영어 명칭을 한글로 읽습니다. AI 답변을 생성하지 않고 저장한 음성을 재생하므로 반복 안내에 LLM 토큰이나 추가 TTS 합성을 쓰지 않습니다. 최초 음성 준비 및 문구·음성 변경 시에만 새 캐시의 TTS 합성이 필요합니다.

블루 플래그는 포메이션 랩과 피트로드에서는 안내하지 않습니다. 레이스 첫 랩에는 SDK의 블루 신호뿐 아니라 최신 차량 위치에서 뒤쪽 랩핑 차량도 확인돼야 안내합니다. 출발 직후 잠깐 켜지는 신호로 인한 오안내를 줄이며, 깃발이 꺼지거나 관측이 끊기면 대기 중인 블루 안내도 폐기합니다.

연료는 **시간 종료 뒤 마지막 완주 통과까지** 계산합니다. 화면과 답변에서 실제 완주 부족분, 설정한 안전 여유분, 여유분 포함 추가 급유량을 나눕니다. 부족하면 무급유 목표 소비량(L/랩)과 절약률도 보여줍니다. 절약 목표는 현재 관측에 따른 계산이며 달성 가능성이나 완주를 보장하지 않습니다. 전체 선두 종료 뒤에도 내 마지막 랩의 연료 경고를 유지하고, 내 체커 표시가 켜지면 전략 자동 보고를 끝냅니다.

**무전 전달 기록 · 경기 후 확인**에서 재생 시작·완료·중단·실패·기한 만료·취소·문자 전달을 조회할 수 있습니다. 최대 10만 건을 개인 DB의 별도 `radio_delivery` 테이블에 저장하며 음성 원본과 셋업 학습 데이터에는 추가하지 않습니다. 상세 JSON은 `GET /api/live-coach/radio-delivery?limit=5000`으로 확인합니다. 기록은 브라우저가 전달한 재생 상태이며 실제로 소리를 들었는지를 보장하지 않습니다. 기존 최근 무전 목록은 재생 시작 확인 기준의 메모리 목록입니다.

네 명의 무전은 **좌우 접촉 위험 → 짧은 경고 → 일반 안내·상세 설명** 우선순위로 한 번에 하나만 재생합니다. 차량이 옆에 있는 동안 다른 음성은 보류합니다. 일반 안내는 제동·조향 부담이 적을 때, 다른 발화·질문·녹음이 끝난 뒤 전달합니다. 중단한 설명을 자동으로 다시 재생하지 않으며 질문 답변은 대화 기록에서 볼 수 있습니다. 같은 깃발을 스포터와 레이스 엔지니어가 중복 안내하지 않습니다. 별도 WebSocket으로 상태와 안내를 보내고, 상태가 바뀌거나 만료된 안내는 폐기합니다. 브라우저의 휴면·OS 절전·연결 단절은 안내를 중단시킬 수 있으므로 실제 주행에서 확인해야 합니다.

패널티의 정확한 유형·이행 시간, 관측하지 못한 전방 사고·합류 안전 판단, 차량별 타이어 손상 등 SDK 자료가 부족한 항목은 임의로 만들지 않습니다. 피트박스 거리는 추정치입니다. 해당 공식 게임 표시와 지시를 확인하세요. 제공되는 기본 정보를 넓게 지원하지만 Crew Chief 및 iRacing 내장 스포터와 모든 기능이 동일하다는 의미는 아닙니다.

짧은 한국어 음성은 **67개 안내에 총 115개 표현**을 Google TTS로 준비해 `iRacing_Backend/spotter_audio`에 저장합니다. 같은 안내가 반복되면 다른 표현을 순환 선택하며 저장한 음성은 합성 대기 없이 재생합니다. 자동 랩타임·순위·브리핑·엔지니어 상세 보고도 고정된 짧은 음성을 사용하고 실제 수치는 화면과 기록에 남깁니다. 이 고정 문구는 첫 사용 때 합성해 개인 대화 DB 폴더의 `radio_audio`에 저장하며 재시작 후에도 재사용합니다. 화면에는 실제 보고와 음성 문구를 구분해 표시합니다. 짧은 안내는 완만한 전가속 구간에서도 전달할 수 있고 긴 설명은 더 엄격한 구간에서 기다립니다. 음소거·볼륨 0에서는 자동 무전 합성을 호출하지 않습니다. 합성 중에도 접촉·플래그·피트 경고는 저장한 음성으로 전달할 수 있고, 합성이 끝난 뒤 상황을 다시 검증합니다. 음성 변경은 `IRACING_TTS_SPOTTER_VOICE`, 기존 짧은 안내 저장 경로는 `IRACING_SPOTTER_AUDIO_DIR`, 추가 고정 문구 저장 경로는 `IRACING_RADIO_AUDIO_DIR`로 설정합니다. JJ 원본 녹음은 포함하지 않고 새 한국어 문장을 사용합니다. 이벤트 타이밍 참고: Crew Chief 사용자 설정과 [공개 소스](https://github.com/mrbelowski/CrewChiefV4/blob/master/CrewChiefV4/iRacing/iRacingSpotter.cs). 소스 코드나 녹음 파일을 복사하지 않았습니다.

API는 `POST /api/live-coach/spotter/prepare`(선택 설정 JSON), `PUT /api/live-coach/spotter/settings`, WebSocket `/api/live-coach/spotter/events`, 동적 무전용 `POST /spotter/radio/{id}/render`와 `/ack`입니다. 로컬 검증은 `test_spotter.py`, `test_spotter_upgrade.py`, `test_race_radio.py`와 `python scripts/validate_spotter.py`로 실행합니다. `--prepare-audio`는 실제 남성 음성을 확인하고 빠진 캐시를 합성하므로 첫 실행에는 과금 요청이 포함됩니다.

### 음성 대화와 주행 메모 시작하기

1. 최초 한 번 `음성코치_설치.bat`를 실행합니다. 현재 GCP 프로젝트에서 Cloud Speech-to-Text API와 Cloud Text-to-Speech API를 활성화하고 서비스 계정에 `roles/speech.client` 및 서비스 사용 권한을 설정합니다. 기존 Vertex AI 인증을 사용하되 Speech 서비스의 권한과 과금은 별도입니다.
2. `실행.bat`로 앱을 시작하고 **음성 코치 → 마이크 준비**를 누릅니다. Chrome/Edge의 `http://localhost:24157`에서 마이크 권한을 허용합니다. iRacing에서 실제 차량에 탑승하면 실시간 SDK 연결 상태가 표시됩니다.
3. **F8을 누른 채 말하고 놓으면 전송**합니다. 게임에 포커스가 있어도 동작하며 휠 버튼을 F8로 매핑할 수 있습니다. 앱 페이지를 열어두세요. 화면에서는 녹음 시작·완료 버튼을 사용합니다. 최대 45초. 기본 **측정값 답변**, 선택형 **AI 원인 분석**, **메모만 기록** 모드를 사용할 수 있습니다. 녹음·전송 중에는 모드를 변경할 수 없습니다.
4. 질문뿐 아니라 “이 코너가 어렵다” 같은 느낌도 저장합니다. 음성이 없을 때 텍스트를 사용할 수 있습니다. 파일 저장 후 주행 요약의 **대화로 남긴 코너**에서 해당 랩의 관측·다음 주행·셋업 가설을 확인합니다. 문장과 위치를 수정하거나 연결 대기 메모의 랩·코너를 직접 지정할 수 있습니다.

실시간 수집은 읽기 전용 `pyirsdk`, 약 30Hz의 최근 180초 메모리 버퍼입니다. 녹음 시작 시 위치와 최근 20초의 5Hz 표본을 고정하고 SQLite의 `voice_notes`, `voice_note_links`에 대화·답변·느낌·위치를 저장합니다. 녹음 원음은 DB/파일에 저장하지 않습니다. 리플레이나 오래된 데이터는 현재 차량 상태로 사용하지 않습니다. 주행 후 IBT 연결은 차량·트랙·레이아웃, 세션 식별자, `SessionTime`·랩·거리·속도 표본을 검증하며 온라인 식별자가 없는 로컬 주행은 여러 표본과 파일 시각이 일치해야 자동 연결합니다. 연결되지 않은 기록은 유지됩니다.

인식은 Google Speech-to-Text V2 `chirp_3`/`ko-KR`와 레이싱 용어 힌트, 선택한 AI 분석은 기존 Vertex AI Gemini, 합성은 Google Text-to-Speech 한국어 음성입니다. `IRACING_SPEECH_REGION` 기본값은 `us`(미국 멀티 리전), `IRACING_TTS_VOICE` 기본값은 `ko-KR-Chirp3-HD-Algenib`입니다. Google의 현재 Chirp 3 지원 리전은 `us`와 `eu`이며, `asia-northeast1`은 한국어 모델 요청을 거부하므로 사용하지 않습니다. 기존에 해당 환경 변수를 설정했다면 `us` 또는 `eu`로 변경한 뒤 앱을 재시작하세요. Gemini의 `GCP_LOCATION`과는 별도 설정입니다. `IRACING_VOICE_DB_PATH`로 대화 DB를 분리할 수 있으며 기본값은 기존 개인 SQLite 경로입니다. 서비스 연결 상태는 설정 여부와 실제 요청 성공을 구분합니다. 자동 수집/파일 분석은 음성 서비스를 호출하지 않습니다.

**비용 구분:** 측정값 답변·자동 보고·메모만 기록은 AI 토큰을 사용하지 않습니다. 녹음 질문은 음성 인식(STT), 질문 음성 답변은 TTS 비용이 발생할 수 있으며 같은 답변 음성은 최대 64개를 메모리에서 재사용합니다. 개인 질문과 AI 답변 음성은 고정 문구 디스크 캐시에 저장하지 않습니다. 텍스트 입력과 음성 답변 끄기를 함께 쓰면 STT/TTS를 호출하지 않습니다. **AI 원인 분석**이 실제 AI를 호출할 때는 별도의 토큰 비용이 발생합니다.

기본 답변 목소리는 남성 `Algenib`입니다. 같은 한국어 Chirp 3 HD의 남성 선택지는 `Achird`, `Algenib`, `Algieba`, `Alnilam`, `Charon`, `Enceladus`, `Fenrir`, `Iapetus`, `Orus`, `Puck`, `Rasalgethi`, `Sadachbia`, `Sadaltager`, `Schedar`, `Umbriel`, `Zubenelgenubi`입니다. 다른 목소리를 쓰려면 `IRACING_TTS_VOICE`에 `ko-KR-Chirp3-HD-Puck`처럼 전체 이름을 설정하고 앱을 재시작합니다. 현재 화면에는 목소리 선택 메뉴가 없습니다.

답변 음성은 목소리 높이를 유지하면서 1.15배속으로 재생합니다. 자동 답변과 “답변 다시 듣기”에 모두 적용됩니다.

**음성 코치 → 오디오 출력장치 → 답변 볼륨**에서 0~100%로 소리를 조절하거나 **음소거**를 누르세요. 자동 답변·다시 듣기·테스트 소리에 재생 중에도 바로 적용됩니다. 볼륨과 음소거 상태는 같은 브라우저·사이트 주소에 저장되며, 음소거 해제 시 설정한 볼륨으로 돌아옵니다. 슬라이더를 움직여도 음소거가 해제됩니다. 게임 소리와 마이크 입력 볼륨은 별도로 조절합니다.

**음성 코치 → 오디오 출력장치**에서 헤드셋이나 스피커를 선택하고 **테스트 소리**로 확인하세요. 자동 답변과 다시 듣기에 모두 적용하며, 선택은 같은 브라우저·사이트 주소에 저장됩니다. 장치 이름이 안 보이면 **마이크 준비**로 권한을 허용한 뒤 **목록 갱신**을 누르세요. 출력장치를 바꾸면 현재 답변 재생이 중단됩니다. 연결된 장치가 사라지면 Windows 기본 장치로 전환하며, 테스트 소리는 Google Cloud를 호출하지 않습니다. 출력 선택을 지원하지 않는 브라우저에서는 Windows 기본 장치를 사용합니다. 최신 Chrome 또는 Edge를 권장합니다.

iRacing이 기록 중인 IBT 파일은 Windows의 공유 잠금으로 읽기가 막힐 수 있습니다. 앱에서는 이를 **읽기 대기** 상태로 표시합니다. 이때 기존 분석 결과와 실시간 음성 코칭은 유지하며, 텔레메트리 기록이 종료되어 파일을 읽을 수 있게 되면 자동으로 다시 확인합니다. 기본 단축키 `Alt+L`로 기록을 종료하거나 세션을 종료한 뒤 잠시 기다리세요. 잠금 해제 후에도 계속 대기하면 해당 파일의 읽기 권한과 다른 프로그램의 사용 여부를 확인하세요.

추가 API: `/api/live-coach/status`, `/captures`, `/utterances`, `/notes`, `PATCH /notes/{id}` 및 F8 이벤트용 WebSocket `/events`. 메모는 셋업 효과 확정·자동 학습 표본으로 취급하지 않습니다. 주행 중 AI 설명은 IBT 분석에서 다시 확인하며, 해당 랩·위치 비교는 진행 중 셋업 실험의 고정된 조건을 바꾸지 않습니다.

파일 목록은 차량·트랙을 먼저 표시합니다. 요약의 손실 코너를 누르면 해당 코너가 선택된 비교 화면을 엽니다. 셋업은 구간·속도·증상을 선택한 뒤 추천을 갱신하고, 후보 상세에서 실제 값을 확인해 시험하세요. 진행 중 실험은 A 고정 → B 연결 → 체감 기록 → 효과 확인 순서로 표시되며, B를 연결하면 체감 입력이 자동으로 열립니다. 주행 유형과 기록 저장은 상단 주행 선택의 펼침 메뉴에 있습니다.

- **주행 요약:** 내 기록과 기준 기록, 먼저 확인할 코너, 다음 런 과제를 봅니다.
- **코너 비교:** 지도나 코너 버튼으로 구간을 확대하고 속도·브레이크·스로틀·조향·기어·시간 차이를 같은 거리에서 비교합니다. Garage61 기준과 로컬 기준을 확인할 수 있습니다.
- **셋업 실험:** 진입/중간/탈출, 코너 속도, 체감 증상을 선택합니다. 관측 근거와 가설을 확인한 다음 하나의 셋업 변경을 A/B로 검증합니다.
- **기록:** 저장한 세션과 개인화 학습을 확인합니다.
- **설정:** 연결 상태와 사용 방법을 확인합니다.
- **사용 가이드:** IBT 기록부터 Garage61 기준 선택, 셋업 A→B 실험, 결과 해석과 문제 해결까지 앱 안에서 읽습니다. 상단의 **처음 사용 가이드** 버튼으로도 열 수 있으며 서버 연결이나 분석 결과가 없어도 표시됩니다.

주요 화면 제목·지표·입력·버튼에 마우스를 올리면 기능 설명이 표시됩니다. 화면 맨 위의 **마우스 오버 설명** 토글로 자동 설명을 켜고 끌 수 있으며 선택은 같은 브라우저에서 유지됩니다. 꺼둔 상태에서도 물음표 클릭과 키보드 포커스로 도움말을 볼 수 있습니다. `Esc` 또는 바깥 클릭으로 닫습니다. 매뉴얼의 이동 버튼은 실제 기능 화면을 열고 현재 피드백과 실험 상태를 유지합니다.

셋업 실험의 기본 방식은 **탐색 추천**입니다. 구간·속도·증상을 선택하고 ‘피드백으로 분석 갱신’을 누르면 유효랩 1개 또는 무효·미완주 랩의 정상 코너 구간에서 운전 편의를 위한 작은 변경 하나를 찾습니다. 랩타임이 일정할 필요는 없습니다. 실제 현재 셋업 값과 해당 코너의 충분한 측정이 있어야 하며, 후보는 ‘근거 약함’으로 표시합니다. 차량별 변경 단계가 확인되지 않으면 숫자를 만들지 않고 Garage 한 클릭을 안내합니다. 먼저 평소 페이스로 1~2랩 달려 체감과 조향 수정을 확인하고 더 불안해지면 원복하세요.

후보의 실험 시작 버튼으로 원래 값·목표값·변경 전 파일 A·비교 기준·목표를 저장합니다. 변경 후 새 파일을 선택해 B로 연결하면 A는 그대로 유지됩니다. 주행 후 증상 변화, 운전 편의와 부작용을 기록하고 A/B 결과를 확인하세요. 진행 중 실험과 파일별 피드백은 같은 브라우저에서 새로고침해도 복원됩니다. 실험 중 수집된 새 Garage61 자료는 알림으로 표시하며 기준을 자동 교체하지 않습니다.

**근거 우선 추천**은 기존 반복 신호·외부 기준 중심의 후보를 사용합니다. 탐색 체감 개선과 셋업 효과 확정은 구분합니다. 목표는 운전 편의·단기 페이스·긴 주행 안정성 중 선택합니다. A/B는 일반 주행 각 3개, 퀄리파잉 각 2개, 긴 주행 목표 각 5개의 유효랩부터 자연 편차를 함께 계산하며, 표본 부족은 미확정입니다. 완주율과 실수, 여러 랩의 입력도 비교합니다. 연료·노면·타이어·BOP 등 주요 조건이 다르거나 알려지지 않으면 효과 확정과 개인화 학습을 보류합니다. 여러 설정을 함께 바꾼 실험은 단일 설정 효과로 학습하지 않습니다. 제동 불안만으로는 브레이크 바이어스 방향을 정하지 않습니다.

목록에는 짧은 주행과 분석 제한 파일도 표시됩니다. 먼저 가벼운 파일 정보와 저장된 인덱스를 표시한 뒤 선택한 파일을 분석합니다. 아직 분석하지 않은 랩 수는 ‘확인 중’입니다. 정상 구간은 코칭과 탐색에만 재사용하며 공식 랩 페이스와 A/B 표본에는 추가하지 않습니다. 없는 측정 채널은 ‘측정 불가’로 표시합니다.

상단에서 내 기준 랩·Garage61 한 드라이버의 실제 랩·여러 랩 합성 기준을 선택하고 적용하면 요약·그래프·코너 카드가 같은 기준을 사용합니다. 코너를 확대하면 상세 데이터를 다시 가져옵니다. 분석 격자는 약 2m 간격이며 최대 25,000점을 사용하므로 50km보다 긴 트랙에서는 더 넓어질 수 있습니다. 측정 범위 밖이나 큰 데이터 누락은 그래프로 이어 그리지 않습니다. 자동 코너 구간은 트랙의 공식 코너 이름과 다를 수 있습니다.

세션 유형 버튼으로 기록 저장을 확정합니다. A/B 결과를 장기 기억에 저장하려면 두 파일을 같은 세션 유형으로 먼저 분류하세요. Garage61 인증·조회·다운로드가 제한되면 상태를 확인하고 검증된 로컬 캐시로 분석할 수 있습니다.

### 점검 개선 (2026-10-09)

- 연습·퀄리파잉에서는 완료 랩 수 차이로 랩핑 접근을 안내하지 않습니다. 빠른/느린 클래스 구분은 SDK의 클래스 예상 랩타임이 있으면 그 값을 사용합니다.
- 같은 클래스 차량과의 간격은 SDK의 위치 도달 예상 시간이 거리 환산과 일치할 때 그 값을 사용합니다. 여전히 공식 시간차가 아닌 추정입니다.
- 출발선에 걸친 코너도 분석에 포함하고, 자동 코너 번호는 차량·트랙·레이아웃별로 저장해 재시작 후에도 유지합니다(개인 DB 옆 `corner-definitions.json`, 삭제하면 다시 감지).
- 같은 파일의 반복 분석과 음성 메모 조회가 빨라졌습니다. 기존 음성 메모는 첫 실행 때 내용 손실 없이 새 저장 형식으로 옮겨집니다.
- 개발자·에이전트용 구조 설명과 남은 작업은 [AGENTS.md](AGENTS.md)에 있습니다.

## 연습 결과 확인 보강 (1.1.0 이후 작업본)

‘오늘의 한 가지’는 **연습 종료**, **입력 목표 달성**, **페이스 개선 확인**을 구분합니다. 브레이크 해제 과제는 최저속도만 보지 않고 실제 해제 지점을 측정합니다. ABS·속도·제동 거리·조향 등 과제의 부가 조건도 함께 확인하며, 필요한 채널이 없으면 달성으로 세지 않습니다.

파일 비교는 같은 코너 범위의 같은 통과들에서 입력과 시간을 계산합니다. 양쪽 유효 통과가 각각 3회 이상이고, 연료·노면·타이어·BoP·셋업 조건을 확인할 수 있으며, 시간 개선이 구간별 편차(IQR)보다 커야 ‘개선 확인’이 됩니다. 조건이 다르거나 부족하면 관측값과 확인이 필요한 이유를 보여 줍니다. 이는 주행 과제 확인이며 셋업 효과의 학습 근거로 쓰지 않습니다. 기존 과제의 기준 자료가 부족하면 **과제를 처음 정한 IBT를 다시 분석**해 보강할 수 있습니다.

Active Reset 반복 연습의 각 시도는 `data/practice-drills.jsonl`에 자동 저장됩니다(`IRACING_DRILL_HISTORY_PATH`로 변경 가능). 구간 시간·목표 입력·부가 조건·복귀 위치·출발 조건이 남고, 위치나 출발 조건이 달라지면 다른 묶음으로 비교합니다. 저장은 SDK 읽기와 별도 스레드에서 하며 음성이나 녹음은 저장하지 않습니다. **저장된 반복 연습 기록**을 펼치면 최근 12번 연습의 각 최근 30개 시도를 볼 수 있습니다. 파일에는 전체 시도가 보존됩니다. 이전 버전에서 저장하지 않은 시도는 복구하지 않습니다.

**연습 종료로 기록**을 눌러도 같은 차량·트랙·레이아웃의 이후 정상 주행을 분석하면 가장 최근 종료 과제를 다시 확인합니다. 종료 전 파일을 다시 열어 확인한 것으로 처리하지 않습니다. ‘배운 것’에는 수동 종료 횟수와 검증된 개선을 따로 표시하며, 조건을 확인하지 않은 과거 양수 델타는 확인된 시간에 더하지 않습니다.

**설정 → 오버레이**에서 가로·세로 크기, 위치, 표시·배경 불투명도를 각각 조절한 뒤 **현재 설정 저장·고정**을 누르면 다음 실행에도 배치가 유지됩니다. 고정 중에는 게임으로 클릭을 통과시킵니다. 바꾸려면 **고정 해제·편집**을 누르세요. 저장 파일은 데이터 폴더의 `overlay-settings.json`입니다. **미리보기**는 게임 없이 보는 가상 데이터이며, 실제 주행 화면과 구분합니다.

비교 그래프는 같은 트랙 위치를 기준으로 맞춥니다. 느리게 달리는 포메이션 랩에서도 왼쪽 이력이 짧아지지 않도록 이미 수집한 최대 3분의 기록에서 필요한 범위를 고릅니다. 아직 달리지 않은 구간, 피트·차량 이탈·관측 단절 전의 입력은 채워 넣지 않습니다. 화면 갱신은 계산·전달 시간을 포함해 30Hz를 목표로 하며, 받은 입력은 별도 애니메이션 차례를 기다리지 않고 그립니다.

출발선을 지나도 직전 랩의 입력 이력을 유지합니다. 기준 랩의 끝·시작에 있는 관측 표본 사이가 25m·0.5초 이내인 경우에만 작은 경계 공백을 연결하며, 큰 누락은 채우지 않습니다. SDK의 랩 번호와 위치 갱신 시차를 처리하고, 주행 중 조건에 맞는 기준은 작은 연료·온도 변화 때문에 매 랩 다시 불러오지 않습니다.

비교할 기준 랩이 없으면 내 최근 6초의 페달 그래프와 현재 기어를 표시하며, 하단에는 **현재 속도 · 브레이크·가속 입력률**을 보여 줍니다. 측정값이 없는 항목은 `—`입니다. 주행 오버레이에 Garage61 토큰·연결·검색 상태를 띄우지 않습니다. 기준이 연결되면 기존 코너 시간 차이·제동 위치 차이 표시로 돌아갑니다.

**주행 중 자동 표시**를 켜면 차량 탑승 중 같은 크기의 창을 사용합니다. 연습·퀄리·레이스의 기본 화면은 상단 글자 없이 넓힌 Garage61 비교 그래프이며, 하단에는 같은 기준 대비 **직전 코너 시간 차이·제동 시작 위치 차이**를 표시합니다. 손실은 노랑·단축은 초록·제동 위치는 하늘색입니다. 주행 파일 분석으로 저장된 코너 구간과 깨끗한 통과가 있어야 비교하며, 관측하지 못한 제동 시작은 추정하지 않습니다. 미측정은 `—`로 표시하고, 30초 지난 결과·피트·이동 복귀·연결 단절 뒤에는 이전 수치를 쓰지 않습니다. 연습에서는 같은 차·트랙·레이아웃의 실제 ‘오늘의 한 가지’ 과제가 있으면 기존 목표·결과 화면을 사용하고, 일반 주행과 코너 반복 연습 모두에서 통과 결과와 최근 5회를 측정합니다. 5회 모두 목표와 부가 조건을 충족하면 축하가 나옵니다. 입력 달성은 페이스 개선 확정과 구분하며, 개선 확인은 이후 정상 주행 파일 분석을 사용합니다. 차량 밖·리플레이·세션 종료·연결 끊김에는 숨깁니다.

그래프는 실제 내 입력을 형광 실선으로, 과제에서 선택한 내 기준 랩 또는 Garage61 종합 기준을 옅은 면으로 표시합니다. 같은 트랙 위치를 맞추고 기준의 다음 2초를 보여 줍니다. 과제가 없으면 현재 조건과 비슷한 Garage61 기준을 찾습니다. 과제의 기준 파일·선택 정보가 없으면 다른 랩으로 대체하지 않고 확인 필요로 표시합니다. 이전 과제는 과제를 정한 파일과 기준을 다시 분석해야 기준 정보가 복구될 수 있습니다. 조향 목표에서는 실제 조향 입력도 표시합니다.

자동 표시가 켜져 있으면 세션 연결 후 차량·트랙·노면 조건이 확인되는 대로, 차량 탑승·피트 출구 이전에도 기준을 준비합니다. **로컬 `Garage61_References/`와 `live/`의 CSV·메타데이터 캐시부터 확인**하고, 같은 차량·레이아웃과 조건에 맞는 자료가 없으면 설정된 Garage61 토큰으로 다운로드합니다. SQLite DB에 텔레메트리 곡선이 들어 있는 방식은 아닙니다. 조건이나 연결을 확인할 수 없으면 준비가 늦어질 수 있으며, 준비 전에는 내 입력만 표시합니다.

iRacing의 차량별 타이어 번호와 Garage61의 타이어 코드는 직접 비교하지 않습니다. 이를 같은 코드로 취급해 연동 후에도 기준 그래프가 나오지 않던 오류를 수정했습니다. 차량·레이아웃·노면의 건조/젖음·깨끗한 랩·기록 시기·온도·연료 조건으로 기준을 고르며, **타이어 일치 여부는 미확인**으로 둡니다. 이 한계는 설정 화면의 기준 상태에 표시하고 주행 HUD에는 띄우지 않습니다. 타이어가 바뀌면 기준을 다시 확인합니다.

자동 기준은 ‘깨끗한 랩’ 표시뿐 아니라 **CSV 원본과 실제 주행 곡선도 검사**합니다. 한 바퀴의 시작·끝 누락, 피트·트랙 밖 표본, 역방향 위치 이동, 페달 누락·범위 오류, 0.5초 넘는 시간 단절, 장시간 저속, 속도·거리·랩타임 불일치가 있으면 제외합니다. 비슷한 조건의 정상 페이스에서 크게 벗어난 랩도 제외하고, 조건 점수가 비슷하면 기록이 빠른 랩을 최신 랩보다 우선합니다. 저장된 캐시와 새 다운로드에 같은 검사를 적용하며, 새 파일은 검사를 통과한 뒤에만 정식 캐시에 넣습니다. 이 검사는 기준으로 쓰기 부적절한 데이터를 거르는 것이며 최적 주행이나 셋업 일치를 보증하지는 않습니다.

기본 화면 오른쪽의 큰 숫자는 **현재 기어 단수**입니다. 같은 트랙 위치의 Garage61 기어보다 낮으면 **빨강**, 같으면 **흰색**, 높으면 **초록**입니다. 변속 사이의 단수를 보간하지 않으며, 기준 기어가 누락되면 현재 단수를 회색으로 표시합니다. 현재 기어도 없으면 `—`, 중립은 `N`, 후진은 `R`이며 비교 색상을 적용하지 않습니다. 창 크기는 유지하며 기본 그래프 옆에 표시합니다.

평소에는 기존 하단의 직전 코너 시간 차이와 제동 시작 차이를 좌우에 표시합니다. 추가 안내가 있을 때만 **같은 하단 자리를 최대 4초 동안 중앙 정렬 문구와 종류별 배경색으로 교체**합니다. 랩 기록은 파랑, 개선은 초록, 앞차 접근은 청록, 연료·무효 등 주의 안내는 노랑 계열입니다. 안내가 끝나면 기존 문구와 배경으로 돌아옵니다. 오버레이는 기존 **390×150** 비율을 유지하며 그래프·기어를 가리거나 줄을 추가하지 않습니다.

현재 입력으로 **0.5초 이상 안정된 직선 주행**을 확인했을 때 안내를 시작합니다. 제동·리프트·큰 조향·옆 차량 겹침·경고가 발생하면 즉시 닫고 기존 표시로 돌아갑니다. 주변 차량·깃발·입력 채널이 불명확하면 표시하지 않습니다. 그래프를 덮지 않으므로 긴 직선이나 미래 Garage61 기준이 없어도 관측된 랩·연료 안내를 표시할 수 있습니다. 오래된 상황은 뒤늦게 표시하지 않으며, 연결 단절·피트·리플레이·세션 변경 때는 숨깁니다.

| 세션 | 추가 안내 | 표시 근거 |
| --- | --- | --- |
| 연습 | 반복 코너 제동 위치 | 같은 Garage61 랩 대비, 같은 코너를 연속 3회 통과하며 매번 0.1초 이상 손실과 같은 방향 5m 이상 제동 위치 차이가 관측됨 |
| 연습 | 개선 확인 | 같은 기준·같은 코너의 이전 깨끗한 3회 중앙값보다 이번 구간이 0.15초 이상 단축. 반복 표시는 직전 개선 수치보다 다시 0.15초 이상 단축된 경우만 허용하며 입력 변화가 원인이라고 단정하지 않음 |
| 연습·레이스 | 랩 완료 | 출발선 사이를 끊김 없이 관측한 깨끗한 랩과 iRacing 완료 기록. 이전 베스트가 없으면 이번 기록만 표시. 출발선 뒤 SDK 기록·랩 시계 갱신을 확인해 비슷한 직전 랩 기록을 재사용하지 않음 |
| 연습·퀄리 | 최대 손실 구간 | **별도 카드 없이 랩 결과 안에 합쳐** 같은 Garage61 기준과 비교한 깨끗한 구간 중 최대 손실을 표시. 비교한 구간 수를 명시하고 확정 전에는 공식 코너 번호라고 부르지 않음 |
| 퀄리 | 유효 랩 결과·베스트 갱신 | 첫 유효 랩과 베스트 미갱신 랩도 표시. 베스트 갱신은 iRacing 기록과 일치해야 하며 이전 베스트를 모르면 차이를 만들지 않음 |
| 퀄리 | 기록 무효 | 해당 랩에서 인시던트 증가를 관측함. 트랙 이탈도 관측된 경우에만 그 사유를 표기 |
| 레이스 | 이번 랩 피트 | 기존 엔지니어의 관측 연비와 연료 잔여 랩 계산. 완주 연료가 충분하면 표시하지 않으며, 필요한 급유량을 모르면 `—` |
| 레이스 | 급유 설정 부족 | 연료 부족으로 피트가 필요하고 남은 연료가 2.5랩 이하일 때 필요 급유량보다 현재 설정이 1L 넘게 부족함. 급유 체크가 꺼져 있으면 설정량 0L로 비교. ‘이번 랩 피트’가 필요한 경우 그 카드에 합쳐 표시하며 게임 설정은 변경하지 않음 |
| 레이스 | 앞차 접근 | 같은 클래스 바로 앞 차량과 출발선에서 측정한 연속 간격이 랩마다 0.15초 넘게 줄고 8초 이내임 |

일반 안내는 **랩당 최대 1회**, 안내 종료 후 **최소 45초 간격**으로 제한합니다. 연료·무효 같은 경고는 우선하되 30초 간격을 두며 상황이 더 급해지면 예외적으로 교체합니다. 급유 설정 부족은 120초 이내 반복하지 않습니다. 그래프는 안내 중에도 계속 갱신합니다. ‘오늘의 한 가지’를 진행 중인 연습에서는 기존 목표 화면을 유지합니다. 게임 없이 여는 기존 미리보기는 가상 데이터이며 위 안내의 실제 세션 조건을 만들지 않습니다.

저장된 IBT의 30Hz 재생·임시 저장소·Windows 오버레이 검증을 완료했으며, 실제 게임 주행 중의 표시와 사용감은 별도 확인이 필요합니다. 이미 배포한 1.1.0 공유본과 패치 기준 파일은 유지합니다.

## 설정과 공유 (2026-10-12)

- 모든 기록·음성·키·설정은 **데이터 폴더 하나**에 있습니다. 새로 받은 판은 프로그램 폴더 안의 `data`를 씁니다. 위치는 "설정" 탭 맨 위에 표시됩니다.
- "설정" 탭의 "설치 설정"에서 주행 파일(IBT) 폴더, Google Cloud 서비스 계정 키 파일, Garage61 토큰을 넣습니다. 저장하면 바로 적용됩니다. 키와 토큰은 이 컴퓨터의 데이터 폴더에만 저장되고 화면에 다시 표시되지 않습니다.
- Google 키가 없어도 주행 분석과, 받아 둔 음성으로 나오는 스포터·엔지니어 안내는 됩니다. 키는 마이크 질문, AI 답변, 새 문장 합성에만 필요합니다.
- 다른 사람에게 줄 때는 `python scripts/make_share_copy.py`로 공유본을 만드세요. 기록, 음성 메모, 키, 토큰을 뺀 폴더가 `share/iracing-coach`에 생깁니다. 받은 사람은 `설치.bat` → `실행.bat` 순서로 실행합니다.

2026-10-18 리팩토링에서 분석·저장·API·화면·실시간 오버레이 코드를 역할별로 분리했습니다. 실행 방법, 데이터 형식·위치, 화면 주소(`http://localhost:24157`)는 유지합니다. 공유 도구는 분리한 백엔드 모듈과 오버레이 보조 파일도 포함하며, 오버레이 의존 파일이나 Pillow 설치 항목이 빠지면 공유본 생성을 중단합니다. 이번 작업에서는 버전과 기존 배포 기록을 변경하지 않았습니다.

### 업데이트를 작은 패치로 내보내기

1. 버전을 올리고(`backend_api.py`의 `APP_VERSION`, `package.json`) `npm run build`를 실행합니다.
2. `python scripts/make_share_copy.py --out share/iracing-coach-1.0.1`로 새 공유본을 만듭니다.
3. `python scripts/make_patch.py --from 1.0.0 --new share/iracing-coach-1.0.1`을 실행하면 `share/iracing-coach-patch-1.0.0-to-1.0.1.zip`이 생깁니다.

받는 사람은 앱을 끄고 이 압축 파일을 쓰던 폴더에 덮어쓰기로 풀면 됩니다. 패치는 프로그램과 새 음성만 담고, `data` 폴더의 기록·설정·키·토큰·확정한 코너 번호·피트 기록은 담지 않으므로 그대로 남습니다.

## 데이터 위치

- IBT: 사용자 Documents/iRacing/telemetry 등 기존 검색 폴더
- 개인 DB: 데이터 폴더의 `iracing_tuner.sqlite3`
- Garage61 기준 CSV: 데이터 폴더의 `Garage61_References`
- 토큰: 기존 Garage61 토큰 설정 파일 또는 환경변수
- 자동 코너 정의: 개인 DB 옆 `corner-definitions.json` (환경변수 `IRACING_CORNER_DEFINITIONS_PATH`로 변경 가능)
- 파일 메타데이터 인덱스: 개인 DB 옆 `telemetry-file-index.sqlite3` (환경변수 `IRACING_FILE_INDEX_PATH`로 변경 가능)

경로는 `IRACING_TELEMETRY_DIRS`, `IRACING_TUNER_DB_PATH`, `IRACING_EXTERNAL_REFERENCE_DIR` 환경변수로 변경할 수 있습니다. `IRACING_AI_ENABLED=0`과 `GARAGE61_AUTO_COLLECT=0`으로 자동 AI/외부 수집을 비활성화할 수 있습니다.
