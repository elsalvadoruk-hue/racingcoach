# 자동 업데이트 배포 방법 (개발자용)

앱은 실행할 때 GitHub 릴리스를 확인합니다. 그때 새 버전이 있거나 이 버전에 필요한 음성이 빠져 있으면 업데이트 창을 띄웁니다. 켜 둔 동안에도 6시간마다 다시 확인하지만, 그 결과는 설정 탭의 "업데이트" 칸에만 표시하고 창은 띄우지 않습니다. 주행 중에 창이 뜨지 않게 하기 위해서입니다.

## 앱이 하는 일

- **프로그램**: `vX.Y.Z` 태그 가운데 가장 높은 정식 릴리스를 `APP_VERSION`과 비교합니다. 초안과 프리릴리스는 제외합니다. "업데이트 받기"를 누르면 앱이 계속 도는 동안 `.update/`에 내려받아 풀어 둡니다. "지금 다시 시작해서 적용"을 누르면 실행.bat의 실행 도우미가 서버를 끄고 새 파일을 덮어쓴 뒤 다시 켭니다. 화면은 스스로 새로고침됩니다.
  - `data/`(기록·설정·키·토큰·음성)는 덮어쓰지 않습니다.
  - 받을 때 새 파일마다 해시를 기록하고, 지금 설치된 파일과 내용이 같은 것은 크기·수정 시각을 `pending.json`에 적어 둡니다. 다시 시작할 때는 그 파일들을 읽지 않고 바뀐 파일만 씁니다(1.4.3부터, 약 90초 → 몇 초). 적용은 *이전* 버전의 실행 도우미가 하므로, 이 개선은 1.4.3에서 그다음 버전으로 갈 때부터 적용됩니다.
  - `requirements*.txt`가 바뀌었으면 pip 설치를 다시 합니다.
  - 릴리스에 `racingcoach-app-X.Y.Z.zip`이 첨부되어 있으면 빌드된 화면을 그대로 씁니다. 첨부가 없으면 태그 소스를 받아 설치.bat처럼 화면을 다시 빌드합니다. 이때는 Node.js가 필요하고 몇 분 걸립니다.
  - Git으로 받은 폴더(`.git`이 있는 폴더)에서는 덮어쓰지 않고 `git pull` 안내만 보여 줍니다.
- **음성**: 이 프로그램에 필요한 음성 목록은 `releases/voice-<버전>.json` 가운데 가장 높은 버전입니다. 목록에 있는데 데이터 폴더에 없는 음성만 골라, `voice` 릴리스에 첨부된 조각 zip 가운데 그 음성이 든 조각만 받습니다.
  - "이전 버전 음성 정리"는 예전 음성 목록에만 있던 파일만 지웁니다. 사용자의 Google 키로 새로 합성된 음성은 지우지 않습니다.
  - Google Drive 링크(`app_update.VOICE_DRIVE_URL`)는 직접 받을 사람을 위해 업데이트 창에 계속 표시됩니다.

## 새 버전을 낼 때

1. `APP_VERSION`(iRacing_Backend/backend_api.py)과 package.json의 `version`을 올리고, 패치 노트를 쓰고, 커밋합니다.
2. 2.0.3부터 LMU는 Python 리더가 기본입니다. 일반 SDK 구조 변경 때문에 브리지를 새로 만들 필요는 없습니다. 릴리스 제작 시 포함 잠금 DLL·소스·매니페스트의 해시를 검사합니다. 옛 브리지는 명시적 `IRACING_LMU_READER=bridge` 되돌리기용으로 함께 둡니다. 이 경로의 SDK·소스가 바뀌었을 때만 개발 Windows PC에서 `python scripts/prepare_lmu_bridge.py`로 준비합니다.
3. `npm run build`
4. `python scripts/make_release_assets.py app` → `share/release/racingcoach-app-X.Y.Z.zip`. 잠금 DLL과 되돌리기용 브리지를 포함하고 runtime은 제외합니다. `python scripts/make_release_assets.py setup` → 처음 설치용 `racingcoach-setup-X.Y.Z.zip`. 고정 주소·SHA256의 Python 런타임 전체와 라이선스가 추가됩니다.
5. 릴리스 초안을 만들고 앱·setup ZIP을 모두 첨부한 뒤 원격 크기·SHA256을 확인하고 정식 공개합니다. setup ZIP을 처음 설치용으로 먼저 안내하고, 기존 사용자는 앱 업데이트 창을 그대로 쓰도록 설명합니다.
   릴리스 본문이 업데이트 창에 그대로 보이므로 변경 내용을 사용자용으로 씁니다.

## 음성이 바뀐 버전을 낼 때

1. 지금처럼 `python scripts/make_voice_pack.py --version X.Y.Z ...` 를 실행해 `releases/voice-X.Y.Z.json`을 만들고 커밋합니다. 이 파일이 프로그램 업데이트와 함께 사용자에게 가서 "필요한 음성"이 바뀝니다.
2. `python scripts/make_release_assets.py voice --version X.Y.Z`
   - 이전 목록은 GitHub `voice` 릴리스의 `voice-chunks-latest.json`에서 읽어 옵니다. 바뀌지 않은 음성은 예전 조각을 그대로 가리키므로, 새 조각에는 새 음성과 바뀐 음성만 들어갑니다.
   - 처음 올릴 때는 전체 음성이 약 48 MB씩 조각으로 나뉩니다(1.4.0 기준 약 13개).
   - 쓰지 않는 음성이 예전 조각에 많이 쌓였다고 안내되면 `--repack`으로 전부 새로 묶습니다.
3. 출력된 `gh release create voice ... --latest=false`(처음 한 번)와 `gh release upload voice ... --clobber`를 실행합니다.
   - 조각 이름에는 내용 해시가 붙어 있어서 한 번 올린 조각은 바뀌지 않습니다. 예전 조각은 지우지 마세요. 아직 예전 목록을 가진 사용자가 받을 수 있어야 합니다.
4. 프로그램 릴리스(위 절차)를 냅니다. 사용자는 프로그램을 업데이트한 뒤 빠진 음성만 받게 됩니다.

음성을 GitHub에 아직 올리지 않았으면 앱은 "아직 없습니다"라고 알리고 Drive 링크를 안내합니다.

## 주의

- 실행.bat의 `call ... launch_app.py %* & goto finished` 줄과 `:finished` 라벨은 유지하세요. 업데이트가 실행 중인 실행.bat을 덮어써도 창이 라벨로 돌아가게 하는 장치입니다.
- 1.4.1 이하 사용자에게는 업데이트 기능이 없으므로, 이 기능이 들어간 첫 버전은 지금처럼 직접 받아 덮어쓰게 안내합니다.

## 옛 LMU 연결 파일만 배포하기 (2.0.2·명시적 bridge 되돌리기용)

사용자 앱은 컴파일러를 실행하지 않습니다. 개발자가 LMU SDK가 있는 Windows PC에서 연결 파일을 준비합니다.

1. `python scripts/prepare_lmu_bridge.py`를 실행합니다. 배포용 DLL/매니페스트와 `share/lmu-bridges/bridge-<identity>-win-x64.zip`이 만들어집니다. SDK 헤더는 포함하지 않습니다.
2. 처음 한 번 `gh release create lmu-bridges --title "LMU 연결 파일" --notes "앱이 자동으로 받는 연결 파일입니다." --latest=false`로 배포 채널을 만듭니다. 이 태그는 앱 정식 버전 비교에서 제외됩니다.
3. 출력된 `gh release upload lmu-bridges ...` 명령으로 ZIP을 추가합니다. SDK·소스 조합마다 이름이 다르므로 기존 파일을 삭제하거나 교체하지 마세요.
4. 새 SDK라도 브리지 소스가 그대로면 사용자 앱의 버전 변경 없이 이 파일만 배포할 수 있습니다. 브리지 소스나 Python 변환 코드도 바뀌면 앱 업데이트가 필요합니다.

앱은 현재 SDK와 소스의 조합에 해당하는 파일만 요청합니다. 내려받은 파일의 SDK/소스/DLL 해시와 64비트 형식을 검증한 뒤 캐시에 저장하며 게임에는 데이터를 쓰지 않습니다. 다운로드는 별도 작업 스레드에서 수행하고 실패·미제공은 5분 뒤 자동 재시도합니다. 설정의 “실시간 연결”으로 즉시 다시 확인할 수도 있습니다. 기존 `/api/lmu/live/bridge/build` 요청도 다운로드 준비로 처리하며 컴파일러를 실행하지 않습니다.
