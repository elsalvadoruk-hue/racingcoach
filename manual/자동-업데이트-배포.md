# 자동 업데이트 배포 방법 (개발자용)

앱은 시작할 때 정식 `vX.Y.Z` 릴리스를 확인합니다. 초안·프리릴리스·음성 전용 태그는 앱 업데이트 대상에서 제외합니다. 켜 둔 동안의 재확인은 **설정 → 업데이트**에만 표시하며 주행 중 업데이트 창을 띄우지 않습니다.

## 앱과 설치본 배포

1. 최신 main과 작업 브랜치의 차이를 확인하고 개인 데이터와 실행 중 앱을 보존할 별도 작업 폴더에서 통합합니다.
2. `iRacing_Backend/backend_api.py`의 `APP_VERSION`, `package.json`, `package-lock.json`의 루트 패키지 버전을 맞추고 패치 노트·README를 갱신합니다. 의존성 버전은 함께 바꾸지 않습니다.
3. [개발 안내](개발-안내.md)의 전체 백엔드·화면·런처/패키징 검사를 임시 저장소와 합성 설정에서 실행하고 `npm run build`로 최종 화면을 만듭니다. LMU 잠금 DLL·native rollback 번들과 화면·라이선스가 포함되는지도 확인합니다.
4. Git 스테이징·전체 이력 감사를 통과한 소스와 문서를 커밋합니다. 실제 사용자 기록·키·토큰·로그·음성 캐시는 포함하지 않습니다.
5. `python scripts/make_release_assets.py app`으로 `share/release/racingcoach-app-X.Y.Z.zip`을 만듭니다. Git 추적 파일과 최신 화면 빌드를 담으며 `runtime/`은 제외합니다.
6. `python scripts/make_release_assets.py setup`으로 `racingcoach-setup-X.Y.Z.zip`을 만듭니다. 고정한 Python 런타임의 크기·SHA256·압축 경로·라이선스를 검사해 처음 설치본에만 포함합니다.
7. 두 ZIP의 CRC·경로·내용·개인정보 제외·버전·해시와 실제 임시 설치/업데이트를 검증합니다. setup의 runtime을 제외한 파일은 app ZIP과 같아야 합니다. 업데이트는 기록·설정·음성·runtime을 보존해야 합니다.
8. 사용자의 해당 버전 업로드 승인을 확인하고 main/태그를 반영합니다. GitHub 릴리스를 초안으로 만든 뒤 두 ZIP을 첨부합니다. 원격 asset 크기·SHA256을 로컬과 대조한 뒤 정식 latest로 공개합니다. 릴리스 본문은 앱 업데이트 창에도 표시되므로 사용자용으로 씁니다.
9. 공개 ZIP 다운로드·해시·latest 및 실제 업데이터의 버전 선택을 확인합니다. 기존 버전의 태그·파일은 바꾸지 않습니다.

Git으로 받은 폴더에서는 앱이 소스를 덮어쓰지 않고 `git pull`을 안내합니다. 설치본 업데이트는 `.update/`에 준비한 뒤 재시작 시 적용하며 `data/`, `runtime/`, 키·토큰·기록·음성을 보존합니다. 패키지가 바뀌면 필요한 설치를 수행합니다. 앱 ZIP이 없으면 태그 소스로 돌아가 화면 빌드에 Node.js가 필요하므로 정식 릴리스에는 앱 ZIP을 반드시 첨부합니다.

## LMU 연결 파일

2.0.3부터 기본은 **잠금 전용 DLL + 설치 SDK 헤더를 읽는 Python 리더**입니다. SDK 변경마다 사용자가 컴파일러를 받거나 DLL을 만들 필요가 없습니다. 잠금 소스·DLL·매니페스트를 함께 보존하고 `make_share_copy.bundled_bridge_files`의 검증을 통과해야 합니다.

기존 `iRacing_Backend/lmu_bridges/`의 native 번들은 `IRACING_LMU_READER=bridge` rollback용으로 유지합니다. native 소스나 해당 SDK용 번들을 바꿀 때만 개발자가 `python scripts/prepare_lmu_bridge.py`로 준비·검증합니다. 기존 `lmu-bridges` 다운로드 채널과 예전 앱용 파일은 보존합니다. LLVM-MinGW 자동 다운로드·컴파일 방식은 기본 배포에 포함하지 않습니다.

## 음성 변경 배포

필요한 음성은 `releases/voice-<버전>.json` 중 가장 높은 버전의 목록으로 결정합니다. 음성팩 버전과 앱 버전은 독립적입니다. 새 Google 합성은 과금 범위에 대한 사용자 승인을 먼저 확인하며 준비된 음성을 다시 합성하지 않습니다.

1. 승인한 고정 안내와 숫자 준비 범위만 검증해 음성 목록을 만듭니다. 실제 재생·캐시·이전 음성 보존을 확인합니다.
2. `python scripts/make_release_assets.py voice --version X.Y.Z`로 변경분을 포장합니다. 기본은 원격 `voice-chunks-latest.json`을 기준으로 기존 조각을 재사용합니다. 로컬 전체팩에서 만들려면 `--from-zip`을 사용합니다.
3. `voice` 릴리스에 새 해시 이름의 ZIP과 버전 고정 JSON을 올리고 마지막에 latest 목록을 반영합니다. `voice` 릴리스는 latest 앱 릴리스로 지정하지 않습니다. 기존 ZIP·버전 JSON을 삭제하거나 덮어쓰지 않습니다.
4. 원격 다운로드 해시와 쿼리 없는 latest URL의 버전까지 확인한 뒤 로컬 음성 목록을 앱과 함께 커밋·배포합니다. 이미 공개한 목록과 파일을 다시 올릴 필요는 없습니다.

앱은 목록 중 빠진 음성만 받습니다. “이전 버전 음성 정리”는 과거 목록에만 있는 파일만 지우며 사용자가 새로 합성한 음성은 지우지 않습니다. Google Drive 전체팩은 수동 다운로드의 예비 경로이며 별도 승인 없이 수정하지 않습니다.

`실행.bat`의 `call ... launch_app.py %* & goto finished`와 `:finished` 라벨은 유지하세요. 업데이트가 실행 중인 배치 파일을 덮어써도 실행 도우미로 돌아가기 위한 장치입니다. 1.4.1 이하의 수동 이전은 [설치 상세 안내](설치-상세-안내.md)를 따릅니다.
