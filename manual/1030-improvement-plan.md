## 2~7단계 구현 결과

2단계: LMU 충돌 시각·크기와 랩 무효·랩 집계·트랙리밋을 공통 표본으로 전달한다. 충돌은 연속 관측 구간 안에 발생한 새 사건만 손상 비교에 사용한다. 긴 공백 중 사건·과거 시각·반복 프레임은 새 접촉으로 세지 않는다. 코너의 교통 맥락은 `SOLO`/`TRAFFIC_PRESENT`/`UNKNOWN`으로 보존한다. 통과 측정은 별도 `corner_observation`으로 남기고 깨끗한 단독 통과만 기준·비교 조언에 사용한다. 공식 판정 변화가 관측된 구간은 제외하되 이미 끝난 모든 구간을 일괄 무효화하지 않는다.

3단계: 완료 랩타임이 없어도 첫 랩의 유효 위치 이력을 수집한다. 스포터와 피트월은 같은 통과 이력을 공유하고 출처·원본 시각·표본 수·준비 부족 사유를 전달한다. 클래스 예상 랩타임만으로 접근 발화를 허용하지 않는다. LMU 직접 간격은 대상이 확인된 동일 랩·피트 밖·최신 전체순위 인접 차량만 비교값으로 전달한다. 대상 ID 없는 트랙상 직접값은 비교 불가 사유를 남긴다. 직접값으로 통과 이력을 덮지 않는다. 같은 scoring 기준 사이 속도를 적분해 제동 시 역행을 막고, 속도 결측·긴 관측 공백은 새 scoring 기준까지 위치 미확인이다. 라인은 scoring 확인 전 넘지 않는다. 4초 보관 한도는 유지하며 다른 명시 세션의 값으로 덮지 않는다. 같은 원본 시각의 반복은 이력을 지우거나 신선도를 연장하지 않는다.

4단계: 피트 손실 학습에서 코션·사고·견인·수리·트랙 밖·트랙 위 장시간 정차·표본 공백/역행·피트/속도 결측을 제외한다. 정상 랩 기준도 완전히 관측한 깨끗한 랩을 사용한다. 기존 개인 지식 파일을 일괄 수정하지 않고 새 적합 표본의 이동 손실·정차시간·샘플 수·근거를 남긴다. 타이어 작업 규칙 미확인은 단일 동시 작업 예상으로 바꾸지 않으며 계산 가능한 범위를 반환한다. 단일 자동 손실이 없으면 확정 복귀 순위·해당 음성을 만들지 않는다. 명시한 수동 손실 입력은 계속 사용할 수 있다.

5단계: LMU FL/FR/RL/RR의 펑크·바퀴 탈락·압력(kPa)·타이어/브레이크 온도(°C)·마모 원본 비율을 현재 시각과 함께 전달한다. reader에서 변환된 온도를 다시 변환하지 않는다. 0·False는 유효 관측이며 결측과 구분한다. 서비스 뒤 False 복구도 그대로 반영한다. 2초를 넘긴 자료는 현재 관측으로 표시하지 않는다. iRacing의 과거 갱신 타이어 값을 실시간 예열로 쓰지 않으며 최적 온도·마모 비례 그립 손실·새 경고 음성은 추가하지 않는다.

6단계: 포메이션을 처음 관측한 위치부터 다음 스타트라인까지를 하나의 안내 구간으로 사용한다. 기존 2~78% 배분을 이 구간에 적용하고 문장 길이·남은 예상 시간·기존 쉬는 간격·우선 무전을 확인한다. 정지 후 같은 시작 위치를 유지하고 세션/설정 변경에는 초기화한다. 불연속 이동·표본 공백·시간 부족은 생략 사유를 남기며, 첫 라인 도달과 그린 이후에는 추가 후보를 생성하지 않는다. 합성 검사에서 시간이 충분한 남은97/50/30/10% 구간 모두8개를 생성했다. 생성8개는 실제 재생8개 보장이 아니다.

7단계: 채택한16항목만 별도 `formation_items` 설정으로 제공한다. 출발 순위·참가 규모는 고정하고 지원되는 선택 카드/페이지를8초 간격으로 순환한다. 무전 OFF/브리핑0·분석/과제/비교 기준 없음에서도 현재 연료·날씨·LMU 바퀴/에너지를 사용한다. 기존 카드 선택·슬롯·입력 그래프 설정을 보존하고 추천 구성도 현재 포메이션 선택만 변경한다. 수동 포메이션 선택이어도 그린에서 종료한다. 긴 직접 작성 메모는 원문·부정어를 유지해 페이지로 나누며 수정·삭제를 반영한다. AI 답변은 메모로 사용하지 않는다.

기록은 게임·차량·트랙·레이아웃으로 나눈다. 옛 게임 식별 없는 기록은 다른 게임의 기록으로 추정하지 않는다. RaceHistory version1의 기존 자료를 보존하며 선택 필드와 유효 랩 기록을 추가했다. 경기 ID가 같은 결과는 중복 추가 대신 갱신하고 출발 출처·결과 상태·잠정 여부를 보존한다. 저장·분석/메모 조회는 큐4개·작업 스레드1개·2초 갱신으로 분리해 SDK loop에 새 파일/DB/네트워크/오디오 I/O를 넣지 않는다. 기존 분석은 명시 게임이 있는 자료만 새 텍스트의 근거로 사용하며 과거 자료를 일괄 재분석하지 않는다.

## 검증·보존

Python 성능 기준을 변경 전에 수집하고 실패 재현으로 원인을 고정한다. React 변경 단계에서 React Best Practices와 shadcn 지침을 적용하고, 최종 build와 Playwright·실제 네이티브 렌더링을 검증한다. UI 변경이 없는 1단계에 UI build/browser 결과를 기능 검증으로 대신하지 않는다.
검사는 임시 저장소·합성 SDK, AI/외부 수집 비활성화로 실행한다. 사용자 앱/게임·DB·설정·키·음성·옐로 정책·미채택 배틀 개발은 조작하지 않는다. 새 음원/유료 합성은 제외한다.
버전 상승·commit/push·릴리스는 이번 작업 범위에 없다. 구현·자동 검증과 실제 게임 가독성·새 실주행·한국어 청취를 구분한다. 소유QA 서버·브라우저·임시 저장소는 검증 뒤 정리하고 최종build·기존ZIP·검증 근거를 보존한다.
