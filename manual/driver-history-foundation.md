# 드라이버 리포트의 공통 주행 기록 기반

드라이버 리포트는 2.4.0(2026-10-27)부터 제공하며, 2.4.1에서 입력 관측을 9개 항목으로 넓혔습니다. 앱을 일반 주소로 실행하면 드라이버 리포트로 시작합니다. 실제 주행 뒤 종료를 확인하면 **주행 분석**으로 이동합니다. 왼쪽 **드라이버** 메뉴 또는 `#driver`에서도 관측 원장을 확인할 수 있습니다.

1920×1080 전체화면에서는 페이지 스크롤 없이 핵심 수치와 모든 기능을 한 화면에 배치합니다. 체감 네 가지 선택·도전 선택·평가·취소·가져오기 일시정지와 이어하기를 카드에서 조작합니다. 성향의 긴 근거, 성장 비교 방법, 체감의 상세 상황, 전체 도전·경기 이력은 각 카드의 상세 창에서 확인합니다.

제목 아래에는 개인 페이스·랩 간 편차 비율·분석 유효 랩 비율·시간당 인시던트 점수의 요약 카드 4개가 있습니다. 개인 페이스는 비교 조건을 확인한 랩타임 변화율이며 음수는 랩타임 감소를 뜻합니다. 같은 조건의 독립 세션 비교가 부족해도 같은 차량·코스의 날짜별 측정값이 있으면 **관측 페이스 변화**를 표시합니다. 이 값에는 연료·날씨·셋업 등 조건 차이가 포함될 수 있어 실력 향상으로 판단하지 않습니다. 편차는 MAD 비율이며 측정 1랩이면 0% 대신 —로 표시하고 2랩부터 계산합니다. 분석 유효 랩 비율은 완주 랩 중 앱의 판정이 확인된 유효/무효 랩으로 계산하며 게임의 공식 판정과 구분합니다. 인시던트는 **레이스·퀄리**의 개인 누적 카운터 증가점수를 같은 구간의 트랙 위 관측시간으로 나눈 값입니다. 연습과 세션 종류 미확인 기록은 점수·시간 모두에서 제외합니다. 정차는 포함하고 첫 누적값·공백·카운터 리셋·리플레이는 제외합니다. LMU처럼 개인 카운터 근거가 없는 경우는 —와 이유를 표시합니다. 구버전 요약은 전체 기록 분석 또는 **기존 기록 다시 확인**으로 보완할 수 있지만, 이번 표시·기간 집계 변경은 원본 재분석을 요구하지 않습니다.

성향 메인 카드는 측정값이 있는 항목을 3개씩 보여주며 **이전·다음**으로 넘깁니다. **측정 N / 전체 9종**에서 실제 측정 범위를 확인합니다. **자세히**의 **항목 설명** 탭에서 9개 항목 중 하나를 고르면 뜻·예시·대표 수치가 나오고 계산 조건·측정 근거를 펼칠 수 있습니다. **수치 읽는 법** 탭에는 반복 성향의 기준과 해석 범위를 모았습니다. 미측정 항목도 선택해 `—`와 보류 이유를 볼 수 있습니다. 각 항목의 입력 횟수·관측일·관측 기록·확인된 독립 세션을 구별하며, 값의 크기만으로 잘한 운전이나 실수라고 판정하지 않습니다. 성향과 주행 변화 카드의 **자세히** 버튼은 같은 크기로 표시합니다.

현재 입력 관측은 아래 9가지입니다. 입력 횟수가 많아도 독립 세션·관측일·반복 양상 근거가 부족하면 수치를 표시하면서 **관측**으로 유지합니다. 같은 조합에서 2일 이상·확인된 독립 세션 3개 이상·세션당 관련 입력 5회 이상 등 반복 조건을 통과하면 항목별 성향 이름을 붙입니다. 표의 시간은 원본 채널 주기의 오차를 함께 확인하며, 항목별 수치는 조합과 날짜에 같은 비중을 주어 요약합니다.

| 항목 | 무엇을 읽는지와 예 | 계산 기준 |
| --- | --- | --- |
| 제동·조향 | 브레이크를 밟는 동안 조향도 함께 한 비율입니다. 제동 1초 중 0.3초 겹치면 30%입니다. | 브레이크 10% 이상인 완전한 제동 구간에서 조향이 겹친 시간 비율의 중앙값입니다. 코너 위치나 주행선은 판정하지 않습니다. |
| 스로틀 전개 | 가속 페달을 20% 이하에서 80% 이상으로 올린 시간입니다. 0.8초에 걸쳐 밟은 입력과 빠르게 밟은 입력을 구분합니다. | 완전한 전개 구간의 소요시간 중앙값입니다. 시간 오차를 뺀 0.60초 이상과 더한 0.35초 이하를 구분하며 실제 가속 성과는 별도입니다. |
| 제동 전개 | 한 제동 입력이 구간 최대값의 20%에서 80%로 커진 시간입니다. 최대 브레이크가 80%라면 16→64% 시간을 읽습니다. | 최대 입력 30% 이상인 완전한 제동 구간의 상대 20→80% 시간 중앙값입니다. 오차를 뺀 0.45초 이상·더한 0.20초 이하를 구분합니다. |
| 제동 해제 | 브레이크를 놓아 가는 시간입니다. 페달을 오래 유지한 시간과 구별합니다. | 완전한 제동 구간의 마지막 상대 80→20% 시간 중앙값입니다. 오차를 뺀 0.45초 이상·더한 0.20초 이하를 구분합니다. |
| 가속 재조절 | 한 가속 입력 중 페달을 줄였다 다시 올린 횟수입니다. 40→80→55→80%는 한 번이며 마지막 해제는 세지 않습니다. | 최대 스로틀 60% 이상인 완전한 구간에서 12%p 이상 감소·회복하고 최소 0.15초 또는 원본 3주기 중 긴 간격을 확인한 횟수의 중앙값입니다. |
| 조향 전개 | 한 방향으로 핸들을 돌리는 입력이 커진 시간입니다. 많이 돌린 정도보다 입력 전개의 속도를 읽습니다. | 최대 조향 0.12rad 이상(iRacing) 또는 잠금범위 4% 이상(LMU)인 완전한 구간의 상대 20→80% 시간 중앙값입니다. 오차를 뺀 0.60초 이상·더한 0.25초 이하를 구분합니다. |
| 조향 재조절 | 한 방향 조향을 전개한 뒤 줄였다 다시 키운 횟수입니다. 30→20→30도처럼 되돌린 입력을 세며 마지막 풀림은 제외합니다. | 최대값 80% 도달 뒤 최대값의 15%와 최소 변화량(0.04rad 또는 LMU 잠금범위 1%) 중 큰 값 이상 감소·회복하고 최소 0.20초 또는 원본 3주기 중 긴 간격을 확인한 횟수의 중앙값입니다. |
| 타력 입력 | 두 페달을 거의 밟지 않은 시간의 비율입니다. 같은 관측시간 100초 중 해당 구간이 8초면 8%입니다. | 36km/h 초과·트랙 위·피트 밖에서 두 페달 3% 이하가 0.40초 이상 이어진 시간 ÷ 같은 조건의 페달 관측시간입니다. 전략이나 효율은 판정하지 않습니다. |
| 변속 회전수 | 같은 목표 기어로 올려 변속할 때 직전 RPM의 흩어짐입니다. 2→3단끼리, 3→4단끼리 따로 비교합니다. | 36km/h 초과·스로틀 60% 이상·브레이크 5% 이하인 한 단 상향변속을 사용합니다. 한 랩의 같은 목표 기어 변속 3회 이상에서 RPM의 MAD÷중앙값×100을 구하고 기어별 비율의 중앙값을 표시합니다. 원본 RPM 오차도 확인하며 최적 변속점을 뜻하지 않습니다. |

경기 결과 카드의 첫 수치는 **보관한 경기 결과**입니다. 공식 최종 결과·경기 종료 관측·종료 미확정 결과표를 구분합니다. 연습 파일에 포함된 예정 경기의 빈 항목은 결과 수에 넣지 않으며, 공식 확인이 없다고 실제 경기 참가 횟수가 0이라는 뜻은 아닙니다. 본인 순위표는 관측 순위로 볼 수 있고 공식 우승·포디엄·평균 순위에는 확인된 공식 결과만 사용합니다.

공통 분석 화면에서 파일 분석을 마치면 해당 원본의 관측 요약을 별도 로컬 저장소에 기록합니다. 분석용 `QUALIFYING`·`BASELINE_3LAP`·`ENDURANCE` 선택이나 장기 기억의 수동 저장 여부가 실제 세션 종류와 주행 수를 바꾸지 않습니다. 저장 실패로 기존 파일 분석 결과를 버리지 않습니다.

## 저장하는 범위

- 원본 내용의 SHA256과 원본별 관측 구간, 게임, 차량·트랙·레이아웃 식별 범위
- 실제 원본에서 확인한 세션 종류와 주행 시각, 각각의 근거와 미확인 사유
- 출처가 같은 기록의 교체 이력 대신 현재 요약, 여러 출처의 연결 관계
- 확인 가능한 운전 구간의 시간·거리, 측정 가능한 랩과 당시 관측 조건, 차량·코스 표시명
- 랩별 9개 입력 관측의 간결한 요약, 원본 기록 주기·시간 해상도·표본 수

선택한 주행의 체감·도전 이력과 본인의 경기 결과는 각각 별도 로컬 저장소에 보관합니다. 조회만으로 체감을 만들거나 도전을 달성 처리하지 않습니다.

새 원본 텔레메트리 사본, 드라이버 이름, 원문 세션 YAML, 개인 질문·음성은 저장하지 않습니다. 이 기능은 자료를 외부로 전송하지 않으며 기존 로그 보내기 설정을 바꾸지 않습니다. 외부에서 가져온 것으로 표시된 비교 기록과 LMU 가져오기 폴더의 기록은 개인 주행 원장에서 제외합니다. 일반 파일의 기록된 드라이버 식별 범위만으로 그 파일이 현재 사용자의 것이라고 보증하지 않습니다.

## 중복과 확인 필요의 의미

동일한 내용의 파일은 이름이나 위치를 바꾸거나 다시 분석해도 하나의 출처입니다. 같은 출처를 다시 분석하면 그 출처의 요약 전체를 한 트랜잭션에서 교체합니다.

iRacing 원본의 이벤트·서브세션·본인 차량 인덱스와 드라이버 식별·차량·트랙·실제 `SessionNum`이 충분히 확인되면 `NATIVE` 범위로 연결합니다. 같은 범위의 분할·겹침 기록은 같은 시간축에서 관측 구간의 합집합을 만들고, 관측 공백은 그대로 남깁니다. 원본의 서로 다른 실제 세션은 분석 모드와 독립적으로 구별합니다.

식별 근거가 부족하거나 시계가 역행한 기록은 `SOURCE_ONLY`로 둡니다. 이는 원본에 묶인 미확정 관측이며 독립된 실제 주행 횟수를 뜻하지 않습니다. 다른 파일의 같은 주행이라고 추정해서 합치지 않습니다. LMU의 합성 어댑터 세션 정보는 네이티브 이벤트 식별 근거로 사용하지 않습니다.

실제 시각을 확인하지 못하면 `recorded_at`은 `null`, 출처는 `UNKNOWN`입니다. 파일명·수정 시각이나 기존 분석 DB의 저장 시각을 실제 주행일로 대체하지 않습니다. 여러 세션이 섞였거나 원본 시계의 대응을 확인하지 못한 경우도 날짜를 보류합니다.

`coverage.intervals`는 관측 구간입니다. 실제 운전 시간·거리·완주·공식 유효 랩이나 실력 향상을 뜻하지 않습니다. 리플레이로 확인된 표본, 공백, 시계 역행은 이어 붙이지 않습니다. 서로 다른 시간축은 따로 남기고 합계를 만들지 않습니다. 여러 출처의 표본 수에는 겹침이 있을 수 있어 중복 제거된 표본 수로 표현하지 않습니다. LMU의 공식 유효 여부는 계속 확인 필요입니다.

LMU는 분석용 60Hz 보간 축과 구별해, 이미 읽은 원본 GPS 시간축의 표본 수·연속 구간만 간결하게 보관합니다. 원본 배열을 별도로 남기거나 기록할 때 DuckDB를 다시 읽지 않습니다. 원본 시계가 역행하면 구간을 분리하고 실제 날짜를 보류하며, 원본 시간축의 근거가 없는 객체는 관측 범위를 `UNAVAILABLE`로 둡니다.

LMU의 입력 관측은 이미 읽은 채널 목록의 원본 기록 주기·단위와 피트 상태의 확인 시작점을 사용합니다. 분석용 60Hz를 실제 페달 기록 주기로 취급하지 않습니다. 조향은 기록된 잠금각 대비 비율로 읽고, 실제 휠 각도를 모를 때 임의의 각도 성향으로 바꾸지 않습니다.

## 위치와 조회

기본 위치는 앱 데이터 폴더의 `driver-history.sqlite3`입니다. `IRACING_DRIVER_HISTORY_PATH`로 별도 위치를 지정할 수 있습니다. 기존 분석·음성 DB는 자동 이전하거나 재집계하지 않습니다. 새 저장소는 처음 기록할 때 생성하며, 빈 기록 조회나 모듈 불러오기만으로 파일을 만들지 않습니다.

백엔드의 읽기 전용 API는 다음과 같습니다.

- `GET /api/driver-history/status?game=iracing`
- `GET /api/driver-history/drives?game=lmu&limit=100&offset=0`
- `GET /api/driver-history/drives/{drive_id}`
- `GET /api/driver-report?game=iracing&period_days=0`

게임 필터는 `iracing`·`lmu`, 목록 한도는 1~200입니다. 리포트의 `period_days`는 `0`(전체)·`30`·`90`을 허용합니다. 원본 출처 수, 연결된 관측 수, 네이티브 세션 범위 수와 출처별 부분 관측 수를 구별합니다. 조회 API는 새 기록을 쓰거나 원본 파일을 다시 분석하지 않습니다.

드라이버 화면에 처음 들어가면 선택한 게임의 설정 폴더에 있는 IBT·DuckDB 전체를 백그라운드에서 확인합니다. 새 원본을 하나씩 읽고 측정 요약을 저장하므로 90일보다 오래된 파일도 가져옵니다. 이전 분석 DB의 결과나 파일명·수정 시각으로 주행 내용을 만들어내지 않습니다. 진행 중에도 이미 반영된 기록을 조회하고 다른 화면을 사용할 수 있습니다. 화면을 닫거나 이동해도 서버의 작업은 계속되며, **일시정지**를 누르면 현재 파일 분석을 중단하고 자원을 정리합니다. 중단한 파일은 완료 처리하지 않으며 **이어하기**를 누르면 다시 시도합니다. 앱을 종료했다 다시 열면 파일별 완료 지점을 재사용합니다. 읽을 수 없는 파일은 실패·건너뜀 수로 표시하고 나머지를 계속 처리합니다.

실제 파싱과 요약은 낮은 우선순위의 별도 Python 프로세스에서 실행합니다. 주행 중이거나 주행 파일 분석·비교 요청이 처리 중이면 현재 가져오기 프로세스도 중단해 자원을 해제합니다. 주행 종료·분석 완료 뒤 10초간 유휴 상태가 유지되면 미완료 파일부터 자동 재개합니다. 종료 후 자동 분석이 시작되지 않아도 유휴 10초 뒤 재개합니다. CPU 사용률이 75% 이상이거나 가용 메모리가 `max(512 MiB, min(2 GiB, 전체 메모리 × 10%))` 미만일 때도 자동 대기하며, 여유가 회복되고 10초간 유휴 상태가 유지되면 재개합니다. 주행·분석·자원 부족으로 중단한 파일은 실패·완료 수에 더하지 않고 재개 시 다시 처리합니다. 이미 원장에 반영을 시작한 짧은 저장은 완료 지점을 남긴 뒤 대기합니다. 사용자가 직접 일시정지한 작업은 자동 재개하지 않습니다. 변하지 않았고 유효한 요약이 있는 완료 파일은 다시 파싱하지 않습니다.

가져오기 진행 정보는 `GET /api/driver-history/library?game=iracing`, 시작·재확인은 같은 주소의 `POST`, 일시정지는 `POST /api/driver-history/library/pause?game=iracing`을 사용합니다. 조회는 가져오기를 시작하지 않습니다. 체크포인트는 원장 옆 `driver-history.library.sqlite3`이며 원본 경로 대신 경로 해시·크기·수정 시각·내용 해시·계산 버전을 보관합니다. 변하지 않았고 현재 원장에도 유효한 요약이 있는 파일은 다시 파싱하지 않습니다. 복사본은 내용 SHA256으로 중복을 막습니다. 가져온 비교용 기록과 기록 중인 DuckDB는 제외합니다.

이미 연결된 구버전 요약만 다시 읽는 **기존 기록 다시 확인**도 유지합니다. 이전 분석의 경로 또는 설정 폴더의 원본 시각으로 후보를 좁히고 내용 해시가 일치하는 원본만 사용합니다. 원본이 없거나 바뀌었으면 기존 요약을 보존합니다. 전체 가져오기와 이 재확인 작업은 동시에 파싱하지 않습니다.

2.4.1의 입력 요약 버전은 `driver-inputs-v2`입니다. 전체 측정 버전 `observed-metrics-v3`와 기존 원장 스키마는 유지하고 입력 요약에만 버전을 둡니다. 기존 기록에 새 입력 항목이 없으면 해당 원본을 백그라운드에서 한 번 읽어 **입력 정보만 보완**합니다. 거리·시간·랩 판정·주행 식별·경기 결과와 기존 완료 지점은 보존합니다. 반영할 때 내용 해시와 기존 관측·랩 경계를 확인하므로 복사본이나 새 주행을 늘리지 않습니다. 화면에는 **기존 기록 N개 보완 대기**로 남은 범위를 표시합니다.

현재 입력 버전까지 보완한 파일은 앱 재시작이나 입력 버전이 같은 후속 패치에서 다시 읽지 않습니다. 매 패치마다 전체 파일을 재분석하지 않습니다. 변하지 않은 원본의 자동 보완이 실패하면 같은 입력 버전에서 계속 반복하지 않으며 **기존 기록 다시 확인**으로 재시도할 수 있습니다. 채널이 없는 원본은 없는 항목의 이유를 남기고 보완을 마칩니다. 원본이 없거나 내용·관측 경계가 맞지 않으면 기존 요약을 보존합니다. 주행·전경 분석·자원 부족·수동 일시정지에는 전체 가져오기와 같은 중단·재개 규칙을 적용합니다. 더 오래된 전체 측정 요약이 필요한 파일은 기존 갱신 절차로 구분합니다.

이 작업은 `POST /api/driver-history/refresh?game=iracing`으로 시작하고 같은 주소의 `GET`으로 진행 상황을 확인합니다. 게임 전체에서 동시에 한 작업만 수행하며 화면을 닫아도 시작한 확인은 계속될 수 있습니다. 기존 읽기 전용 리포트 API는 원본을 열거나 요약을 갱신하지 않습니다.

## 드라이버 화면에서 확인하기

일반 앱 시작의 기본 화면은 드라이버 리포트입니다. `#summary`·`#settings` 등 명시한 직접 링크는 유지합니다. 현재 분석 파일이 없어도 원장을 조회하고 기존 원본을 가져올 수 있습니다. **전체**가 기본이며 **30일·90일**은 가져온 기록 중 해당 기간의 주행량·공식 결과·관측·랩·최근 목록·발견 기록을 고릅니다. 전체에는 날짜 미확인 관측도 포함하지만 날짜별 그래프에는 넣지 않습니다. 파일 반영이 진행되는 동안 리포트도 갱신하며 **새로고침**으로 직접 확인할 수 있습니다. **주행 분석에서 확인**은 기존 분석 화면으로 이동하며, 도전은 별도 **이 도전 선택** 버튼으로 저장합니다.

실시간 SDK에서 본인 차량의 실제 움직임을 관측한 뒤 차량 밖 상태가 3초, 또는 명시적 연결 종료가 10초 지속되면 같은 게임의 **주행 분석**으로 한 번 이동합니다. 정차·피트 진입·리플레이·읽기 오류·미확인 상태로 종료를 추정하지 않습니다. SDK 관측 간격이 2.5초를 넘으면 종료 확인 시간을 다시 셉니다. 앱 시작·백엔드 재시작·게임 변경 때 과거 종료를 재생하지 않으며 다른 게임의 기록을 보고 있을 때는 이동하지 않습니다. 새 기록 저장·분석은 기존 자동 처리 순서를 따르므로 이동 직후 분석 자료가 준비 중일 수 있습니다.

한 화면에 이번 리포트·나의 운전 성향·최근 관측·다음 목표·발견과 기록을 배치합니다. **전체·30일·90일 선택은 제목 줄의 거리·시간·우승·포디엄·평균 순위를 포함한 모든 통계에 적용합니다.** 원본·확인 세션·파일별 관측 수와 발견 기록도 선택 기간을 따릅니다. 기간에 기록이 없으면 예전 기록으로 채우지 않고 빈 상태와 이유를 표시합니다. 현재 선택한 파일·비교 랩을 바꿔도 기간 범위가 바뀌지 않습니다. 기간 변경은 저장된 요약을 조회하며 파일 가져오기나 원본 분석을 다시 시작하지 않습니다. 게임·기간을 바꾸면 이전 리포트 조회를 취소하고 늦은 응답을 표시하지 않습니다. 새 조회가 실패하면 같은 게임·기간에서 마지막으로 확인한 내용을 유지하고 재시도할 수 있습니다. 자동 대기 중에도 리포트와 다른 화면은 사용할 수 있고, 직접 일시정지할 수 있습니다.

## 집계할 수 있는 수치와 보류하는 판단

- **운전 시간·거리:** iRacing의 속도·트랙 위 상태가 확인된 연속 구간을 사용합니다. 세션 식별이 부족하거나 리플레이 채널이 없는 IBT도 측정값을 `PARTIAL`로 표시하므로 확정된 독립 세션 수나 실제 운전의 확정 합계가 아닙니다. 정차·확인된 리플레이·연결 공백을 메우지 않습니다. 같은 차량·코스·레이아웃의 대응 가능한 UTC 구간은 합집합으로 계산합니다. 겹친 거리나 대응하지 않는 시계는 잠재적 중복을 더하지 않고 확인된 관측량의 하한만 반영합니다. 상단에 부분 관측 포함 여부와 근거를 표시합니다. LMU의 실제 운전 구간은 이번 단계에서 `UNAVAILABLE`이며 측정 랩·날짜별 기록은 볼 수 있습니다.
- **측정 랩 중앙값·편차:** `VALID`·완주·피트 표본 없음·개별 랩의 시간 연속성 등 측정 조건을 통과한 랩만 사용합니다. 다른 구간의 공백 때문에 정상 랩까지 제외하지 않습니다. 리플레이 채널의 부재는 미확인으로 보존하며 관측 랩을 표시하지만, 확인된 리플레이나 잘못된 상태값을 포함한 랩은 제외합니다. 편차 비율은 랩타임의 중앙절대편차를 중앙값으로 나눈 값입니다. 공식 유효 여부는 `UNKNOWN`입니다. 단일 기록도 측정값을 표시할 수 있지만 이를 성장으로 판정하지 않습니다.
- **기간 추세:** 같은 게임·차량·트랙·레이아웃·실제 세션 종류를 확인한 독립 세션을 비교합니다. 각 기록의 연료·노면/기온·노면 상태·타이어·셋업 해시가 모두 있고 현재의 보수적인 동일 조건 검사를 통과해야 합니다. 독립 세션과 날짜 분리 근거가 부족하면 이 비교는 `trend=UNAVAILABLE`로 보류합니다. 같은 차량·코스·레이아웃의 날짜별 측정 랩은 별도 **관측 페이스 변화**로 표시할 수 있으며 `comparison_status=OBSERVATION_ONLY`로 구별합니다. 조건 차이가 포함된 관측이므로 운전 실력이나 변화의 원인을 확정하지 않습니다.
- **공식 결과:** iRacing의 원본·SDK에 보관된 본인 최종 클래스 결과와 공식 완료 근거를 확인해 별도 저장합니다. 같은 이벤트 결과의 분할·반복 수집을 한 결과로 묶고, 충돌하는 최종 순위는 공식 집계에서 보류합니다. 우승·포디엄·평균 순위는 이 결과만 사용하며 화면의 전체·30일·90일 선택에 맞춰 집계합니다. 날짜 미확인 결과는 전체에서만 확인할 수 있습니다. 최종 표가 없는 옛 IBT, 식별이 부족한 기록, LMU의 완료·순위 관측은 공식 결과로 승격하지 않습니다. 미확인을 0회·0위로 채우지 않습니다.
- **입력 관측·성향:** 위의 9개 항목을 원본 채널로 측정합니다. 완주·피트·시계 연속성·가용 채널·원본 주기를 확인하고, 확인된 리플레이와 외부 비교 기록은 제외합니다. 세션 식별이 부족해도 관측 수치·표본·범위·보류 이유를 보여줍니다. 성향 이름은 같은 조합에서 서로 다른 2일 이상·확인된 독립 세션 3개 이상·세션당 입력 5회 이상의 반복 근거가 있고 같은 방향이 충분히 반복될 때만 붙입니다. 조합과 날짜마다 같은 비중으로 요약하며 9개 항목을 각각 판단하고 반대 관측도 표시합니다. 한 코스에서만 확인되면 그 범위에 한정합니다. 코너 위치·주행선·차량 균형 선호·인격·재능이나 빠르기 점수는 계산하지 않습니다.
- **이전과 최근 비교:** 같은 차량·코스·레이아웃·실제 세션 종류의 원시 랩타임을 같은 방식으로 비교합니다. 30일·90일은 직전 같은 길이의 기간을 우선 사용하며, 이전 기간이 비어 있거나 전체 보기일 때는 관측일을 앞·뒤로 나눕니다. 전후 날짜·측정 랩·관측 수·확인 세션 수·중앙값·편차를 함께 보여줍니다. 조건 일치 비교와 조건 차이가 포함된 `OBSERVATION_ONLY`를 구별하고, 페이스 방향·편차 방향·이전 수준 유지 여부와 불확실성을 각각 표시합니다. 최근 측정이 부족하면 유지 판단을 보류하고 다른 조합이나 오래된 세션을 대신 쓰지 않습니다. 새 조합에 이전 기록이 없어도 현재 측정값은 표시합니다. 강점에 해당하는 관측 결과는 조작 성향과 별도로 설명합니다.

리포트의 페이스·성장 비교에는 `VALID`·완주·피트 표본 없음·원본 시계 연속성 등의 조건을 통과한 측정 랩만 사용합니다. 측정 랩이 없는 주행은 이 비교에서 제외하지만 확인된 주행 시간·거리와 출처 기록은 남을 수 있습니다. 기존 주행 분석의 무효 랩 정상 구간 코칭은 별도이며 전체 유효 랩으로 취급하지 않습니다. LMU 측정 가능성과 게임 공식 유효 판정도 구별합니다.

## 체감·도전과 달성 기록

**오늘 운전하기 어땠나요?**에서 해당 날짜·차량·코스를 확인한 뒤 편했어요·보통이에요·어려웠어요·잘 모르겠어요를 한 번 선택하면 저장합니다. 다른 답으로 바꾸거나 지울 수 있으며, 어려웠어요의 상황 선택은 선택 사항입니다. 미응답과 잘 모르겠어요는 다르게 보관하고 객관적인 주행 판정으로 바꾸지 않습니다. 과거 주행을 선택해도 그 주행에 연결하며 현재 주행에 복제하지 않습니다.

날짜와 조합이 확인되고 측정 랩이 3개 이상인 기록에서 **측정 페이스 3랩 재현**, **페이스와 편차 5랩 유지** 목표를 선택할 수 있습니다. 선택 시의 기준·기존 출처와 주행을 고정하고 게임별 진행 중 도전 하나를 보관합니다. 선택 이후의 새 독립 주행에서 같은 차량·코스·레이아웃, 실제 날짜·측정 랩과 비리플레이 근거를 확인해 달성을 저장합니다. 과거 파일을 처음 가져오거나 같은 원본을 재분석한 것은 새 달성이 아닙니다. 식별·리플레이 근거가 부족하면 관측값은 남기되 달성은 미확인으로 둡니다. 도전 취소와 달성 이력도 보관합니다.

정상 분석·가져오기로 새 요약이 저장되면 진행 중 도전을 확인하고, **달성 여부 확인**으로 다시 시도할 수도 있습니다. 단순 리포트·기록 조회는 도전을 갱신하지 않습니다. 체감은 원장 옆 `driver-history.journal.sqlite3`, 경기 결과는 `driver-history.results.sqlite3`에 보관합니다. 모두 원본 텔레메트리와 분리된 로컬 저장소이며 빈 조회로 생성하지 않습니다.

관련 API는 `GET /api/driver-journal`, 주행별 체감의 `PUT`·`DELETE /api/driver-journal/feelings/{drive_id}`, 도전 선택 `POST /api/driver-journal/challenges`, 취소 `POST /api/driver-journal/challenges/{challenge_id}/cancel`, 달성 재확인 `POST /api/driver-journal/reconcile`, 결과 조회 `GET /api/driver-results`입니다. 게임은 `game=iracing|lmu`로 분리하고 결과 조회 기간은 `period_days=0|30|90`을 사용합니다.

2.4.0까지의 드라이버 리포트에 2.4.1의 9개 입력 관측과 입력만 보완하는 절차를 추가했습니다. 최신 배포 파일과 공개 상태는 [Releases](https://github.com/elsalvadoruk-hue/racingcoach/releases)에서 확인하세요. 위 표본·입력 경계는 현재 구현의 보수적인 관측 규칙이며 검증된 실력 척도가 아닙니다.

## 개발 검증 이력

아래 검증 수와 화면 구성은 각 단계 당시의 이력입니다. 2.4.0의 두 입력 항목·3탭 검사 결과를 2.4.1의 9개 항목 검사 결과로 사용하지 않습니다. 2.4.1의 최종 검증은 별도 릴리스 근거에 기록합니다.

기간별 전체 통계·경쟁 세션 인시던트·성향 상세 가독성 후속에서는 관련 백엔드 192개·React 5 suites/64개와 production build를 확인했습니다. 실제 격리 API와 합성 IBT·DuckDB를 연결한 브라우저 36조건에서 전체·30일·90일의 거리·시간·공식 결과·발견 기록 변경, 연습 인시던트 제외, 자세히 버튼 크기 일치, 성향 3탭·설명 펼침·키보드·초점 복귀·두 게임·FHD 메인 무스크롤을 확인했습니다. 원본 추출·결과 추출·가져오기 체크포인트 버전은 바꾸지 않아 이번 수정으로 완료 파일을 다시 분석하지 않습니다. 새 실주행·다른 PC 검증은 아니며 커밋·push·릴리스·앱 버전 변경은 없습니다. 근거는 `logs/driver-report-competitive-20261027/verification.json`입니다.

지표 누락·경기 0회 표시 오해·성향/도전 상세창 후속에서는 백엔드 전체 2,197개와 추가 경계 1개, React 전체 826개와 추가 경계 1개, 스크립트 125개로 중복 없는 3,150개 검사가 통과했습니다. 최종 production build와 실제 격리 API의 브라우저 73조건에서 두 게임의 상세창 세로 배치·닫기 크기·초점 복원, FHD 8카드 무스크롤, 성향 용어/예시, 앱 분석 유효 비율과 관측된 0점 표시, 도전 선택/취소를 확인했습니다. 기존 개인 결과 저장소는 읽기 전용 조회에서 본인 결과표 7개를 보존하며 공식 최종 결과는 미확인이었습니다. 연결 가능한 실제 IBT 3개에도 최종/종료 근거가 없었고 원본과 개인 저장소는 변경하지 않았습니다. 이는 실제 출전·완주 횟수가 0이라는 뜻이 아닙니다. 근거는 `logs/driver-report-followup-20261027/verification.json`입니다.

아래 기존 검사 수·실제 원본 확인은 각 단계의 당시 구현에 대한 이력입니다. 체감·도전·경기 결과·입력 성향·이전/최근 비교를 함께 연결한 이번 통합 검증과 구별하며, 과거 수치를 현재 전체 기능의 통과 수로 사용하지 않습니다.

체감·도전·공식 결과·성향·성장 비교를 연결한 이번 검증은 백엔드 2,156개·React 112 suites/815개·스크립트 125개, 총 3,096개 검사와 production build를 통과했습니다. 임시 합성 IBT·DuckDB와 실제 API를 연결한 브라우저에서 체감 네 가지·상세 상황·수정/삭제·복원, 분석한 파일의 정확한 주행 ID 연결, 과거 주행 선택, 도전 취소·과거 기록 소급 달성 차단·새 독립 주행 자동 달성, 두 게임 분리, 성향 근거·성장 전후 수치·최종 결과 조회를 확인했습니다. FHD 전체화면에서는 8개 카드의 핵심 내용과 조작을 페이지 스크롤 없이 표시합니다. 상세 근거는 `logs/driver-report-features-20261027/verification.json`입니다. 새 실주행·다른 PC의 동작을 검증한 것은 아닙니다.

검증은 임시 SQLite와 합성 기록으로 수행합니다. 재분석·파일 복사·분할·겹침·공백·세션 변경·역행·날짜 누락·미확인 공식 유효 여부·저장 잠금·원자 교체·게임 분리와 저장 실패 후 분석 보존을 확인합니다. 실제 개인 DB를 이전하거나 실제 주행 자료를 외부로 보내는 검증은 하지 않습니다.

전체 가져오기 추가 전인 2026-10-27 점검에서 백엔드 1,935개, 화면 108 suites/764개, 런처·패치 40개 검사와 production build가 통과했습니다. 당시 최종 변경 뒤 드라이버 관련 145개도 다시 통과했습니다. 실제 build의 격리 브라우저에서 합성 IBT 읽기·기존 기록 갱신·수치 반영·게임/기간 전환·근거창·조회 오류 복구와 1100~1600px 배치를 확인했습니다. 근거는 `logs/driver-report-review-20261027/verification.json`과 `report.md`이며 이번 전체 가져오기 검증과는 구별합니다.

이미 연결된 실제 원본 12개는 읽기 전용으로 열고 임시 원장에 재계산해 모두 갱신됐으며 측정 랩 65개를 확인했습니다. 개인 원장은 변경하지 않았습니다. 일반 앱을 다시 실행한 뒤 드라이버의 **기존 기록 다시 확인**으로 반영할 수 있습니다. 11개 원본의 플랫폼 세션 ID 누락과 공식 결과·성향·성장 추세의 근거 부족은 그대로 유지합니다. 새 실주행의 정확도·다른 PC 동작·공식 결과 보관을 확인한 것은 아닙니다.
