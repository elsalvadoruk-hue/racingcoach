# 포장 오벌 로그 자동 검수와 기록 재생

개발본을 쓰는 오벌 주행자는 기존 **세션 로그 자동 보내기**를 켜고 평소처럼 주행하면 됩니다. 이 문서는 받은 ZIP을 살펴보는 개발자·검수자용입니다. 앱의 기존 화면과 자동 보내기 스위치를 그대로 사용합니다.

## 중요한 장면을 남기는 방식

전체 ZIP이 전송 한도에 들어가면 원래 자료를 그대로 보냅니다. 포장 오벌의 주변 차량 자료를 줄여야 할 때만 다음 관측을 기준으로 장면을 고릅니다.

- 양쪽 차량·한쪽 두 대, 겹침 진입과 해소, 5초 이상 이어진 병렬 주행
- 세션 상태·깃발·페이스 모드·본인의 피트 허용·대열 위치 신호 변화와 누락·복귀
- 세션 시각이 주변 차량 자료와 하나의 구간에서 대응하는 재생 실패·중단

최대 6개 창·창당 200행·합계 1,200행·압축 160KB를 유지합니다. 시작과 끝, 관측상 겹침이 없는 비교 구간을 우선 확보한 뒤 사건 종류와 시각을 분산해 선택합니다. 일반적인 10Hz 기록에서 200행은 약 20초이며, 사건 전후 약 10초씩을 포함합니다. 기록 시작·끝·공백 근처나 용량이 부족한 경우 짧아집니다. 서로 겹치는 창은 중복 행 없이 합칩니다. 사건이 많으면 전부 담지 못합니다.

원본 행·순서·누락·0/false는 바꾸지 않습니다. 시각 역행·중복·결측·0.5초 초과 공백을 건너지 않습니다. `export_selection`에 원본/선택/생략 행 수, 원본 행 범위, 사건 종류별 관측·선택 수와 생략 사건 수를 남깁니다. `start`는 포함, `stop`은 제외하는 원본 행 인덱스입니다. 시계가 되풀이되어 대응이 모호한 무전은 선택 근거에 억지로 연결하지 않습니다. 원래 파일은 유지하며 SDK 수집 루프에는 작업을 추가하지 않습니다.

공간이 더 부족하면 추가 자료가 빠질 수 있습니다. 자동 보내기의 기존 동의·전송 시점·재시도·하루 한도는 그대로입니다. 전체 자료를 받는 **로그 파일 받기**에는 이 축소를 적용하지 않습니다.

## 받은 ZIP 검수하기

저장한 ZIP 폴더를 지정합니다. 이 명령은 해당 자료를 읽고 지정한 결과 폴더에만 검수 산출물을 씁니다. Drive 접속이나 다운로드·자동 전송·음성 재생은 하지 않습니다.

```powershell
python scripts/review_coach_logs.py "C:\받은 로그" --out "C:\오벌 검수 결과"
```

파일 하나 또는 여러 파일·폴더도 지정할 수 있습니다.

```powershell
python scripts/review_coach_logs.py "C:\받은 로그\coach-log-example.zip" --out "C:\오벌 검수 결과"
```

결과 폴더의 `index.md`에서 기록별 보고서와 재생 화면을 엽니다. `index.json`에는 분류·중복·읽기 실패 목록도 있습니다. 같은 ZIP은 SHA256으로 제외하고, 같은 game/run_id/started_at의 내보내기 여러 개는 관측 행이 많은 자료를 우선 사용합니다. 같은 기록을 여러 경기나 여러 사람으로 세지 않으며 자료끼리 합치지 않습니다. 일부 ZIP이 손상돼도 다른 기록은 처리하고 종료 코드 1과 오류 목록을 남깁니다. 정상 처리한 기록이 없을 때도 종료 코드 1입니다.

각 기록 폴더에는 다음 파일이 생깁니다.

| 파일 | 내용 |
| --- | --- |
| `report.md` | 분류·수집/내보내기 버전·관측 범위·의심 구간·한계 |
| `review.json` | 전체 사건, 실제 무전 이력, 검토 항목, 과거 로그의 후보와 개발본의 위트 무음 평가 |
| `replay.html` | 외부 연결 없이 열 수 있는 기록 재생 화면 |
| `replay.jsonl` | 같은 표본을 순서대로 처리할 수 있는 기계 판독 자료 |

## 재생 화면 읽기

`replay.html`을 브라우저로 엽니다. **이전/다음**, **재생/일시정지**, **1·2·5배**, 탐색 막대와 **관측 사건으로 이동**을 제공합니다. 생략·끊김 뒤 다음 구간에서는 자동으로 멈추고 구간 시작을 표시합니다. 기록 사이를 보간하거나 이전 차량 상태를 이어 붙이지 않습니다.

현재 표본의 좌우 겹침 신호, 랩·속도·피트 값, 대열·깃발 원시 신호, 주변 차량의 기록값과 시각이 대응하는 실제 무전 이력을 함께 표시합니다. 무전은 읽을 수 있도록 같은 구간의 최근 4초·최대 6행을 보여 줍니다. `gap_m`은 트랙 진행 방향의 거리이며 차량의 좌우 위치를 뜻하지 않습니다. 무전 대응은 같은 연속 구간 안에서 가장 가까운 표본과 최대 0.15초 범위로 제한합니다. 대응하지 못한 무전도 **전체 무전 이력**에 보존합니다. 재생 실패·중단과 클리어 의심 장면도 사건 선택에서 바로 이동할 수 있습니다.

다음 상황을 `REVIEW`로 추립니다.

- 클리어 재생 시작 근처에 해당 쪽 겹침이 관측된 경우
- 실제 재생 실패·중단 이력이 있는 경우
- 같은 연속 구간에서 같은 key의 다른 안내가 1초 안에 시작한 경우

이 결과는 의심 장면을 빠르게 찾기 위한 것입니다. 정상적인 재진입·우선순위 선점일 수도 있습니다. 의심 신호가 없어도 `INSUFFICIENT_FOR_PASS`로 남기며 자동 정상 판정하지 않습니다. 수집 버전이 없는 과거 기록은 내보낸 앱 버전으로 대체하지 않습니다. 분류가 없는 과거 로그는 `UNKNOWN`을 유지합니다.

## 위트 무전과 연결하는 범위

확인 가능한 겹침 해소 장면을 `overlap_resolved` 후보로 추립니다. 현재 기록만으로는 주행·리플레이 상태, 출발/재시작, 부하, 다른 무전이 말하는 시간, 최근 농담과 소재 이력 등 모든 발화 조건을 확인할 수 없습니다. 그래서 후보는 전부 `DEFERRED`로 남깁니다. 기록이 없다는 이유로 “말할 여유가 있었다”고 판단하지 않습니다.

2.4.2 핫픽스 기반 개발본에서는 **실제 발화 없이** 조건 판단과 가상 문구 선택을 기록합니다. 개발본 ZIP의 `banter-shadow.json`을 읽어 재생 화면의 **위트 무전 무음 평가**에 표시합니다. 무전과 같은 시각 대응 기준을 쓰며, 시계가 반복되거나 관측 구간 밖인 평가는 전체 목록에만 남깁니다. `ELIGIBLE_SHADOW`는 기록한 시험 조건을 통과했다는 뜻이며 실제 발화 허가나 안전 판정이 아닙니다. 기존 `radio_counts`나 안내 수에는 넣지 않습니다.

한국어 창작 초안은 **8상황·72개** 모두 무음 검토 대상입니다. 긴 병렬·양쪽 차량 해소는 5초 이상 겹침 후 3초 이상 해소, 조용한 주행은 연속 120초 겹침 없음으로 후보를 만듭니다. 세션 베스트 변화·3초 유지된 클래스 순위표 상승·3랩 동안 인시던트 증가 없음·체커 비트 진입·피트 서비스 1→2 전환도 원시 근거와 함께 기록합니다. 세션 베스트·공식 유효 랩·추월·본인 완주·서비스 완료의 의미를 확정하지 못한 후보에는 별도 보류 이유가 붙습니다.

경기 상태·깃발·페이스 모드의 10초 안정, 주행/피트/리플레이·속도·입력 부하·예상 발화 여유, 현재 프런트 음성/질문/대기/무음 상태를 확인합니다. SDK의 비페이싱 값은 `4`이며 출발/재시작 `0`~`3`은 보류합니다. 연습도 세션의 실제 주행 상태로 평가하며 레이스 전용 기능으로 간주하지 않습니다. 빠진 조건은 보류합니다. 만료 5초, 자료 공백·역행·연결/프로필 변경과 조건 변화 뒤 오래된 후보를 재사용하지 않습니다.

시험용 가상 선택 기준은 **최소 600초 간격·최근 8문장·최근 4소재 회피**입니다. 운영 빈도가 확정된 것은 아닙니다. 같은 문구를 모두 소진한 채 영구 보류되지 않도록 초안 안에서 순환 가능하게 했습니다. 최근 가상 선택 24개는 별도 이력에 저장해 세션 전환·앱 재시작 뒤에도 사용합니다. 실제로 들린 이력과는 다릅니다. 무음 평가 저장은 최근 2,048개 전체 한도이며 ZIP에는 기록당 최대 128개(처음 8개+최근 120개)를 넣고 생략 수를 표시합니다. 전송 크기가 부족하면 상세 평가부터 제외합니다. 저장 실패는 제한된 후보 버퍼 안에서 재시도하며, 연결 초기화나 버퍼 회수로 모든 후보의 기록을 보장하지는 않습니다.

## 절차 관측과 누적 검수

`oval-procedures.json`은 절차 원시 신호·변화·5초 간격 표본·후보·보류·한 랩 전 취소/정상 그린 도달·프런트 음성 점유 관측을 담습니다. 실제 안내 집계와 분리합니다. 저장 큐는 256개, 클라이언트 관측 대기는 64개·5초이며 미저장 절차 기록은 연결 초기화 후에도 별도 worker가 저장합니다. DB는 전체 최근 4,096개, ZIP은 해당 기록 최대 256개(처음 16개+최근 240개)입니다. 큐 탈락 누적값·내보내기 생략·보관 한도를 구분하며 과거 전체 기록의 보존을 보장하지 않습니다.

검수 보고서의 `feature_coverage`와 전체 폴더의 `coverage.json`은 기능별 관측·미관측을 표시합니다. 자료가 없으면 `NOT_OBSERVED`, 있으면 `REVIEW_REQUIRED`이며 자동 정상 판정·기능 활성화는 없습니다. 반복 세션 시계와 주변 차량 자료 밖의 절차는 전체 목록에만 남깁니다.

기록별 `regression.json`은 최대 32사건·사건 전후 최대 20표본씩을 원본 관측값으로 보존합니다. 절차·위트 사건을 우선하며 연속 구간 경계를 넘지 않습니다. 생략 사건 수와 `exact_live_replay=false`를 기록하므로 원래 30Hz SDK·실제 위치의 정답을 재현하는 검사로 사용하지 않습니다. 다음 공개 범위와 음원 준비는 [다음 패치 준비표](oval-next-patch.md)를 참고합니다.

새 음성·합성·발화 설정은 없습니다. 경고·깃발·F8 응답의 기존 재생 우선순위는 유지하며, 실제 위트 발화와 중단 후 재개 여부는 후속 검수 범위입니다.

이전 NASCAR 무전 조사에서 잡은 후속 권장안은 친근하고 능청스러운 팀 동료 말투입니다. 8~10개 상황에서 창작 초안 120~160개를 만들고, 청취 검수를 거친 60~80개부터 도입하는 방향입니다. “옆집이 드디어 이사 갔네요.” 같은 표현도 긴 병렬이 끝난 뒤 안정된 상황에서만 검토합니다. 30분에 2~4회는 첫 시험용 빈도 후보이며 확정 수치가 아닙니다. 같은 문구뿐 아니라 같은 농담 소재도 세션 간 반복을 줄이고, 오래 기다린 농담은 폐기합니다. 기존 F8 우선 정책을 전역 변경하지 않습니다.

최대 10Hz 관측을 보여 주는 도구입니다. 실제 30Hz 스포터 판단이나 소리의 정확한 재현, 실제 청취·차량 위치의 정답, 경기 절차 허용·안전 판정으로 사용하지 않습니다. 실제 오벌 검수는 주행자 자료로 이어갑니다.
