작성일: 2026-10-28 · 조사 기준: `main / 1e26374638f841162e8f341d9d08c972d8479b8f`

상태: 조사·기획 완료, 제품 구현 전. 이 문서의 문구·시간·화면은 제안이며 현재 앱 기능과 구별한다.

## 1. 권장하는 첫 범위

첫 대상은 **iRacing 포장 오벌의 스톡카 주행**으로 잡는다. 먼저 주변 차량 안내를 만들고, 검증된 경기 신호에 따라 코션·정렬·재시작·피트 허용 상태를 덧붙인다. 더트 오벌·인디카 고유 절차·고급 전략은 후속 범위로 둔다. 같은 포장 오벌에서도 경기별 설정과 차량 규칙이 다르므로 모두 NASCAR 절차로 묶지 않는다.

사용자가 체감할 핵심은 다음 네 가지다.

1. 옆 차가 있을 때 **안쪽/바깥쪽/양쪽**을 짧게 듣는다.
2. 3대 병렬 주행에서 본인이 가운데인지, 한쪽에 두 대가 있는지 구별한다.
3. 코션 중에는 게임이 요구하는 정렬과 재시작 상태를 이해한다.
4. 피트가 본인에게 열렸는지 확인한다. 진입 허용과 피트 전략은 별개로 안내한다.

## 3. 오벌을 처음 접할 때 필요한 말

| 말 | 쉬운 뜻 | 제안하는 안내 |
| --- | --- | --- |
| 안쪽, low / inside | 트랙 중앙에 가까운 쪽. 반시계 포장 오벌에서는 보통 운전자의 왼쪽 | “안쪽 차량.” |
| 바깥쪽, high / outside | 바깥 벽에 가까운 쪽. 같은 조건에서는 보통 오른쪽 | “바깥쪽 차량.” |
| 3대 병렬, three-wide | 내 차를 포함해 가로로 세 대가 나란히 달림 | 가운데면 “양쪽 차량. 가운데입니다.” |
| 코션, full-course caution | 경기 전체가 중립화되어 정렬하는 상태 | “풀코스 옐로. 게임 정렬 지시를 확인하세요.” |
| 페이스카 | 출발·코션 중 대열을 이끄는 차 | 화면의 정렬 지시와 함께 설명 |
| 재시작 | 코션 뒤 경기를 다시 이어 감 | 실제 신호가 확인된 상태만 읽음 |
| 프리 패스, Lucky Dog | 게임이 지정하는 랩 회복 배정 | 배정 표시와 추월 실행 지시를 구별 |
| 웨이브 바이 / 웨이브 어라운드 | 게임 지시에 따른 대열 이동·랩 회복 절차 | 배정만으로 “지금 추월”을 말하지 않음 |
| 클리어 | 직전에 겹치던 쪽 차량의 겹침이 해소됨 | 진로 변경 허가·트랙 전체 안전 보장은 아님 |

`CarLeftRight`는 차량의 좌우 신호다. **반시계 방향과 정확한 오벌 레이아웃을 확인한 경우에만** 왼쪽→안쪽, 오른쪽→바깥쪽으로 바꾼다. 방향 미확인·역방향·로드 레이아웃에서는 좌우 표현을 유지한다. 조향각이나 차량명으로 방향을 추정하지 않는다.

공식 [Spotting 안내](https://support.iracing.com/support/solutions/articles/31000162971-spotting)도 주변 차량의 low/high/left/right와 3대 병렬 상태를 효율적으로 전달하는 역할을 설명한다. 여기의 한국어 문구는 이 앱을 위한 제안이다.

## 4. 공식 규정에서 확인한 핵심

조사일 현재 공식 페이지가 연결하는 규정은 **V.2026.09.09**다. 검색에 나타난 2011·2024·2025판의 페널티·절차를 그대로 섞지 않는다. 아래는 규정 요약이며 실제 경기의 Race Control 지시와 추가 규정을 함께 확인해야 한다.

| 상황 | 확인된 내용 | 기획 반영 |
| --- | --- | --- |
| Start Zone이 있는 첫 출발 | flagman의 그린이 출발 기준 | 선두 가속을 보고 출발을 지시하지 않음 |
| Start Zone이 있는 재시작 | 선두가 존 안에서 가속 시점을 선택, 끝까지 안 가면 flagman이 시작 | 첫 출발과 다른 상태로 처리 |
| 오벌 출발·재시작 | 출발선 전 같은 대열 차량을 왼쪽으로 추월해 이득을 얻으면 Drive-Through 대상 | 클리어와 추월 허용을 분리 |
| 다른 앞줄의 선두 | 출발선 전 폴 차량을 앞서면 제재 가능 | 단순 그린만으로 모든 추월을 허용하지 않음 |
| 풀코스 코션 | 정렬 순서 동결, Race Control 정렬 지시 준수 | 현재 순위로 추종 대상을 재구성하지 않음 |
| 재시작 준비 | 두 랩 전·한 랩 전 지시와 대열 재편 가능 | 남은 경기 랩 수로 카운트다운을 만들지 않음 |
| 피트 | 코션 초·말 등에 입·출구가 닫힐 수 있음 | 본인 입장 허용과 출구 신호를 구별 |
| Wave-By | 적용 시기와 해당 차량의 피트 제한이 있음 | 배정·실행·피트 상태를 각각 확인 |

출처: [Official Sporting Code 안내](https://www.iracing.com/iracing-official-sporting-code/), [V.2026.09.09 PDF](https://ir-core-sites.iracing.com/members/pdfs/20260909-official_sporting_code_dated_Sep_09_2026.pdf) §6.8.2, §6.9, §6.10.6, §7.5.4–7.5.5. 인쇄 페이지 24·25·29.

이 표의 Start Zone 절차를 존이 없는 경기까지 확대하지 않는다. 오벌 프로필이라고 코션이 반드시 활성화됐다고 판단하지 않는다. 코션 설정·정렬 방식·Start Zone 적용 여부는 해당 세션에서 확인하며, 알 수 없으면 확인 필요로 둔다. 프리 패스의 현재 자격 계산을 이번 일반 규정만으로 완성했다고 보지 않는다.

| --- | --- | --- |

`PitSvFlags`는 타이어·급유 등 **선택한 피트 서비스**다. `OnPitRoad`는 피트에 있는지, `PlayerCarPitSvStatus`는 서비스 상태다. 어느 것도 피트가 열렸다는 뜻으로 바꾸면 안 된다. `SessionFlags.servicible`도 입구·출구 개방과 같다고 가정하지 않는다.

받은 보고서 snapshot에는 `PaceMode`, `CarIdxPaceLine/Row/Flags`, `PitsOpen`이 없다. 기존 로그로 이 신호를 복원했다고 주장할 수 없다. `PaceMode=not_pacing` 한 값만으로 그린을 확정하지 않는다.

## 7. 제품 구성과 음성 정책 제안

### 7.1 프로필 선택

설정 제안은 `자동 / 로드 / 포장 오벌`이다. 자동은 검증된 트랙 종류·정확한 레이아웃으로 선택하고, 정보 부족 시 현재 좌우 안내를 유지한다. 수동 포장 오벌 선택도 방향 미확인 상태에서 안/밖 변환이나 규칙 확정을 허용하지 않는다.

내부 후보 상태는 `ROAD`, `ASPHALT_OVAL`, `DIRT_OVAL`, `UNKNOWN`이다. 스포츠카가 오벌에서 달리거나 스톡카가 로드에서 달리는 경우도 구별한다. 차량 종류와 레이스 라이선스 분류만으로 레이아웃을 결정하지 않는다. 게임·세션·트랙 전환 시 이전 프로필의 대열과 안내를 폐기한다.

### 7.2 근접 차량 안내: 첫 구현 범위

| 관측 상태 | 제안 문구 | 주의점 |
| --- | --- | --- |
| 안쪽 한 대 | “안쪽 차량.” | “바깥으로 가세요” 같은 이동 명령을 붙이지 않음 |
| 바깥쪽 한 대 | “바깥쪽 차량.” | 바깥벽까지 여유가 있다는 뜻이 아님 |
| 양쪽 한 대씩 | “양쪽 차량. 가운데입니다.” | `CarLeftRight=4`일 때만 가운데 |
| 안쪽 두 대 | “안쪽 두 대.” | 이때 본인은 가운데가 아님 |
| 바깥쪽 두 대 | “바깥쪽 두 대.” | 단순 “세 대입니다”로 위치 정보를 잃지 않음 |
| 양쪽→한쪽 | “안쪽만 남았습니다.” 또는 “바깥쪽만 남았습니다.” | 먼저 없어진 쪽만 보고 전체 클리어를 말하지 않음 |
| 겹침 지속 | “계속 안쪽.” 등 | 반복 간격은 검증 후 결정 |
| 겹침 해소 | “안쪽 클리어.” 등 | 충분한 신선도·연속 해소 확인 후만 발화 |

오벌에서는 **내가 추월하는 중에도 확인된 겹침을 안내하는 정책**을 추천한다. 스포츠카의 추월 억제를 그대로 적용했을 때와 비교해 채택한다. 진입 확인 시간은 0.10–0.20초를 실험 후보로 두되 확정값으로 배포하지 않는다. 클리어는 현행 0.15초를 기준으로 거짓 클리어·깜빡임을 검증한다. 양쪽/한쪽 두 대로 위험도가 높아진 경우에는 이전의 짧은 유지 안내보다 새 상태를 우선한다.

병렬 주행이 계속되면 코너 데이터가 없어도 유지 안내가 가능한 정책을 비교한다. 시간·상태 변화·다른 음성 점유를 함께 보며, 초 단위로 끝없이 같은 말을 반복하지 않는다. 기준은 놓친 위험과 불필요한 반복을 모두 기록해 결정한다.

### 7.3 코션·정렬·재시작: 신호 검증 후 구현

| 관측/상황 | 제안 문구 | 활성화 조건 |
| --- | --- | --- |
| 실제 풀코스 코션 진입 | “풀코스 옐로. 게임 정렬 지시를 확인하세요.” | 코션 신호 확인, 별도 이벤트로 1회 |
| 본인 피트 허용 false→true | “피트 허용 상태로 바뀌었습니다.” | `PitsOpen` 의미를 실제 게임과 검증한 뒤 |
| 본인 피트 허용 true→false | “피트 제한 상태입니다. 게임 지시를 확인하세요.” | 동일. 진입·출구 의미를 혼동하지 않음 |
| 재시작 한 랩 전 | “그린까지 한 랩. 출발 준비하세요.” | 게임의 한 랩 전 신호, 기존 안내와 중복 제거 |
| 본인 정렬 위치 | “안쪽 줄입니다.” | line/row의 실제 매핑·세션 상태까지 확인 |
| 코션 뒤 실제 그린 전환 | “그린. 재시작.” | 오벌 전용 정책, 재접속·재코션을 구별 |
| 프리 패스 배정 | “프리 패스가 배정됐습니다. 게임 지시를 확인하세요.” | 본인 PaceFlags의 실제 배정 신호 |
| 웨이브 어라운드 배정 | “웨이브 어라운드 대상입니다. 게임 지시를 확인하세요.” | 해당 신호 검증. 즉시 페이스카 추월 지시는 금지 |

코션 뒤 그린 안내는 기존 사용자 결정과 달라지는 **오벌 전용 권장안**이다. 실제 구현 시 프로필 설명·선택 사항으로 명확히 다루며, 이번 기획만으로 기존 동작을 변경하지 않는다.

후속 구현의 상태 흐름은 `UNKNOWN → INITIAL_PACING → RACING → CAUTION → RESTART_PACING → RACING`을 기본으로 삼는다. 실제 관측된 전환만 허용하며, 한 랩 전 취소·코션 연장·재코션이면 준비 문구를 폐기한다. 도중 연결된 경우 첫 출발·재시작 이력을 만들어내지 않는다. 배정 flag는 코션 주기별로 중복을 막고 연결 해제·세션 교체 시 지운다.

### 7.4 화면과 음성 공급

화면은 기존 스포터 설정에 현재 프로필·안내 기준·자동 판별 근거를 짧게 표시한다. 코션 중에는 경기 상태·본인 정렬·피트 허용을 표시하되 `미확인`을 별도 상태로 둔다. 운전 중 긴 규칙 설명은 읽지 않고, 도움말에서 용어와 예시를 제공한다.

새 문구는 준비된 고정 음성을 사용한다. 기존 기본팩·선택팩에 없는 문구는 화면에만 표시하고 자동 유료 합성을 요청하지 않는다. 문구 목록·목소리별 파일 수·제작 비용은 구현안 확정 뒤 별도로 산정한다. 이번 조사에서는 음성을 만들지 않았다.

우선순위는 현행 사용자 약속을 유지한다. 자동 안내 중에는 겹침 경고가 최우선이며, F8 질문 답변은 기존대로 겹침 경고도 끊을 수 없다. 오벌에서 이 순서를 바꾸는 것은 별도 정책 결정이다. 모든 새 안내는 재생 직전 게임·세션·프로필·신선도·해당 조건을 다시 확인한다. 해제된 상태의 대기 문구·재시도 문구는 폐기한다.

## 8. 단계별 개발과 완료 조건

| 단계 | 산출물 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| A. 신호 확인 | 최소 메타데이터·페이싱·피트 채널의 읽기 전용 수집과 로컬 재생 자료 | 누락과 0/false 구별, 원본 시각, 본인 인덱스, 게임 표시와 대응 확인 |
| B. 오벌 근접 안내 | 프로필·안/밖 표현·3대 병렬·유지/클리어·음성 목록 | 합성 회귀와 격리 브라우저 통과, 실제 오벌 대조 전에는 실검증 미완료 표시 |
| C. 경기 절차 | 검증된 코션·정렬·한 랩 전·그린·피트 허용·배정 안내 | 기능별 실제 양성/해제/결측 대응이 확인된 것만 활성화 |
| D. 실사용 검수 | 일반 포장 오벌·쇼트트랙·슈퍼스피드웨이 등 확인 범위별 검수 | 위험한 거짓 클리어·오래된 재시작/추월 허용 안내 0건, 누락/지연과 한국어 청취 확인 |

추천 개발 순서는 **A와 B의 로컬 기반 → 확인된 C 기능 순차 활성화 → D**다. 피트 허용이나 프리 패스의 자료 부족 때문에 근접 안내의 설계·합성 검증까지 멈출 필요는 없다. 반대로 합성 성공을 실제 절차 검증으로 승격하지 않는다.

실자료는 기존 오벌 기록 또는 동의된 검증 환경에서 확보하는 방안을 먼저 찾는다. 사용자에게 구매·추가 경기·장시간 주행이 필수라고 요구하지 않는다. 게임에 명령을 보내거나 설정을 바꾸는 수집 기능은 만들지 않는다.

주요 회귀 조건은 다음과 같다.

- 정확한 오벌/같은 시설 로드 레이아웃·차량 교차·더트·스키드패드·정보 부족·수동 선택·두 게임 전환.
- 좌/우/양쪽/한쪽 두 대·양쪽에서 한쪽 잔류·두 대에서 한 대·빠른 추월·내 추월·긴 병렬·결측·깜빡임.
- 재접속·시간 역행·세션 변경·off·리플레이·피트·관전에서 거짓 클리어와 오래된 음성 없음.
- 코션 미활성 경기·첫 출발과 재시작·한 랩 전 취소·재코션·중간 접속·Start Zone 정보 부족.
- 본인/다른 차량 프리 패스·웨이브·EOL, flag 중복·해제·배정 충돌·피트 조건 변경.
- F8 답변 우선, 상태 변경 중 오디오 준비 지연·재생 실패·재시도·팩 누락·무전 끄기.
- 동일 입력의 기존 로드·LMU 이벤트/문구/음성 정책 보존, 새 채널로 SDK loop에서 I/O·네트워크 작업을 하지 않음.

성능은 구현 시 후보 생성 비용과 신호→이벤트→실제 재생 지연을 분리해 측정한다. 임의의 시간 목표나 FPS 개선을 이번 조사 결과로 주장하지 않는다.
