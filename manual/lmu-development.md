# LMU 연동 개발: 집 PC에서 이어하기

개발 브랜치: `feature/lmu-telemetry-isolation`

현재는 **기존 iRacing과 분리된 LMU 파일 분석·파일 간 비교·다중 랩 고스트·코너 후보 비교·입력 반복성·연습 과제 이력·차량 상태 24채널 관측/두 랩 비교와 실시간 진단 수집을 구현한 단계**입니다. 실제 Monza / GT3 연결과 정상 인정 기록 `2:05.798`의 사용자 대조를 확인했으며, 컷 시도 사례의 게임 문구와 새 수신 지연 진단의 실주행 검증은 남아 있습니다. 게임의 랩 유효성 자동 판정이나 실시간 음성 코칭이 완성된 버전은 아닙니다. 현재 개발 PC의 최신 화면은 **http://127.0.0.1:24176/**이며 집 PC에서는 아래 실행 명령의 포트로 새 서버를 시작합니다. `main` 병합·태그·릴리즈는 하지 않습니다. 실주행 순서는 [실시간 검증 안내](lmu-live-validation.md)를 참조하세요. 아래 날짜별 항목은 당시의 개발 기록입니다.

## 2026-10-20 집 PC 인계

- 중단 지점: 차량 상태 두 랩 비교와 휠 순서 조사까지 완료. 다음 개발은 **셋업 정보 요약과 두 기록의 설정 차이 표시**입니다. 연습 과제의 실주행 전후 검증은 사용자가 집에서 진행할 때 이어갑니다. 당장 새 주행을 요구하지 않습니다.
- 최종 검사: LMU Python **200/200**, UI **25/25** 통과. 실제 5개 랩·3쌍·24채널·72응답의 통계 **13,041개**와 그래프 값 **73,062개**가 원본 계산과 일치했습니다. 이 숫자는 이번 인계 시점 결과이며 집 PC 설치 환경은 별도 확인합니다.
- 유지할 한계: `valid=None`, `VALIDITY_UNVERIFIED` / `GAME_SCREEN_UNVERIFIED`, 조건 `NOT_COMPARED`. SDK의 휠 순서는 확인했지만 DuckDB `value1..4`의 휠 위치 매핑은 `UNVERIFIED`입니다. [조사 근거](lmu-wheel-order-research-20261020.md)를 참조하세요.
- Git에 포함: 소스·합성 회귀 검사·개발/조사 문서. **원본 `.duckdb`, `.wal`, 실주행 JSONL, 빌드 DLL, 로컬 검증 로그와 가상환경은 포함하지 않습니다.** 개발 기록의 `logs/...` 근거 경로는 개발 PC 로컬 파일입니다.
- 기존 실파일로 재검증하려면 게임의 `UserData/Telemetry`에서 종료된 `02_30_41Z`, `04_46_01Z`, `05_52_11Z`가 포함된 `.duckdb` 세 파일을 개인 전송 수단으로 별도 복사하고 `LMU_TELEMETRY_DIRS`로 그 폴더를 지정합니다. 파일 전체 이름은 `Autodromo Nazionale Monza_P_2026-10-20T<시각>.duckdb`입니다. 기록 중이거나 WAL이 남은 `06_09_24Z`는 이 검증에 사용하지 않았으며 강제 checkpoint하지 않습니다.
- 실시간 판정 근거까지 이어볼 경우 `logs/lmu-live/e15c0635a1734657936b79a3ccd084bc.jsonl`, `logs/lmu-live/d60a971970034593870caa319a1670ac.jsonl`도 별도 복사합니다. 저장 경로가 달라지면 파일 ID도 달라지므로 화면의 파일 목록을 새로 읽고 선택합니다.
- 다른 worktree의 오디오 1.4.1 및 자동 업데이트/1.4.3 작업은 이 LMU 브랜치에 병합하지 않았습니다. 오디오·버전 파일을 덮어쓰지 말고 LMU 앱을 별도로 실행합니다.

집 PC에 이미 이 브랜치가 있고 작업 폴더가 깨끗하면:

```powershell
git status --short
git fetch origin
git switch feature/lmu-telemetry-isolation
git pull --ff-only origin feature/lmu-telemetry-isolation
```

미커밋 변경이 보이거나 다른 작업이 진행 중이면 해당 폴더를 변경하지 말고 아래의 새 폴더 복제 절차를 사용합니다. 다음 세션에는 이 문서의 집 PC 인계와 맨 아래 최신 개발 기록부터 확인하면 됩니다.

## 분리 구조

| 항목 | iRacing | LMU |
| --- | --- | --- |
| 진입점 | 기존 `backend_api.py` / `실행.bat` | `lmu_api.py` |
| 로컬 포트 | `24157` | `24158` |
| Python 환경 | 기존 설치 환경 | 별도 `.venv-lmu` 권장 |
| 설치 목록 | 기존 `requirements*.txt` | `requirements_lmu.txt` |
| 파일 읽기 | 기존 IBT reader | `lmu_telemetry.py`, `.duckdb` 전용 |
| 파일 경로 | 기존 iRacing 설정 | `LMU_TELEMETRY_DIRS` |
| 실시간 수집 | 기존 `live_telemetry.py`, iRacing SDK | `lmu_live.py` + `lmu_shared_memory.py` + 설치 SDK용 native bridge, 명시적 시작/중지 |
| 상태·조회 API | 기존 API | `/api/lmu/...`, 별도 앱에만 등록 |
| 설정·캐시·개인 DB | 기존 저장소 | iRacing 저장소 접근 없음. 실시간 진단만 `logs/lmu-live/<recording_id>.jsonl`에 별도 기록 |

LMU 모듈은 iRacing 설정·DB·SDK·음성 서비스에 접근하지 않습니다. LMU 실행에는 Node.js·Garage61·Google Cloud 키·음성팩이 필요하지 않습니다. 이 로컬 서버는 사용 중인 PC에서만 실행하며 외부 서버 운영은 필요하지 않습니다.

## 가져오기와 실행

기존 작업 폴더에 미커밋 변경이 있으면 먼저 별도로 보존하세요. 브랜치가 원격에 push된 뒤 새 폴더에서 시작하는 경우:

```powershell
git clone --branch feature/lmu-telemetry-isolation https://github.com/elsalvadoruk-hue/racingcoach.git racingcoach-lmu
cd racingcoach-lmu
git config core.hooksPath .githooks
py -3.12 -m venv .venv-lmu
.\.venv-lmu\Scripts\python.exe -m pip install -r iRacing_Backend/requirements_lmu.txt
$env:LMU_TELEMETRY_DIRS='D:\SteamLibrary\steamapps\common\Le Mans Ultimate\UserData\Telemetry'
.\.venv-lmu\Scripts\python.exe -m uvicorn lmu_api:app --app-dir iRacing_Backend --host 127.0.0.1 --port 24158
```

Python 3.12가 없다면 설치된 Python 3.11 이상으로 가상환경을 만드세요. 경로는 집 PC의 실제 Steam 라이브러리 위치로 바꾸세요. `LMU_TELEMETRY_DIRS`는 **이 PowerShell 창의 프로세스에만** 적용되며 새 창에서는 다시 지정합니다. 지정하지 않으면 `ProgramFiles(x86)`와 `ProgramFiles` 아래 기본 Steam 경로만 찾습니다. 다른 드라이브의 라이브러리는 자동 탐색하지 않습니다.

### 원격 push가 불가능할 때

GitHub 쓰기 권한이 없는 계정으로 인증된 PC에서는 `403`으로 push가 실패할 수 있습니다. 로컬 브랜치와 커밋은 그대로 유지됩니다. 권한 있는 계정으로 인증한 뒤 `git push -u origin feature/lmu-telemetry-isolation`을 실행하면 됩니다.

Git bundle로 옮기는 경우 회사 PC에서 아래처럼 파일을 만들고 집 PC로 가져갑니다. 이 번들은 `main` 기준 커밋이 필요한 증분 번들입니다.

```powershell
git bundle create racingcoach-lmu.bundle feature/lmu-telemetry-isolation ^origin/main
git bundle verify racingcoach-lmu.bundle
```

집 PC에서 새 저장소를 복제한 뒤 가져옵니다. `D:\Transfer`는 번들을 복사한 실제 위치로 바꾸세요.

```powershell
git clone https://github.com/elsalvadoruk-hue/racingcoach.git racingcoach-lmu
cd racingcoach-lmu
git fetch D:\Transfer\racingcoach-lmu.bundle feature/lmu-telemetry-isolation:feature/lmu-telemetry-isolation
git switch feature/lmu-telemetry-isolation
```

이후 위의 가상환경 설치부터 이어갑니다. 번들에는 커밋된 소스 변경만 포함되며 로컬 주행 파일·개인 설정은 포함되지 않습니다.

여러 폴더를 검사하려면 Windows에서 `;`로 구분합니다. 타인에게 직접 받은 파일은 별도 폴더에 보관하고 그 폴더를 추가할 수 있습니다. 비교 파일과 랩은 화면에서 직접 선택하며 트랙·레이아웃·차량 메타데이터가 일치하는지 검사합니다. 메타데이터 일치가 주행 조건 동등성이나 유효 랩을 보장하지는 않습니다.

```powershell
$env:LMU_TELEMETRY_DIRS='D:\SteamLibrary\steamapps\common\Le Mans Ultimate\UserData\Telemetry;D:\LMU-References'
```

브라우저에서 **http://127.0.0.1:24158** 을 엽니다. 연결 상태 → 파일 선택 → 파일 검사 순서로 확인합니다. 종료는 실행 창의 `Ctrl+C`입니다. 기존 iRacing은 기존 `실행.bat`으로 별도 실행할 수 있습니다.

`[Errno 10048]`이 나오면 다른 프로그램이 해당 포트를 사용 중입니다. 기존 프로그램을 종료하지 말고 명령의 `--port 24158`을 `--port 24168`처럼 빈 포트로 바꾼 뒤 브라우저 주소도 맞추세요.

## 이번 단계에서 가능한 것

- 지정한 폴더의 `.duckdb` 목록 조회. `.ibt`·`.duckdb.wal`은 읽지 않습니다.
- 선택한 파일만 읽기 전용으로 열어 메타데이터·채널 이름·단위·주파수·이벤트·샘플 수 확인.
- 게임의 연속된 `Lap` 이벤트 시각으로 양쪽 경계가 있는 랩을 표시. 파일 앞뒤의 미완성 구간은 완주로 만들지 않습니다.
- `Lap Time`을 해당 종료 시각으로 연결. 기록 누락·시간 불일치·피트 포함·샘플 부족·큰 거리 역행을 진단.
- 동명 파일도 폴더별 식별자로 구분. SteamID와 CarSetup은 API에 전달하지 않습니다.
- 시간·거리 진단을 통과한 두 기록 랩을 직접 선택해 같은 거리에서 비교. 누적 시간 차이·속도·스로틀·브레이크·조향 그래프를 표시합니다. 게임의 유효성 판정은 미확인으로 유지합니다.
- 거리 구간별 소요 시간·시간 차이와 최대 단축/지연 구간 표시. 구간을 선택하면 채널 통계와 그래프의 동일 거리 범위를 확인합니다.

`Lap Dist` 리셋을 랩 경계로 쓰지 않으며, 단위나 스티어링 각도를 값 범위로 추측하지 않습니다. 파일이 잠겨 있거나 기록 중이면 종료한 기록으로 다시 검사하세요. 파일·DB·iRacing 설정에 쓰지 않고 외부 확장 로딩도 비활성화합니다.

### 랩 상태 해석

| 상태 | 뜻 |
| --- | --- |
| `VALIDITY_UNKNOWN` | 경계 간 시간과 기록 시간이 일치하지만 게임의 유효 랩 판정은 미확인 |
| `UNTIMED` | 해당 종료 시각에 양수인 `Lap Time`이 없음 |
| `PIT_LAP` | 피트 진입 상태가 포함됨 |
| `TIMING_MISMATCH` | 경계 간 시간과 기록 시간이 다름 |
| `INCOMPLETE` | 거리 샘플이 부족하거나 기록 범위를 벗어남 |
| `DISTANCE_DISCONTINUITY` | 랩 내부에 큰 거리 역행·리셋이 있음 |

이 상태는 모든 이상을 판별하는 분석기가 아닙니다. 진단 하나만 대표로 표시할 수 있습니다. 컷·패널티·포메이션·텔레포트 등의 유효성 판정은 구현되지 않았습니다. 따라서 모든 랩의 `valid`는 `null`, `best_lap_time_s`는 `null`이며 유효 베스트 랩을 자동 선택하지 않습니다.

## 다음 작업 순서

1. 브랜치를 가져와 별도 Python 환경으로 LMU 앱을 실행하고, 종료된 기존 파일로 분석 화면과 차량 비교를 확인합니다. 파일 ID는 집 PC 경로 기준으로 다시 생성됩니다.
2. 원본 셋업 항목의 구조·단위를 조사해 안전한 요약과 두 기록 간 설정 차이를 구현합니다. 개인정보·원문 전체 공개나 관측 차이의 인과 효과 추정은 하지 않습니다.
3. 연습 과제 실주행 전후 비교는 사용자가 집에서 진행할 때 이어갑니다. 새 주행을 하기 전에는 기존 데이터·합성 검사로 가능한 개발을 우선합니다.
4. 게임의 랩 유효성 표시·수신 지연·피트·재연결·세션 전환은 향후 필요한 사례별로 대조합니다. SDK 순서와 DuckDB 휠 열 순서의 직접 대응은 별도 검증 전까지 미확인으로 유지합니다.
5. 실시간 수집기는 이미 설치 SDK 기반으로 구현했습니다. 집 PC에서 사용할 경우 아래 로컬 브리지를 빌드하고 명시적으로 수집을 시작합니다. 음성/코칭·상대 차량 통합과 게임 업데이트별 ABI 확인은 후속 범위입니다.

파일 분석에는 native bridge나 C++ 도구가 필요하지 않습니다. 실시간 수집을 사용할 때만 설치된 LMU SDK와 Visual Studio x64 C++ 빌드 도구로 집 PC에서 브리지를 만듭니다. 아래 `sdk_dir`는 실제 게임 경로로 바꾸세요. SDK 헤더와 생성 DLL은 Git에서 가져오지 않습니다. 빌드·probe는 게임 수집을 시작하지 않습니다.

```powershell
.\.venv-lmu\Scripts\python.exe -c "import sys; sys.path.insert(0, 'iRacing_Backend'); from lmu_shared_memory import build_native_bridge; print(build_native_bridge(sdk_dir=r'D:\SteamLibrary\steamapps\common\Le Mans Ultimate\Support\SharedMemoryInterface'))"
```

현재 실시간 수집기의 기본 SDK 경로는 시스템 기본 Steam 설치 위치입니다. 게임을 다른 드라이브에 설치한 경우 빌드뿐 아니라 `SharedMemorySource(sdk_dir=...)`를 사용하는 서비스의 SDK 경로 구성도 맞춰야 하므로, 오류 시 반복 주행하지 말고 해당 경로부터 확인합니다.

MyLMU 자동 수집·유료 서비스·외부 서버 운영은 현재 설계에 포함하지 않습니다.

## 검증

LMU 전용 환경의 개발 검증:

```powershell
.\.venv-lmu\Scripts\python.exe -m pip install -r iRacing_Backend/requirements_lmu_dev.txt
.\.venv-lmu\Scripts\python.exe -m unittest discover -s iRacing_Backend -p 'test_lmu_*.py' -v
```

### 2026-10-20 추가 개발: 거리 구간별 분석

검증 실행 결과는 기존 iRacing 분석 합성 테스트 `31/31 PASS`, 코너 관련 테스트 `27/27 PASS`, LMU 전용 테스트 `37/37 PASS`였습니다. 앞의 두 결과는 기존 iRacing analyzer 자체가 유지된다는 뜻이며 LMU DuckDB에 그대로 실행됐다는 뜻이 아닙니다. LMU 적용 판정은 실제 파일의 채널·이벤트·route 분리 대조로 별도 판단했습니다. 이름이 일치하지 않은 30개 키에는 원시 SDK 이름 23개와 내부/파생 키 7개가 섞여 있습니다. 이것이 LMU 센서 30개 부재를 의미하지는 않습니다.

다음 구현 순서는 (1) LMU의 `GPS Latitude/Longitude`와 `Lap Dist`를 이용한 트랙 방향·레이아웃 식별 근거 확보, (2) 브레이크·가속 구간 adapter와 혼합 주파수 테스트, (3) LMU 공식 섹터/코너 정의 확인, (4) 그 뒤에야 코너 비교와 코칭을 연결하는 것입니다. 컷 유효성 판정 근거가 확인되기 전에는 `valid`나 베스트 랩을 자동 확정하지 않습니다.

### 2026-10-20 기능 동등성 웹 조사와 추가 확인

공식 문서·공개 구현·설치 헤더·실제 파일을 대조한 [LMU 기능 동등성 개발 요구사항](lmu-iracing-feature-parity-research-20261020.md)을 추가했습니다. 위 표는 현재 연결 상태이며 기술적으로 구현 불가능하다는 판정은 아닙니다.

- 설치 공식 헤더에 `mLapInvalidated`, `mCountLapFlag`, `mTrackLimitsSteps`가 있습니다. 실시간 수집과 게임 표시 대조로 앞으로 기록하는 랩의 판정 근거를 확보할 수 있습니다. 기존 Monza 파일에는 이 신호가 없어 `VALIDITY_UNVERIFIED`를 유지합니다.
- 실제 `CarSetup`에 172개 설정 항목의 JSON이 있습니다. 셋업 전체 데이터가 없는 것이 아니라 LMU 설정 해석·실험 연결이 미구현입니다. 사용 가능 항목과 물리 단위는 별도 확인이 필요합니다.
- 공식 기록 안내는 채널·주파수 설정을 지원합니다. 현재 66개 채널은 전체 제공 범위가 아니며, 추가 채널은 새 기록으로 확인해야 합니다.
- 지도·자동 코너 측정은 공식 이름 없이도 검증된 기하 구간부터 구현할 수 있습니다. 공식 코너 명칭은 별도 매핑하며, 미확인 유효 랩은 명시적 진단 비교에 한정합니다.
- 권장 순서는 공통 분석 모델·지도·제동/가속 측정, 실시간 수집·유효성, 코너 코칭, 실시간 음성/전략, 셋업 A/B와 외부 서비스 연동입니다. Garage61의 LMU 지원은 확인하지 못했으며 수동 LMU 파일 간 기준 랩 비교부터 구현합니다.

이번 추가 작업은 조사 문서이며 LMU 수집·분석 실행 코드는 변경하지 않았습니다. 게임 설정·원본 기록·SDK 헤더도 수정하지 않았습니다.

### 2026-10-20 순차 개발: 공통 입력 모델과 단일 랩 경로·페달 측정

권장 1단계 중 **공통 입력 기반과 단일 랩 측정**을 구현했습니다. 1단계 전체 완료는 아닙니다. 파일 간 비교·다중 랩/고스트와 기존 iRacing analyzer의 공통 모델 연결은 후속 작업입니다. 앞의 기능 적용표는 구현 전 진단 기록이며, 현재 추가 지원 범위는 아래와 같습니다.

| 구현 | 현재 동작과 제한 |
| --- | --- |
| `telemetry_core.py` | `AnalysisLap`, `ChannelTrace`에 채널별 원본 시간축·단위·유효 샘플 mask 보존. 외삽, 결측·시간 gap을 건너뛰는 보간 차단 |
| `lmu_analysis.py` | 속도 `m/s`, 페달·조향 `ratio`, 좌표 `deg` 정규화. 단위 미확인은 `UNSUPPORTED_UNIT`, 범위 밖 값은 결측 처리. 조향을 각도로 변환하지 않음 |
| 채널 지원표 | `AVAILABLE`, `PARTIAL`, `MISSING`, `INVALID_SAMPLES`, `INSUFFICIENT_SAMPLES`와 원본 채널·단위·주파수 표시. 페달·조향은 `Unfiltered` 우선, 없으면 게임 처리 입력을 명시 |
| 상대 경로 도식 | 좌표의 국소 접평면 근사. `SCHEMATIC`, `geographic_identity=UNVERIFIED`. 실제 Monza 지리 위치·공식 코너·트랙 경계로 확정하지 않음 |

API는 `GET /api/lmu/telemetry/lap-analysis?file_id=<발견한 ID>&lap_number=1&points=301`입니다. `points`는 3~501이며 경로 표시만 조절합니다. 화면은 **http://127.0.0.1:24168** 에서 파일 검사 → 분석할 랩 선택 → **선택한 랩 분석**으로 사용합니다. 기존 두 랩 비교와 거리 구간 분석도 유지합니다.

### 2026-10-20 추가 주행 반영: 파일 간 수동 비교와 두 랩 경로

새 `Autodromo Nazionale Monza_P_2026-10-20T04_46_01Z.duckdb`를 읽기 전용으로 검사했습니다. `11251712` bytes, 66개 채널·38개 이벤트이며 SHA256은 `59445583d2be307f0a6775f5fb1338efcb6fa1b91d06a401901b249d8265c935`입니다. 피트 출발 랩 0을 제외한 랩 1은 `125.56265258789062 s` (`2:05.563`), 랩 2는 `121.04037475585938 s` (`2:01.040`)입니다. 두 랩 모두 정규화 7개 채널 `AVAILABLE`이며, 게임의 컷 유효성 신호는 이번 파일에도 없어 `valid=null`을 유지합니다.

`lmu_comparison.py`에서 각 파일의 `AnalysisLap`을 사용해 공통 거리별 누적 시간·속도·스로틀·브레이크·조향과 고정 거리 구간 통계를 계산합니다. 세션별 시계 시작값을 독립적으로 처리하고, 표시 지점과 별개로 원본 축에서 구간 시간을 계산합니다. 기존 `/api/lmu/telemetry/compare`는 유지하며 새 화면은 정규화 기반 `/api/lmu/telemetry/compare-files`를 사용합니다. 따라서 화면의 페달·조향은 `Unfiltered` 우선이고, 각 기록의 원본 채널·주파수·처리 단계를 상세에 표시합니다.

지원 범위와 제한:

- 기준 파일과 비교 파일·랩을 각각 직접 선택합니다. 같은 파일의 서로 다른 랩도 지원하고, 동일 파일·동일 랩 선택은 차단합니다. 유효 베스트 랩은 자동 선택하지 않습니다.
- `track_name`, `track_layout`, `car_name`, `car_class`의 비어 있지 않은 값이 모두 일치해야 합니다. 상태는 `METADATA_MATCH_ONLY`입니다. 팀/엔트리 표시명 일치가 차량 모델 ID·연식·변형을 확정하지 않으며, 방향·게임 버전·연료·타이어·날씨·노면·셋업 조건도 미확인입니다.
- 거리 축이 끊기거나 정지 구간이 있으면 비교를 차단합니다. 기록 거리 범위 차이가 `max(50 m, 1%)`보다 큰 경우도 차단합니다. 이 검사는 같은 트랙·방향을 증명하는 판정이 아닙니다.
- 결측·잘린 채널·미확인 단위·상이한 입력 처리 단계는 해당 채널을 `UNAVAILABLE`로 제외합니다. 누락 값을 0으로 채우거나 끊긴 샘플을 이어 붙이지 않습니다. 지원되는 다른 채널과 시간 비교는 계속 제공합니다.
- 경로 두 개를 기준 랩 좌표의 공유 원점에 투영하고, 각 경로의 결측·급변에서 선을 분리합니다. `SHARED_RAW_COORDINATES_UNVERIFIED`인 상대 도식이며 자동 회전·평행 이동으로 맞추지 않습니다. 실제 위치·세션 간 좌표계 일치·정밀 주행선 차이를 검증한 기능은 아닙니다.
- 비교 중 파일 크기·수정 시각이 바뀌면 결과를 반환하지 않습니다. 완료된 파일만 사용합니다.

API 사용 예:

```text
GET /api/lmu/telemetry/compare-files?reference_file_id=<이전 파일 ID>&target_file_id=<새 파일 ID>&reference_lap=2&target_lap=2&points=301&sector_length_m=500
```

두 파일 ID는 파일 목록에서 받습니다. `points`는 3~501, `sector_length_m`는 100~2000입니다. 응답은 파일 이름/ID·기록 시각, 호환성 검사, 채널 지원표, 공통 거리 시계열·구간 통계, 경로 두 개를 포함하며 로컬 절대 경로·SteamID·CarSetup 원문은 포함하지 않습니다.

| 항목 | 결과 |
| --- | --- |
| 기록 시간 | `2:01.100` → `2:01.040` |
| 전체 기록 시간 차이 | `-0.059661865234375 s` |
