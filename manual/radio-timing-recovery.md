# 랩타임 안내와 음성 정지 복구

## 한국어 로컬 음성 질문 (2.6.1)

“지금 뭐에 집중해야 해?”로 현재 레이스의 우선순위를 묻습니다. 유효한 연료·피트 계획을 먼저 확인하고, 근거가 있으면 결승 전에 따라잡힐 뒤차와 시간을 잃는 구간 또는 앞차보다 빠른 구간을 알려 줍니다. 실제 추월 가능 지점을 단정하지 않으며 기록에서 판단 이유를 확인합니다. 재생 준비 중 상대·계획·수치가 바뀌면 답변을 취소합니다.

SenseVoice의 “소음 재인식 준비 · 약 0.6MB”로 GTCRN 잡음 제거 모델을 추가할 수 있습니다. 기존 질문이 연결되지 않았을 때만 원음을 메모리에서 처리해 한 번 더 인식합니다. 피트 명령·숫자·불명확한 대상은 이 재인식으로 실행하지 않습니다. 일반 질문과 대기 중에는 추가 연산하지 않습니다. 녹음 완료 뒤 0.18초를 더 받아 마지막 음절을 보존합니다.

잡음 제거 모델은 [sherpa-onnx의 GitHub GTCRN 배포 파일](https://github.com/k2-fsa/sherpa-onnx/releases/download/speech-enhancement-models/gtcrn_simple.onnx)이며 535,638바이트입니다. 설치할 때 크기와 SHA256을 확인합니다. 이미 설치한 SenseVoice는 이 작은 추가 파일만 받을 수 있습니다.

경쟁차 구간 비교는 “앞차보다 내가 어디서 빨라?”, “나는 앞차보다 어느 코너에서 더 빨라?”, “뒤차보다 제가 어느 구간에서 느려요?”처럼 본인을 나타내는 말을 넣어도 됩니다. 앞차·뒤차와 빠른 구간·느린 구간을 구분하며 실제로 비교 가능한 구간만 답합니다.

앱과 실행창을 닫고 **실행.bat**으로 다시 연 뒤 **음성 코치 → 음성 인식 → 로컬 인식기 받기**로 SenseVoice를 설치합니다. 선택한 모델이 없으면 설치 항목이 팝업 맨 위에 펼쳐집니다. 설치가 완료되면 설치 항목이 아래로 접히고 켜기·녹음 화면으로 전환됩니다. 설치한 모델의 변경·복구는 **설치·모델·질문 예시**에서 합니다. 기본 설치에는 포함하지 않으며 설치 버튼을 눌렀을 때만 받습니다. Whisper base를 비교용으로 선택할 수도 있습니다. 예전 small 파일은 보존하지만 선택 목록은 SenseVoice와 base만 표시합니다.

상단 스포터·피트월 옆의 **음성 인식** 버튼으로 어느 화면에서든 켜고 끌 수 있습니다. 켜져 있으면 버튼에 불이 들어옵니다. 모델이 없으면 설치 팝업을 먼저 엽니다. 음성 코치 본문의 **음성 인식 켜기**도 같은 기능을 제어합니다. 처음 사용할 때 **로그 보내기 필수 안내 → 전송 안내 확인 → 동의하고 켜기**를 거칩니다. 기존 전송 동의는 새 범위가 추가되어 재동의가 필요합니다. 인식률 개선을 위해 한동안 인식 문장·보정과 근거·연결 질문·답변·모델·처리 시간·실패 및 피트 명령 결과를 받습니다. 인식 테스트와 차량 미연결 질문도 포함하며 새 동의 이후 기록만 보냅니다. 원음·Google 질문·장치 이름과 ID는 보내지 않습니다. 전송 목적·수신처·보관 기간은 동의창에 표시합니다. 로그 보내기를 끄면 로컬 음성 인식이 중지됩니다. 스포터·피트월·Google 질문은 계속 사용할 수 있습니다.

모델을 준비한 뒤 **로컬 질문 단축키**를 누른 채 말하고 놓거나 **질문 녹음 시작 → 녹음 완료 · 전송**을 사용합니다. 최대 10초이고 Google 질문 단축키와 별개입니다. 한 번 켜면 다음 앱 실행 때 같은 마이크와 유효한 전송 동의가 확인될 경우 자동 준비합니다. 직접 끄면 자동 시작도 해제됩니다. 스포터·피트월은 이전 정상 재생 때의 마이크·출력장치와 같을 때 켜 둔 상태를 복원합니다. Windows 기본 장치도 실제 장치를 비교하며 권한·장치가 확인되지 않으면 보류합니다. 브라우저가 자동 재생을 막으면 **테스트 소리**를 눌러 허용합니다.

**인식 테스트 시작 → 테스트 녹음 완료**는 게임 없이 문장 연결을 확인합니다. 피트 명령을 전송하거나 답변을 재생하지 않습니다. 결과는 **기록 → 로컬 음성 인식 기록**에 저장되며 개선용 전송 대상입니다. 기록은 검색하고 10건씩 넘겨 보며 팝업에는 최신 테스트 결과만 표시합니다. 로컬 기록 조회는 최근 최대 200건 범위입니다.

권장 모델은 [SenseVoice Small INT8](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17) 약 240MB이며 고정 배포 파일의 크기와 SHA256을 확인합니다. 실행 프로그램은 PyPI의 sherpa-onnx 2.0.3과 NumPy입니다. [Whisper base](https://huggingface.co/Systran/faster-whisper-base)는 모델 약 148MB이며 별도의 faster-whisper 실행 환경을 사용합니다. 두 실행 환경을 분리하며 설치 크기와 캐시 공간은 환경에 따라 달라집니다.

CPU 두 스레드만 사용하며 GPU를 사용하지 않습니다. 대기 중에는 마이크와 인식 연산을 멈추고 모델만 메모리에 유지합니다. 끄면 프로세스를 종료합니다. 개발 PC의 실제 제품 SenseVoice 프로세스는 합성 질문 5개를 인식했고 대기 2초의 CPU 시간 증가는 측정상 0초, 메모리는 약 358MB였습니다. 기준 사양 5600X·3060Ti·16GB의 실제 게임 FPS와 실물 마이크 정확도 검증은 별도입니다.

일반 질문은 실시간 차량 연결과 해당 측정값이 있어야 답합니다. **차량 연결 없음**과 **인식 불확실**을 구분합니다.

| 질문 예시 | 연결되는 답변 |
| --- | --- |
| 연료 얼마 남았어 / 기름 몇 리터야 | 현재 연료량 |
| 연료 얼마나 가 / 지금 연료로 얼마나 더 갈 수 있음 / 연료 몇 랩 남았어 | 현재 연료로 주행 가능한 랩 |
| 한 랩에 연료 얼마나 먹어 / 평균 연비 알려줘 | 최근 유효 랩의 평균 소비 |
| 방금 랩타임 / 지난 랩 몇 초야 | 직전 랩타임 |
| 앞차 간격 / 앞차랑 몇 초 차이야 | 앞차와의 간격 |
| 뒤차가 얼마나 빨라 / 뒤차 추격 속도 | 뒤차가 랩당 좁히는 시간 |
| 지난 랩 어디서 날렸어 | 가장 큰 코너 손실 |
| 지금 피트하면 몇 등으로 나와 | 피트 뒤 예상 복귀 순위 |
| 가상 에너지 얼마나 남았어 | LMU 가상 에너지 잔량 |

화면의 **질문 예시 · 43가지**에서 전체 목록을 봅니다. 베스트·이론상 베스트·구간 델타·순위·남은 랩·앞차 추격·앞차와 선두 랩타임·코너 개선·앞뒤 스틴트와 피트 횟수·피트 통과 손실도 지원합니다. 준비된 음성과 측정값이 있는 항목만 말합니다. 연료 잔량과 주행 가능한 랩은 서로 다른 질문입니다. 앞뒤 스틴트는 관측된 정차 이후 랩이며 실제 타이어 교체 여부를 뜻하지 않습니다.

질문 분류는 한국어 표현과 의도별 규칙을 사용합니다. 임의의 대화를 모두 이해하는 대화 모델은 아닙니다. 임의로 여러 질문을 섞거나 지원하지 않는 대상을 지정하면 보류합니다. 여러 정보를 들으려면 “연료 상황 보고” 같은 종합 보고를 사용하세요. 받은 문장이 틀리거나 다른 항목으로 분류되면 로그를 확인하고 한 가지 정보로 짧게 다시 물어보세요. 준비된 답변 음원이 없으면 **설정 → 업데이트 → 빠진 음성 받기**로 설치합니다. 이번 기능용 새 답변 음성 합성은 없습니다.

**로컬 마이크 에코 제거**는 음성 인식 팝업에서 켜고 끕니다. 기본은 꺼짐이며 소음 억제·자동 음량 조절은 유지합니다. Chrome에서 다른 소리를 재생할 때 말소리가 변형되는 사례를 줄이기 위한 설정입니다. 변경은 모델을 다시 불러오지 않고 다음 녹음에 적용되며 녹음·처리 중에는 잠깁니다. 선택은 이 브라우저에 저장되고, 테스트 후 브라우저가 보고한 실제 적용값을 확인할 수 있습니다. Google 질문의 마이크 처리는 별도입니다. 스피커 소리가 많이 섞이는 환경에서는 켜짐과 비교해 선택하세요.

**레이스 표현 보정**은 받아쓰기 후 적용합니다. 뒷차·뒤 차량·후방 차량, 앞쪽 차량·전방 차량, 기름·연료, 렙·랩과 랩 타임 표기를 통일합니다. 신고된 ‘기차’는 간격·랩당 추격·피트 횟수·스틴트 문맥이 맞을 때만 ‘뒤차’ 후보로 확인합니다. 예를 들어 ‘기차 몇 초 차이야?’는 뒤차 간격에 연결하지만 ‘기차 시간표’, ‘앞차 기차 간격’, ‘기차 연료 얼마나 남았어’는 보류합니다. 지원하지 않는 뒤차 랩타임을 뒤차 간격으로 답하지 않습니다. 실제로 입력한 정답과 확인된 비교 자료를 바탕으로 ‘방금 레타임’, ‘피트 후 예상 복귀 수’, ‘뒤차간결’, ‘앞착 간격’, ‘클래스 선도 랩타임’도 문장 전체 문맥이 맞을 때만 보정합니다. 대상이나 시점이 사라지고 ‘랩타임’만 남으면 자신의 랩으로 단정하지 않습니다. ‘방금 랩타임’, ‘앞차 랩타임’처럼 말하면 됩니다.

인식 테스트와 최근 질문 로그에는 **인식 원문·보정 문장·바꾼 단어와 근거**를 함께 표시합니다. 원문은 덮어쓰지 않고 새 동의 후의 로컬 인식 기록과 보정 정보는 개선용으로 자동 전송합니다. Google 질문은 제외합니다. 사전에 없는 오인식을 임의로 추측하거나 로그만으로 자동 학습하지 않습니다. 모델을 추가로 실행하지 않으며 인식 결과를 받은 때만 짧은 문장을 처리합니다. 실제 마이크의 받아쓰기 오류 자체를 모두 고치는 기능은 아닙니다.

**기록의 로컬 음성 인식 기록**에는 인식 문장, 선택한 질문, 답변, 준비·실패 이유와 처리 시간이 나옵니다. 무음·인식 불확실·지원 질문 미확인·데이터 부족·음원 누락을 구분합니다. 답변 준비와 실제 재생 완료는 다르며 재생 결과는 세션 무전 이력에서 확인합니다. 기록에는 전체 질문이 남고 음성 코치에서는 최근 로컬 질문 최대 20개를 표시합니다. 세션 로그를 내보낼 때 **개인 질문 포함**을 선택해야 질문과 분류 진단이 포함됩니다.

로컬 모드의 마이크 원음은 디스크에 저장하거나 외부 인식 서비스로 보내지 않습니다. 설치 후 인식과 답변은 오프라인으로 처리하고 실패해도 클라우드로 자동 전환하지 않습니다. 기존 Google Cloud 질문·메모는 본문의 별도 Google 기능에서 사용하며 해당 서비스의 요금이 적용됩니다. 마이크를 끄거나 세션이 바뀌면 대기하던 이전 답변을 취소합니다.

## 급유 추천과 빠른 클래스 차량 무리 (2.6.0)

급유 추천은 현재 완주 예상 거리와 **설정한 안전 여유**로 계산한 추가 급유량을 리터 단위로 올림합니다. 경기 연장 가능성의 한 랩분을 자동으로 더하지 않습니다. 한 랩 길어질 가능성은 화면에서 확인합니다. iRacing에서 피트 때문에 순위표 갱신이 늦으면 신선한 차량 진행 위치를 대조해 실제 앞선 차를 완주 예상의 선두로 사용합니다.

뒤에서 접근하는 빠른 클래스 차량 사이의 추정 통과 간격이 각각 4초 이내로 이어지면 같은 무리로 판단합니다. 그 무리에 대한 접근 안내를 끝까지 들으면 붙어 오는 후속 차량마다 같은 말을 반복하지 않습니다. 떨어져 접근하는 다른 무리와 실제 좌우 차량 경고는 계속 판단합니다. 기존 준비 음성을 사용하며 새 음성을 받을 필요는 없습니다.

## 무전 버튼 입력 뒤 스포터 중지 안내 (2.6.0)

무전 버튼의 답변 정보를 준비하는 작업은 실시간 무전 전송과 분리합니다. 스포터 데이터가 0.6초 넘게 갱신되지 않으면 오래된 좌우 안내와 대기 무전을 즉시 취소합니다. 잠깐의 지연에는 연결을 유지하고 새 데이터가 들어오면 복구합니다. 수신이 3초 이상 멈춘 연결은 다시 연결합니다.

연결 공백이 3초 동안 계속되면 준비된 ‘스포터 안내 중지’를 한 번 알립니다. 복구되면 대기·재생 중인 중지 안내를 취소하고 최신 차량 상태로 판단합니다. 데이터가 3초 동안 안정적으로 이어져야 다음 중지 안내를 다시 허용합니다. 다른 문장이 재생 중일 때 중지 안내는 끼어들지 않습니다. 새 음성 다운로드는 필요 없습니다. 앱과 실행창을 닫고 `실행.bat`으로 다시 열면 적용됩니다.

## 내 무전 버튼 (2.6.0)

**음성 코치 → 무전 버튼 설정 → 내 버튼 → 버튼 추가**를 누를 때마다 새 버튼이 목록에 저장됩니다. 키는 나중에 연결해도 됩니다. 목록의 휴지통을 누르고 **삭제 확인**을 누르면 그 버튼만 지웁니다. **빠른 등록**의 **앞뒤 간격**, **방금 랩**, **연료 상태**는 자주 쓰는 조합입니다. 원하는 조합을 고른 뒤 휠·버튼박스 버튼이나 키보드 조합을 누르세요.

**등록할 질문**에는 현재 설치된 음성으로 답할 수 있는 질문이 나옵니다. 빠른 등록에도 같은 기준을 적용합니다. **지난 랩 어디서 가장 많이 잃었어?**와 **지난 랩 어디서 가장 많이 줄였어?**는 확인된 코너의 직전 랩 기록을 개인 기준 통과 기록과 비교합니다. **뒤차가 랩당 몇 초씩 좁히고 있어?**는 같은 경쟁차와의 결승선 간격이 연속으로 줄었을 때 답합니다. 앞차·클래스 선두의 최근 랩타임, 구간 최고를 합친 이론상 베스트 랩도 물어볼 수 있습니다.

한 버튼에 여러 질문을 담을 수 있습니다. 화살표로 답변 순서를 바꾸고 ×로 해당 자리의 질문만 뺍니다. 다른 버튼을 편집하고 돌아와도 **저장 전**인 변경은 창 안에 남습니다. 각 버튼에서 **저장**한 뒤 창을 닫으세요. **다른 키도 연결**로 같은 무전에 휠과 키보드를 함께 지정할 수 있고, 게임 밖에서는 **저장한 키 테스트**로 확인할 수 있습니다. 게임별 연결이 있으면 해당 게임에서 그 연결을 사용합니다. 무전 버튼에 연결한 키를 해제하면 로컬 또는 Google 질문 단축키로 지정할 수 있습니다.

**음성 코치 → 설치 음성 듣기**에서 설치된 녹음을 미리 들을 수 있습니다. 예를 들어 **코너 코칭 → 시간 손실**에서 **13번 코너**를 선택하고 `0.9초`를 검색하세요. 현재 선택한 팩의 짧은 문장과 원래 문장을 모두 검색할 수 있습니다. 이전 개발본에서 저장한 코너 손실·간격 등 대응하는 질문이 있는 녹음은 같은 키와 순서에서 주행 질문으로 동작합니다. 나머지 기존 녹음은 개별적으로 빼거나 교체할 수 있습니다.

게임 창에서 버튼을 누르면 방금 랩은 누른 순간의 기록을, 연료·앞뒤 간격은 답변을 준비할 때의 측정값을 읽습니다. 마이크와 자동 무전을 꺼도 사용할 수 있습니다. 좌우 경보가 먼저이며, 5초가 지난 요청은 만료됩니다.

앞차·뒤차의 피트 진입 횟수는 레이스 초반부터 관측한 차량이 트랙에서 피트로드로 들어간 횟수(0~10회)를 읽습니다. 피트 통과 손실은 해당 트랙에서 학습한 기록이 있어야 합니다. **예시로 듣기**는 버튼에 담은 질문의 예문을 재생합니다. 게임에서 같은 키를 누르면 실제 값에 해당하는 음원을 사용합니다.

**등록할 질문 → 연료**에서 **지금 연료로 몇 랩 더 갈 수 있어?**와 **최근 랩당 평균 연료 소비는?**를 추가할 수 있습니다. 주행 가능 랩은 현재 연료와 최근 유효 랩의 최대 소비량으로, 평균 소비는 최근 유효 랩 최대 5개의 산술평균으로 계산합니다. LMU에서는 **LMU 가상 에너지 얼마나 남았어?**로 게임이 보내는 현재 잔량을 듣습니다. 두 게임 공통 버튼에 이 질문을 넣으면 iRacing에서는 같은 버튼의 다른 질문을 읽습니다.

연료로 갈 수 있는 거리 0~200랩, 평균 소비 0~30L/랩, 가상 에너지 0~100%를 소수 첫째 자리까지 읽습니다. 예를 들어 기본 전략 무전은 “지금 연료로 약 0.5랩 더 갈 수 있습니다.”, 짧은 전략 무전은 “연료 약 0.5랩.”입니다. **설치 음성 듣기 → 연료·에너지**에서 질문과 무전 길이를 고르고 특정 수치를 검색할 수 있습니다.

이전 개발본에서 비어 있던 버튼은 이름과 키가 남아 있으므로 원하는 질문을 다시 담을 수 있습니다. 등록 목록에는 선택한 형식의 수치별 녹음이 모두 준비된 질문이 표시됩니다.

## 코스 복귀·피트 순서·연료 절약·멀티클래스 무전 (2.6.0)

**스포터 → 주변 차량**에서 **코스 이탈 뒤 차량 접근**을 켤 수 있습니다. 코스 밖에서 느려졌을 때 다가오는 차량이 내 위치에 도착할 때까지의 시간을 추적합니다. 재생을 시작할 때 5초 미만이면 “차량이 옵니다.”처럼 숫자를 뺍니다. 5~6초에는 접근이 일정할 때 정수 초로 내림해 알려 줍니다. 첫 차 뒤에는 “다음 차 접근.” 또는 “다음 차까지 약 5초.”로 이어지고 여러 대가 붙어 오면 연속 접근을 알립니다.

iRacing에서는 같은 목록의 **빠른 클래스 통과 뒤 경쟁차**를 켤 수 있습니다. 빠른 차가 지나간 뒤 가장 가까운 뒤차가 내 순위를 다투는 차로 확인되면 그 차의 클래스 순위를 읽습니다.

**피트월**에서 **피트 전후 경쟁차 순서**를 켜면 나와 상대가 모두 정차하고 트랙에 복귀했을 때 피트 전과 달라진 순서를 알려 줍니다. **연료 절약과 순위 방어**는 완주까지 정차할 계획이나 의무가 없고 같은 뒤차와의 통과 간격이 확인될 때 작동합니다. 의무 정차가 없는 경기에서 무정차로 완주하려면 해당 경기의 피트월에서 **예정 피트 진입 랩**을 비우고 **경기 전체 의무 정차 횟수**에 0을 입력하세요. 랩당 연료 목표를 먼저 읽고 완료가 확인된 뒤 다음 발화 여유에 뒤차 설명을 전달합니다. 두 안내 사이에 차가 바뀌거나 계획이 달라지면 현재 상황을 다시 확인합니다. “뒤차가 랩당 0.4초씩 좁히면 결승 전에 붙음.”에서 0.4초는 뒤차의 페이스가 기준입니다. 이후 유효한 랩의 결과는 “연료 목표 달성. 간격은 유지됨.”처럼 읽습니다.

이 네 기능은 숫자와 단위를 포함한 문장 전체를 준비된 OGG로 재생합니다. 기본 무전은 존댓말이고 짧은 무전은 핵심 정보를 간결하게 읽습니다. **음성 코치 → 설치 음성 듣기**에서 차량 접근·피트 순서·연료 방어·멀티클래스 항목과 형식별로 찾아 들을 수 있습니다. 설정 → 업데이트 → 빠진 음성 받기로 음원을 설치합니다.

## 순위·시간·일반 보고의 시작 시점 (개발본)

발화 보류를 켜고 트랙의 제동 위치가 학습되면, 순위·퀄리 결과·일관성·시간 안내와 일부 일반 피트월 보고는 문장 길이까지 들어가는 구간에서 시작합니다. 다음 제동까지 몇 초 남았는지 아직 알 수 없는 구간에서는 기존 조작 조건을 사용합니다. 안내가 이미 시작되면 직선이 끝났다는 이유로 문장을 자르지 않습니다.

1분·2분 안내는 기준을 지난 뒤 10초 이내에만 시작합니다. 표시 시계가 늘어나면 대기 중인 이전 시간 안내는 취소합니다. 좌우 차량, 현행 깃발, 긴급 피트 지시는 각 상황의 우선순위로 알립니다. 풀코스 코션이 시작되면 대기 중인 로컬 옐로를 거두고, 데브리는 게임에서 깃발이 해제된 뒤 다시 켜질 때 새로 판단합니다.

세션 로그에서 `waiting.reasons.short_window`가 있으면 안내가 문장 길이에 비해 남은 직선이 짧아 대기했다는 뜻입니다. 대기 중 상황이 바뀌거나 발화 기한을 지나면 그 음성은 시작하지 않습니다.

## 2.5.8 레이스 판단 무전

레이스 피트월의 **연료·발화 설정 → 새 레이스 무전 기본·짧은 음성 듣기**에서 두 길이를 같은 상황별로 재생합니다. 청취와 주행 모두 **설정 → 업데이트 → 빠진 음성 받기**로 설치한 별도 음성을 사용합니다. 완주 절약률은 화면에 표시하며 해당 음성이 준비되지 않은 경우 기존 연료 안내를 사용합니다. 실제 주행에서는 **자동 보고 시작**과 음성 읽기를 켜고 피트월 **음성 길이**를 선택합니다. 새 피트 무전이 끝까지 전달되기 전에는 기존 안내가 유지됩니다.

완주 기준 연료 모드에서 남은 거리가 2.2랩 이내이고 실측 소비로 계산한 필요 절약률이 10% 이하면, 피트월이 여유 있는 주행 구간에서 정수 단위 목표를 말합니다. 필요량을 충족하도록 올림하며 이미 말한 목표가 3%포인트 이상 높아지면 갱신합니다. 예비분을 채우기 위한 급유량은 이 목표에서 제외합니다. 입력한 피트 계획, 남은 의무 정차, 두 랩 연속 소비 목표 초과, 연료 압력 경고를 확인하고 LMU에서는 가상 에너지로도 결승에 닿는지 확인합니다.

피트월과 스포터는 같은 차가 같은 방향에서 접근한다는 안내를 끝까지 재생하면 12초 동안 공유합니다. 추가 접근 차량, 만날 코너·직선을 알려주는 위치 무전, 공식 깃발은 별도로 판단합니다. 연습이 끝난 뒤 텔레메트리가 잠시 끊겨도 같은 세션의 체커를 반복하지 않습니다. 상대 정차는 레이스 중 트랙에서 피트로 이어지는 관측이 있을 때 집계합니다.

무전이 조용하면 **출력장치 → 테스트 소리**를 눌러 결과를 확인하세요. 현재 출력 경로에서 장치 연결, 테스트 음원 정보 수신, 재생 시간 진행 여부를 확인합니다. 정상 진행으로 표시됐는데 들리지 않으면 표시된 장치와 앱·Windows 볼륨을 확인하세요. 이후 무전의 재생 진단에는 테스트 결과·시각·출력 경로 종류가 함께 남습니다.

- 앞 두 대가 붙어 있을 때와 순서를 교환한 뒤 다시 공격할 때의 문구가 다릅니다. 앞차 자신의 같은 구간 페이스보다 느려질 때만 감속을 덧붙입니다.
- 코스팅은 연료량·노면 온도·젖음·타이어가 비슷한 독립 통과를 비교합니다. 겹치는 구간을 한 번만 계산하고, 완주까지 잃을 시간과 피트에서 줄일 시간을 표시합니다. 남은 의무 정차나 LMU 가상 에너지 때문에 피트가 필요하면 그 정차를 연료 절약 이득으로 계산하지 않습니다. 피트 의무가 없는 경기에서 규칙을 자동 확인할 수 없다면 **경기 전체 의무 정차 횟수**에 0을 입력하세요.
- 트랙 리밋은 반복 이탈 구간, iRacing의 1x 이력, 코너 탈출까지 남은 이득과 페널티 관측을 사용합니다. 같은 코너에서 1x로 이득을 본 라인과 페널티가 관측된 더 짧은 라인이 각각 반복되면, 화면에 정상 주행 대비 두 경로의 거리 차이를 표시합니다. 이 수치는 코너 전체를 주행한 거리 차이입니다. 게임의 연석 허용 폭은 알 수 없습니다. LMU에서는 게임이 제공하는 트랙 리밋 단계를 사용합니다.
- **예정 피트 진입 랩**은 해당 경기에서만 적용합니다. 지금과 다음 랩 모두 갈 수 있고 복귀부터 첫 제동까지 간격 차이가 충분하면 유리한 쪽을 안내합니다. LMU는 연료와 가상 에너지를 함께 확인해 정차를 앞당길지, 관측한 절약량으로 유지할지 안내합니다.
- iRacing **타이어 음성**도 켜면 실제 교체 후 네 바퀴의 온도·압력이 개인 범위에 들어오고 최근 제동과 탈출까지 확인될 때 푸시를 알립니다. 앞만 준비됐고 뒤가 차면 더 데우도록 안내합니다. 압력만 읽히는 차종에서는 압력 준비까지만 알립니다.

10·11분 등의 긴 피트랩 숫자 음성이 없으면 준비된 “이번 랩 기록이 갱신됐습니다.” 등의 기존 문장으로 알리고 실제 기록은 화면에 유지합니다. 선택한 음성팩에도 대체 문장이 없으면 보류합니다. 새 숫자 음성 합성은 하지 않습니다. 완주 안내는 기존 체커 음성을 사용하고 잠정/공식 결과 구분을 유지합니다. 포메이션에서 주행으로 전환할 때 오버레이의 이전 상태도 먼저 초기화합니다.

검증은 기록 재생·격리 API·합성 조건으로 수행합니다. 실제 주행 중 갱신 주기, 사람 청취, 모든 차량·서버의 순위 정확성을 보장하는 검증은 아닙니다.

## 11월6일 추가 로그 후속 수정 · 로컬 개발본

## 11월3일 로컬 수정 · 미공개

완주를 관측한 것과 순위가 확정된 것을 구분합니다. 쿨다운 진입이나 LMU 본인 완주 신호만으로 순위를 확정하지 않으며, 화면·경기 기록은 잠정 순위를 계속 갱신합니다. iRacing의 같은 세션 공식 결과표가 확인되면 공식 클래스 순위로 바뀝니다. 차량에서 나간 뒤에는 마지막 관측 순위를 유지하고 공식 결과만 추가 반영합니다. 완주 음성은 기존 체커 안내를 재사용해 변동 중인 순위를 단정하지 않습니다. 순위 변경 때문에 시작한 문장을 끊거나 다시 말하지 않습니다. 저장된 잠정 결과는 다음 경기 포메이션에서 확정 순위처럼 읽지 않으며, 같은 완주 기록의 공식 결과가 뒤늦게 도착해도 중복 경기로 쌓지 않습니다.

무전 기록에는 브라우저의 임시 재생 시도 ID·세대, 준비/출력 연결/메타데이터/효과/재생 단계, 경과 시간, 문장 조각 번호를 남깁니다. 시작 전 취소는 `cancelled`, 시작 후 중단은 `interrupted`로 구분합니다. 같은 이벤트를 재시도하면 시도 ID가 달라집니다. 출력장치 이름·ID나 계정 정보는 수집하지 않으며, 진단 대기열에서 빠진 행 수는 누적값으로 표시합니다. 대기열 수준의 만료·취소에는 실제 재생 시도가 없을 수 있습니다. 실제로 들었는지는 `started`와 `completed`를 구분해 확인하며, 나중 취소 행으로 앞선 완료를 지우지 않습니다. 기존 재시도 한도·우선순위·랩타임 2초 시작 기한은 같습니다.

피트월의 **연료 전략 판단 근거**에는 서버가 계산한 선택 목표, 소비 관측 랩 수, 남은 거리의 계산 근거, 완주 부족량, 안전 여유분과 절약·급유 대안을 함께 표시합니다. 관측 1~2랩은 잠정 계산으로 표시합니다. 무급유 완주 목표의 절약률에는 안전 여유를 넣지 않고, 급유량에는 넣습니다. 안전 여유를 포함한 절약 목표는 별도의 목표 절약률로 보여 줍니다. 어느 전략이 더 빠르다고 확정하지 않습니다. 같은 내용은 자동 보고의 당시 계산 근거에서도 확인할 수 있습니다.

새로 내보내는 주행 요약과 구간 자료는 원본 콘텐츠에서 만든 `source_ref`를 공유합니다. 파일을 복사하거나 이름을 바꿔도 같은 콘텐츠면 같은 식별자이며, 원본 파일명·경로는 포함하지 않습니다. 내보내기 작업에서만 파일을 순차 해시하며 주행 중이면 보류합니다. 내보내는 동안 원본이 바뀌면 해당 자료는 제외합니다. 요약은 선택한 기록 파일 전체의 분석이며, 구간 자료는 선택한 코너·랩·표본 구간일 뿐 전체 주행 재생 자료가 아닙니다. 기록 후보 수·세션 불일치·시각 불명·3파일 제한과 실제 겹친 시간 범위를 남깁니다. 과거 로그에는 이 식별자를 소급해 붙이지 않습니다.

이번 후속 작업에서는 요청에서 제외한 LMU 조향 보정·거동 학습과 판정 문턱을 변경하지 않았습니다. 새 음성 제작·외부 전송·공개 배포는 없습니다.

스포터의 **“클리어 왼쪽.”, “클리어 오른쪽.” 두 표현만** 선택 목록에서 제외했습니다. **“왼쪽 클리어.”, “오른쪽 클리어.”**와 나머지 클리어 안내는 유지합니다. 좌우 차량 감지·클리어 판단 조건은 같으며 기존 음원이나 사용자 음성팩을 삭제하지 않습니다.

iRacing의 백기는 전체 선두의 마지막 랩을 나타낼 수 있으므로, 뒤따르는 본인에게 아직 결승선 통과가 두 번 남았다면 “마지막 랩”으로 단정하지 않습니다. 반올림하기 전의 본인 예상 완주 통과랩과 최신 완료랩을 비교하고, 추가 랩 가능성이 있거나 목표를 확인할 수 없으면 이 안내를 보류합니다. 본인 전체 선두의 백기와 LMU의 본인 마지막 랩 신호는 유지합니다. 일반 백기 알림은 그대로입니다.

실시간 코너 비교에서 주변 차량이 있던 통과는 **비교 제외**, 주변 차량 관측이 확인되지 않은 통과는 **비교 보류**로 표시합니다. 유효한 첫 통과만 **첫 기록**으로 표시합니다. 손실이 없는 랩도 **“비교한 N개 구간에서 0.1초 이상 손실 없음”**으로 범위를 명시하며, 비교한 구간이 없거나 수가 확인되지 않으면 손실을 단정하지 않습니다. 이전의 유효한 비교를 보관할 수 있어 카드 이름은 **최근 비교 랩**으로 표시합니다.

앱과 검은 실행창을 완전히 종료한 뒤 다시 실행하면 이 작업 폴더에 적용됩니다. 버전은2.4.5, 기본 음성은2.4.3을 유지하며 기존 배포ZIP에는 이 로컬 수정이 포함되지 않습니다. 새 실주행·실제 장치 재생·사람 청취는 확인하지 않았습니다.

## 2.4.5 · 11월1일 개선

시간제 레이스에서 본인이 전체 선두이면 본인의 결승선 통과 횟수를 그대로 사용합니다. 같은 통과를 시간과 거리로 다시 환산하면서 한 랩이 추가되던 계산을 수정했습니다. 이 거리를 사용하는 연료 부족량과 LMU 에너지 절약 판단에도 적용됩니다. 선두 본인의 예상 피트 정차 시간을 중복 반영하지 않으며, 경기 종료 시계와 선두 통과 시점에 따른 한 랩 변동 가능성은 계속 확인합니다.

랩타임은 앱이 랩 완료를 감지하면 준비된 음성으로 바로 안내합니다. 조작이 조용해질 때까지 기다리던 조건과 직전 일반 안내 뒤 대기는 랩타임에 적용하지 않습니다. 완료 감지 후 2초 안에 재생을 시작하지 못하면 생략합니다. 늦게 도착한 게임의 랩타임 값도 이 시간을 늘리지 않습니다. 준비된 필수 음성이 없으면 합성을 기다리지 않고 생략합니다. 추가 문장은 준비된 것만 붙입니다.

게임이 완료 신호나 랩타임 값을 늦게 제공하거나 교통 정보가 부족한 경우에는 실제 결승선 통과 순간과 차이가 생길 수 있습니다. 모든 배틀을 판별한다는 보장은 없으며, 기존 교통·좌우 차량 정보로 판단합니다.

출력장치 연결·효과음 준비·재생 시작이 5초 이상 멈추거나, 시작한 음성의 재생 위치가 5초 이상 진행하지 않으면 해당 안내를 종료하고 다음 안내를 다시 시도합니다. 정상 진행하는 긴 음성에는 전체 길이 제한을 두지 않습니다. 오류 이유는 기존 로컬 음성 전달 기록과 브라우저 콘솔에 남깁니다. 장치 자체가 계속 연결되지 않는 경우에는 장치 연결과 출력 설정을 확인해야 합니다.

적용하려면 앱과 검은 실행창을 완전히 종료한 뒤 다시 실행하세요.

## 2.4.0의 외부 로그 후속 개선 (2026-10-27)

퀄리 순위·격차 전체 문장이 준비된 음성 범위를 벗어나면 기존 순위 음성으로 안내합니다. 화면에는 원래 순위와 격차를 유지합니다. 일반 전체 문장은 1~40위·0.1~3.0초, 대체 순위 음성은 1~60위 범위입니다. 범위 판정은 실제로 읽는 소수 첫째 자리 표현을 따릅니다. 공동 기록처럼 격차가 0.0초로 표시되는 경우에도 순위만 읽습니다. 필요한 기본·선택 음성이 없거나 파일이 손상된 경우 이번 음성을 생략하며 자동 합성을 요청하지 않습니다. 퀄리 랩타임과 별도인 기존 순위 안내 시점·설정은 유지합니다.

재생 시작 전 오류는 같은 안내에서 총 3회까지만 시도합니다. 첫 실패 후 0.5초, 두 번째 실패 후 1초를 기다리고 유효시간·연결·주행 조건을 다시 확인합니다. 실패한 렌더 음성은 다시 받으며 새 안내와 안전 경고는 별도로 처리합니다. 세 번 실패하면 해당 안내를 종료합니다. 이미 시작한 안내의 기존 중단·재개 정책은 유지합니다. 실제 파일·코덱·장치 중 최초 오류 원인을 확정하는 기능은 아닙니다.

연결 대기 음성은 다른 음성이 재생 중이면 생략하고 화면 상태로 표시합니다. 차량에서 내리거나 연결이 끝나도 이미 시작한 경기 결과 문장은 끝까지 들을 수 있습니다. 생략한 연결 대기 음성을 새 세션에서 뒤늦게 재생하지 않습니다. 실제 좌우 차량 등 안전 경고는 여전히 먼저 말할 수 있으며, 사용자의 무전 끄기·게임 전환·장치 변경은 기존 동작을 따릅니다.

## 2.3.2의 로컬 진단 보완

음성 기록과 독립적으로 주행 연결 상태를 보관합니다. 별도 작업이 2초마다 상태를 확인하고 변화가 있거나 정상 수집 중 30초가 지나면 저장합니다. 최근 64개 주행과 각 주행의 최근 128개 상태만 유지하며 오래된 상태가 생략됐다는 개수도 남깁니다. 이 기록으로 실제 음성이 들렸는지나 정확한 연결 단절 순간까지 확정할 수는 없습니다.

로그 파일 받기에는 해당 주행의 상태 기록도 포함됩니다. 안내가 0건인 주행도 목록에서 찾을 수 있고 마지막 무전 이후의 기록을 확인할 수 있습니다. 무전의 취소·만료 등 전달 결과에는 접수 당시 최신 상태를 별도 표시하며, 이를 원래 안내 판단 순간의 상태로 해석하지 않습니다. 이전 세션의 늦은 결과에는 현재 세션의 주행값을 붙이지 않습니다.

기록은 로컬에 저장하며 마이크 내용·녹음·키·개인 설정을 추가 수집하지 않습니다. 기존 자동 보내기 동의와 전송 조건은 그대로입니다. 전송 한도가 부족하면 추가 상태 기록부터 제외하고, 용량이 남으면 기존 교통 자료를 보존하면서 원시 코너 묶음을 최대 3개까지 추가합니다.

테스트·연습에서는 레이스 출발 문구를 생략합니다. LMU 부분 기록은 트랙 전체 길이를 확인할 수 없다는 안내와 함께 코스 거리 비교를 보류합니다. 실측 조향이 없는 차량의 거동 판정 조건은 그대로 유지합니다.

## 2.5.5 무전 재생·보고·로그 보완 (2026-11-11)

음성의 브라우저 재생 시작이 연속 실패하면 성공하기 전까지 경고를 유지합니다. 두 번째 실패부터 오디오 효과 연결을 정리하고 30초 동안 효과·증폭 없이 원음을 시도합니다. 이 정리는 30초 안에 반복하지 않으며 출력장치 선택·볼륨·음소거·음성 속도·저장된 효과 설정은 바꾸지 않습니다. 계속 소리가 안 나면 “테스트 소리”를 눌러 브라우저 재생을 허용하고, 필요하면 앱과 검은 창을 완전히 닫고 다시 실행하세요. 실제 소리 출력 여부와 장치 문제의 원인은 이 진단만으로 확정하지 않습니다.

같은 자동 보고가 계속 유효하지만 전달되지 않은 경우 새 준비 기록을 반복 저장하지 않습니다. 현재 run에서 최근 20분·최대 8개 준비 결정을 재사용하며 매 요청마다 현재 상황·개별 안내 설정·운전 부하를 다시 확인합니다. 재생 실패는 5·10·20·30초 간격으로 재시도하고, 완료 확인 없이 전달 완료로 기록하지 않습니다. 정상 안전 중단의 재시도와 랩타임의 2초 시작 기한은 유지합니다.

재생 진단에는 브라우저의 준비/네트워크 상태 코드·일시정지 여부·오류 코드·효과 연결 여부·컨텍스트 상태·임시 원음 여부·제한된 연속 실패 횟수만 추가합니다. 장치 이름·ID·경로·계정은 수집하지 않습니다. 세션 로그를 줄인 뒤 작은 상태 진단이 다시 들어갈 공간이 생기면 선택 코너 상세보다 먼저 복원하며 유지 중인 교통 자료를 밀어내지 않습니다.

시간·인시던트·가득 급유 등은 기존 녹음의 수치 범위에 따라 음성 답변이 제한됩니다. 임의 순위/이름의 차량 조회, 뒤차 랩타임, 상대 베스트·iRating·라이선스는 이번 범위에 포함하지 않았습니다. 피트 설정 변경은 아래의 별도 명령 기능에서 지원합니다. 지원하지 않는 대상의 질문을 본인 정보로 바꾸어 답하지 않습니다.

적용은 앱과 실행창을 닫은 뒤 **실행.bat**으로 다시 시작합니다. 인식 테스트는 주행 없이 문장과 질문 연결을 확인하고, 실제 숫자 답변은 게임 연결 후 질문 녹음으로 확인합니다. 원음은 주행 앱에서 저장하지 않으며 기존 별도 비교창의 녹음은 보존됩니다.


## iRacing 피트 음성 명령 (2.6.1)

앱과 실행창을 닫고 **실행.bat**으로 다시 시작한 뒤, **음성 코치 → 음성 인식 → iRacing 피트 명령 보내기**를 켭니다. 기본은 꺼짐입니다. 인식기를 준비한 다음 기존 로컬 질문 단축키나 질문 녹음 버튼으로 말합니다. Google 질문과 LMU에는 적용하지 않습니다.

이 PC의 iRaceIT 1.15.14 스트림덱 플러그인에서 확인한 것과 같은 SDK PitCommand 방식입니다. 채팅창·키 입력·스트림덱 설정 변경 없이 Windows 메시지를 전달합니다. 각 명령은 “피트”로 시작하며 한 번에 하나씩 말합니다. “연료 몇 리터 넣어?”는 기존 정보 질문입니다.

앞의 “피트”가 “히트” 또는 “키트”로 인식되어도 같은 시작말로 처리합니다. “피트 급유 15리터”처럼 설정·넣어라는 말을 생략하거나 “피트 타이어 전부 바꿔줘”, “피트 앞유리 닦아줘”, “피트 설정 다 취소해줘”로 말할 수 있습니다. 연료·급유·기름, 교체·바꿔·갈아, 왼쪽 앞·앞 왼쪽처럼 등록한 표현을 연결합니다. 수치와 단위는 그대로 사용하며 질문·부정·복합 명령은 실행하지 않습니다. 명령 시작말 없이 “급유 15리터”만 말하면 실행하지 않습니다.

| 말할 문장 | 다음 피트 서비스 변경 |
| --- | --- |
| 피트 연료 20리터 설정 | 추가 급유량 20L 선택. 현재 연료 포함 목표량이 아닙니다. |
| 피트 완주 연료 설정 | 한 번의 추가 급유로 완주하는 계획이 확인될 때 기존 여유 설정을 포함한 추천량 적용 |
| 피트 급유 취소 | 급유 선택 해제 |
| 피트 타이어 교체 / 피트 타이어 전부 교체 / 피트 슬릭 타이어 교체 | 다음 정차에 슬릭 타이어 네 바퀴 교체 선택 |
| 피트 레인 타이어 교체 / 피트 웻 타이어 교체 | 다음 정차에 웻 타이어 네 바퀴 교체 선택 |
| 피트 타이어 교체 취소 | 네 바퀴 교체 선택 해제 |
| 피트 왼쪽 앞 타이어 교체 | 해당 바퀴 선택. 오른쪽 앞·왼쪽 뒤·오른쪽 뒤·왼쪽·오른쪽도 지원 |
| 피트 타이어 공기압 180킬로파스칼 설정 | 네 바퀴 교체 선택과 180kPa 설정 |

| 피트 윈드실드 교체 / 피트 윈드실드 취소 | 윈드실드 서비스 선택 / 해제 |
| 피트 빠른 수리 켜 / 피트 빠른 수리 취소 | 빠른 수리 선택 / 해제 |
| 피트 전체 취소 | 모든 피트 서비스 선택 해제 |

급유는 1~150L 정수이며 알려진 탱크 용량을 넘으면 거절합니다. 0L 대신 급유 취소를 사용합니다. 공기압은 단위가 필수이며 100~400kPa 범위만 받습니다. 게임·차량에서 허용하지 않는 설정은 적용되지 않을 수 있습니다. 명령의 숫자·대상에는 질문용 유사어 보정을 적용하지 않습니다.

타이어 종류는 현재 차량의 SDK 목록으로 확인합니다. 웻이 없거나 종류를 확인할 수 없으면 전송하지 않습니다. 슬릭이 여러 종류면 현재 피트에 선택한 슬릭, 현재 장착한 슬릭 순서로 유지하며 둘 다 확인되지 않으면 게임에서 먼저 선택하도록 안내합니다. 다음 피트의 타이어 종류와 교체 체크가 모두 맞아야 반영 완료로 표시합니다. 현재 장착 타이어를 즉시 교체했다는 뜻은 아닙니다. SDK 근거: [PitCommandMode.tc](https://github.com/kutu/pyirsdk/blob/master/irsdk.py), [PitSvTireCompound](https://github.com/kutu/pyirsdk/blob/master/vars.txt).

현재 차량에 연결되어 있고 리플레이가 아니어야 전송합니다. 게임에서 읽어 온 선택값과 요청이 맞으면 **게임 설정 반영 확인**, 전송 뒤 확인되지 않으면 **명령 전송 결과 확인 필요**로 표시합니다. 처리 중 세션·입력 소유자가 바뀌면 남은 전송을 멈춥니다. 이미 전송한 일부 항목은 자동으로 되돌리거나 다시 보내지 않습니다. 같은 녹음 요청의 재시도도 중복 전송하지 않습니다.

게임에서 다음 피트 설정을 확인한 뒤 Orus 목소리로 복창합니다. “피트 급유 15리터” → “추가 급유 15리터로 설정했습니다.”, “피트 레인 타이어 교체” → “웻 네 바퀴 교체 설정했습니다.”처럼 들립니다. 확인되지 않으면 반영 미확인을 따로 알립니다. 급유는 1~150L 정수, 공기압은 100~400kPa 범위이며 차량 권장값을 뜻하지 않습니다. 공기압은 대상과 수치를 두 구절로 읽습니다. “답변·피트 복창을 음성으로 듣기”에서 켜고 끕니다. **설치 음성 듣기 → 피트 명령 복창**에서 기본·짧은 문구를 찾아 들을 수 있습니다. 인식 테스트는 명령을 알아듣더라도 실제 전송하지 않습니다. 실제 게임에서의 반영과 물리 마이크 확인은 후속입니다. 대기 중 추가 명령 처리 루프는 없으며, 요청 때만 최대 약 1초 동안 기존 주행 표본에서 반영 여부를 확인합니다.

현재 클래스 SOF는 iRacing 레이스에서 “클래스 에스오에프 알려줘”로 조회합니다. 같은 클래스의 사람 참가자 iRating이 모두 확인되어야 계산하며, AI나 정보가 부족한 경우 추측하지 않습니다.
